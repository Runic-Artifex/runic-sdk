# Runic SDK 0.2.0-preview.1

> Historical first-preview scope. Its acceptance gates are retired for future
> SDK releases; see the [current release policy](../../../eng/release/README.md).

Status: release preparation. September 8, 2026 is the target publication date;
publication waits for every required demo-preview acceptance gate. This page is a candidate guide, not
proof that packages are public or native scenarios have passed.

The preview distributes SDK libraries, tools and templates through NuGet and npm,
with one GitHub prerelease. Standalone translations editor distributions are outside
this release. The intended inventory is **27 NuGet packages and 8 npm packages**;
`eng/workspace.json` and the current release definition supply the exact identities.
Embedded generators, the bridge inspector, asset packer and translation compiler
are implementation components, not additional published tools.

## Installation and compatibility

Until publication, obtain the immutable candidate archive from the selected successful
CI run. Verify its checksums and source revision before installing; use its NuGet
feed and npm tarballs outside this checkout. The [acceptance handoff](../../../eng/preview-human-acceptance.md)
defines the required identity and evidence. Do not substitute locally rebuilt bytes.

After registry availability has been verified, install exact preview versions:

```sh
dotnet add package Runic.Application --version 0.2.0-preview.1
dotnet new install Runic.Application.Templates::0.2.0-preview.1
dotnet new install Runic.Translations.Templates::0.2.0-preview.1
dotnet tool install --local dotnet-runic --version 0.2.0-preview.1
dotnet tool install --local dotnet-runic-translations --version 0.2.0-preview.1
npm install --save-exact @runic-artifex/application-bridge@0.2.0-preview.1
```

Create a local tool manifest with `dotnet new tool-manifest` if the application does
not have one. Other npm packages also use exact `0.2.0-preview.1` versions. The
`preview` dist-tag tracks previews; existing `latest` tags are preserved. These
commands become public-registry instructions only after publication succeeds.

Use .NET 10 and the repository's pinned toolchain for development and acceptance.
Bun 1.4.2 is the workspace JavaScript runner. Compatibility checks also use real
Node with npm 12.0.2 and pnpm 12.3.4. React, Vue, Svelte and Angular templates are
required acceptance targets. A matrix entry is supported by an acceptance receipt,
not simply by the presence of a template.

Pinned prerelease dependencies are permitted. The bridge currently requires
`effect` **4.0.0-rc.112**; this is an explicit preview dependency exception, not a
promise of compatibility with other Effect 4 release candidates or Effect 3.
Keep application lockfiles and install the dependency versions declared in the
candidate. Preview-to-preview changes may break source APIs, generated bridge
contracts, template defaults or dependency compatibility. Upgrade the Runic set
together, regenerate bridge outputs and retest application behavior. No stable API
or cross-preview binary compatibility commitment is made for this preview.

## Translation source transition

New translation projects and maintained templates use
`sourceLayout: "locale-toml"` in `runic.json`, with one sibling `{locale}.toml`
file per locale. Standard TOML tables, nested tables, dotted keys and inline tables group MF2
string values. Identifier-safe path segments join with underscores into message
IDs; existing flat keys remain supported and flattened collisions are rejected.
For example, `[application] title` retains the API ID `application_title`;
parameters and plural selection retain their existing message semantics.
Projects without `sourceLayout` retain the legacy per-message MF2 layout.
Use the [migration workflow](preview-migration.md#translation-catalogs) to preview
and apply a transactional conversion.

Tomlyn **2.10.1** is pinned for compiler and authoring tooling. The parser is not
a dependency of generated application runtimes. Regenerate translations using
the matching preview tool and build packages after migration.

Runic's Translations Editor is the public demonstration for English and German
coverage, locale TOML editing and parameterized MF2 count messages. Automated UI
acceptance is still being completed; this page does not certify final coverage,
plural rendering or interaction acceptance. Standalone Editor publication remains
outside this SDK preview.

## Native service boundary

| Package                              | Responsibility                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| `Runic.Platform`                     | Host-independent contracts, options, results and capability snapshots              |
| `Runic.Platform.Runtime`             | Leases, transactions, presentation lifetimes, dispatch and provider infrastructure |
| `Runic.Platform.Windows`             | Windows file dialogs and text clipboard                                            |
| `Runic.Platform.Linux`               | GTK/portal file dialogs and text clipboard                                         |
| `Runic.Platform.MacOS`               | AppKit file dialogs, clipboard and scoped file access                              |
| `Runic.Application.Platform`         | Presentation-scoped DI and shutdown hooks                                          |
| `Runic.Application.Platform.Desktop` | Verified Desktop owner and dispatcher integration                                  |

These seven additions bring the existing twenty NuGet identities to twenty-seven.
Native providers are selected statically: an omitted provider must introduce no
native dependencies or initialization. Shared CS-WebUI applications remain free of
Desktop and ASP.NET Core dependencies.

| Host/profile                              | Preview service contract                                  | Demo-preview evidence scope                                                                     |
| ----------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Embedded Runic Desktop, Windows x64       | Owned file dialogs, read/save leases and text clipboard   | Automated JIT/NativeAOT; real selections and clipboard on the available Windows VM              |
| Embedded Runic Desktop, Linux x64 X11     | Same shared service APIs                                  | Automated JIT/NativeAOT; manual checks on this Linux system when using X11                      |
| Embedded Runic Desktop, Linux x64 Wayland | Same APIs; portal/backend limitations reported explicitly | Manual checks if available on this Linux system; otherwise deferred before v1                   |
| Embedded Runic Desktop, macOS arm64       | AppKit services and scoped file access                    | Automated JIT/NativeAOT required; real interaction and signed sandbox checks deferred before v1 |
| CS-WebUI                                  | Shared application/service APIs and scoped cleanup        | Native services explicitly unavailable; both-host lifecycle acceptance                          |

Applications distinguish dismissal, cancellation, unavailable services, failures and
uncertain commits. Clipboard reads distinguish no text from empty text, bound reads
and expose busy/permission failures. Once a native write starts, return its actual
outcome instead of masking it as cancellation.

Provider limitations: macOS clipboard uses ApplicationServices C Pasteboard APIs
and CoreFoundation. Linux GTK supports `UTF8_STRING`; its native selection transfer
occurs before the managed read bound can be checked, so native transfer allocation
is not bounded by that limit. Failed advertised GTK transfers report `IoError`
without a distinct permission-refusal code. Successful Linux writes acquire clipboard
ownership and do not guarantee persistence after the application exits. Headless X11
checks do not establish Wayland/portal or accessibility certification.

Owner identity and generation are verified in C#. Reconnection retains the
presentation; replacement invalidates its outstanding work. Native handles, paths,
streams and access leases stay in C# and never become bridge payloads. File writes
retain atomic replacement. Portal or sandbox access that cannot support sibling
staging reports unavailable before modifying the destination. Directory selection,
persisted bookmarks, mobile support and unowned dialogs are outside this preview.

The patched Linux AT-SPI dependency resolves a confirmed message-reference ownership
defect. A measured residual memory trend of roughly 2.2 MiB over 30 minutes is
accepted as a preview known issue; its strict trend result remains failed and its
cause is unassigned. The exception applies only to Linux sustained-quarter growth
within both 5 MiB and 1%; duration, operations, resources, shutdown and the overall
20% growth bound remain required. It is not a universal or full-v1 waiver, nor a
claim that all native leaks are fixed or are system defects. See the [native investigation and limitations](../../../eng/native/README.md).
Changed candidate binaries still require their own acceptance evidence.

## Migration and release evidence

The customer migration adds native import/export and copy/paste while preserving
business rules. A MAUI-derived text-document demonstration preserves document logic
and covers open, editing, save, cancellation and dirty-close protection. Their
orchestration moves to Runic commands and frontend drafts. Follow the
[migration checklist](preview-migration.md); completion of these demonstrations is a
release gate, not an assumption made by this page.

The final prerelease notes must link the frozen source commit, successful full CI
run, immutable artifact inventory and checksums, dependency graph, provenance,
acceptance receipts and remaining nonblocking limitations. Receipts certify only
their recorded source commit and artifact hashes.

The demo preview requires manual validation on this Linux system and the available
Windows VM. Automated native JIT and NativeAOT CI on Linux x64, Windows x64 and
macOS arm64 remains required. Real macOS interaction and signed sandbox checks,
Wayland checks when unavailable locally, broader accessibility certification and
two independent developer pilots are deferred follow-ups before v1. Their absence
does not block this demo preview and must not be represented as successful validation.
Record the actual Linux display-server profile and remaining coverage limitations.

Release blockers include missing required Linux/Windows manual evidence, failing
automated CI, consumer or review gates, unresolved performance regressions, an
incomplete required 30-minute demo-preview soak, and incomplete registry access.
Full-v1 acceptance retains the strict two-hour soak; longer diagnostic runs remain
optional when investigating a specific issue. Required gates and deferred
follow-ups are distinguished by the current release policy. NuGet account setup uses
the `runic-artifex` organization. If a required gate remains incomplete, retain the
candidate and publish a precise blocker list. Changed bytes after partial publication
require a new preview number.
