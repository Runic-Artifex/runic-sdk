# Volumes

An application lists the desktop's storage volumes, such as USB sticks, SD
cards, a second disk or an encrypted partition, mounts, unmounts and ejects
them, and follows them as they appear, change and disappear (planning item
W310-004). `IDesktopVolumes` in Runic.Platform is the contract;
`AddRunicPlatformServices()` registers the provider for the operating system.
.NET's `DriveInfo` lists only mounted volumes and cannot mount, unmount, eject
or report changes.

## Contract

```csharp
public interface IDesktopVolumes : IAsyncDisposable
{
    ValueTask<PlatformResult<ImmutableArray<DesktopVolume>>> ListAsync(CancellationToken cancellationToken = default);
    IAsyncEnumerable<PlatformResult<DesktopVolumeChange>> WatchAsync(CancellationToken cancellationToken = default);
    ValueTask<PlatformResult<DesktopVolume>> MountAsync(string volumeId, CancellationToken cancellationToken = default);
    ValueTask<PlatformResult<PlatformUnit>> UnmountAsync(string volumeId, CancellationToken cancellationToken = default);
    ValueTask<PlatformResult<PlatformUnit>> EjectAsync(string volumeId, CancellationToken cancellationToken = default);
}

public sealed record DesktopVolume(string Id, string DisplayName)
{
    public ImmutableArray<string> MountPaths { get; init; }
    public string? FileSystem { get; init; }
    public long? Size { get; init; }
    public string? DriveId { get; init; }
    public string? DriveName { get; init; }
    public bool IsRemovable { get; init; }
    public bool IsReadOnly { get; init; }
    public bool IsSystem { get; init; }
    public bool IsLocked { get; init; }
    public bool CanMount { get; init; }
    public bool CanUnmount { get; init; }
    public bool CanEject { get; init; }
}

public abstract record DesktopVolumeChange
{
    public sealed record Snapshot(ImmutableArray<DesktopVolume> Volumes) : DesktopVolumeChange;
    public sealed record Added(DesktopVolume Volume) : DesktopVolumeChange;
    public sealed record Changed(DesktopVolume Volume) : DesktopVolumeChange;
    public sealed record Removed(string Id) : DesktopVolumeChange;
}

public static class DesktopVolumes
{
    public static IDesktopVolumes Unavailable(PlatformUnavailableReason reason);
}
```

- A volume is a filesystem the desktop can mount, or a locked encrypted volume.
  `Id` is the platform's identifier, opaque and stable while the volume is
  present: a UDisks2 object path on Linux, a `\\?\Volume{GUID}\` path on
  Windows, a BSD name on macOS. Volumes of one drive share `DriveId`.
- The volumes are application-scoped and need no window. They connect to
  nothing until the first request; disposal ends every watch.
- `WatchAsync` reports a `Snapshot` of every volume first, then `Added`,
  `Changed` (any property, including mount paths) and `Removed`. When the
  volume service stops it reports `Unavailable(BackendUnavailable)` once and a
  new `Snapshot` when the service is back. Without a volume service, or from
  `DesktopVolumes.Unavailable(reason)`, it reports `Unavailable` once and waits
  for cancellation.
- `MountAsync` returns the volume with its mount path; a mounted volume is
  returned as it is. `UnmountAsync` of a volume that is not mounted succeeds.
  `EjectAsync` unmounts every mounted volume of the drive first and stops at the
  first that fails.
- Mounting and unmounting may show an authorization prompt. Cancellation stops
  waiting for the result; a prompt the desktop already showed may stay open.
- CS-WebUI and other hosts without a provider register
  `DesktopVolumes.Unavailable(ProviderNotConfigured)`.
- Volume identifiers come from trusted C# application code, never directly from
  a web client.

### Outcomes

| Situation | Result | Linux (UDisks2) | Windows | macOS (Disk Arbitration) |
| --- | --- | --- | --- | --- |
| Done | `Success` | The call returned | Mount of a mounted volume, unmount of one without a mount path, `CR_SUCCESS` without a veto | The callback without a dissenter; mount of a mounted volume, unmount of one that is not mounted |
| Authorization refused | `Failed(PermissionDenied)` | `NotAuthorized`, `NotAuthorizedCanObtain` (no authentication agent, or one the user cannot answer), `AccessDenied` | `PNP_VetoInsufficientRights`, `CR_ACCESS_DENIED` | `kDAReturnNotPermitted`, `kDAReturnNotPrivileged`, `EPERM`, `EACCES` |
| Prompt dismissed | `Failed(UserDismissed)` | `NotAuthorizedDismissed` | — (no prompt) | — (no prompt) |
| In use | `Failed(ResourceBusy)` | `DeviceBusy` | `CR_REMOVE_VETOED` and the vetoes for open handles, applications, services and drivers | `kDAReturnBusy`, `kDAReturnExclusiveAccess`, `EBUSY` |
| Encrypted and locked | `Failed(Locked)` | The volume has no cleartext device | — (a locked BitLocker volume is not listed) | — (not detected) |
| No such volume | `Failed(NotFound)` | Not among the managed objects, `UnknownObject`, `UnknownMethod`, `UnknownInterface` | Not listed; `PNP_VetoAlreadyRemoved`, `CR_NO_SUCH_DEVNODE` | Not among the disks; `kDAReturnNotFound`, `ENOENT`, `ENODEV` |
| A conflicting state | `Failed(Conflict)` | `AlreadyMounted`, `NotMounted` from a mount, `Cancelled` | — | `kDAReturnNotMounted` from a mount |
| Not offered by the volume or platform | `Unavailable(BackendUnavailable)` | Mount or unmount of a volume without a filesystem; eject of a drive that is not ejectable | Mount of a volume Windows did not mount, unmount of a mounted one; eject of a drive without a removable device or of the system's disk; `PNP_VetoNonDisableable`, `PNP_VetoIllegalDeviceRequest`, `PNP_VetoLegacyDriver` | Mount of a volume that is not mountable, the startup disk's volumes, eject of a drive that is not ejectable; `kDAReturnUnsupported`, `ENOTSUP` |
| No volume service | `Unavailable(BackendUnavailable)` | No system bus, `ServiceUnknown`, `NameHasNoOwner`, `NoReply`, a disconnected bus | — | No Disk Arbitration session |
| Other errors | `Failed(IoError)` | `Failed` and other UDisks2 errors, with the D-Bus error name | Other `CONFIGRET` results and vetoes; a listing that fails, with the Win32 error | Other `DAReturn` values |

Diagnostics carry the D-Bus error name, the `CONFIGRET` or `PNP_VETO_TYPE` value,
the Win32 error or the `DAReturn` value only, never a path, label or the veto's
device name.

## Linux

The provider talks to `org.freedesktop.UDisks2` on the system bus, as GNOME
Files and Dolphin do, with either toolkit and without loading GTK. Its proxies
come from a minimal introspection file written for the SDK
(`UDisks/org.freedesktop.UDisks2.xml`: `ObjectManager`, `Block`, `Filesystem`,
`Encrypted` and `Drive`, with only the members it uses), not from UDisks2's own
LGPL interface file.

- **Listing.** `GetManagedObjects` on `/org/freedesktop/UDisks2`. A block device
  with a `Filesystem` interface is a volume; one with `Encrypted` and no
  cleartext device is a locked volume, and an unlocked one is listed through its
  cleartext device, which belongs to the drive of its backing device. Devices
  with `HintIgnore` are left out. The name is `HintName`, then `IdLabel`, then
  the drive's vendor and model with the size, then the device name. `IsSystem`
  is `HintSystem`; `IsRemovable` is the drive's `Removable` or
  `MediaRemovable`; `CanEject` is the drive's `Ejectable`.
- **Mount, unmount, eject.** `Filesystem.Mount`, `Filesystem.Unmount` and
  `Drive.Eject` with `auth.no_user_interaction` set to false and the D-Bus
  flag that allows interactive authorization, so Polkit's authentication agent
  can ask the user. UDisks2 chooses the mount point, such as
  `/run/media/<user>/<label>`, and the mount options.
- **Watching.** The watch subscribes to `InterfacesAdded` and
  `InterfacesRemoved`, to `PropertiesChanged` under `/org/freedesktop/UDisks2`
  and to `NameOwnerChanged` for the service before it reads the objects, so no
  change in between is lost. When the name loses its owner it reports
  `Unavailable`; reading the objects again D-Bus activates UDisks2 where the
  system allows it, and the watch reports a new `Snapshot`.
- **Polkit.** UDisks2 checks actions such as
  `org.freedesktop.udisks2.filesystem-mount` (removable media),
  `filesystem-mount-system` (other devices), `filesystem-unmount-others` (a
  mount by another user) and `eject-media`. An active local session is usually
  allowed to mount removable media without a prompt.
- **Sandboxes.** Inside Flatpak add `--system-talk-name=org.freedesktop.UDisks2`
  to the finish arguments; inside Snap, connect the `udisks2` interface. No
  portal offers volumes.

## Windows

The provider in Runic.Platform.Windows uses the volume management API and the
Configuration Manager (cfgmgr32), as Explorer's drive list and "Safely Remove
Hardware" do. It needs no window, COM apartment or administrator.

- **Listing.** `FindFirstVolumeW` and `FindNextVolumeW` enumerate the volumes.
  One whose `GetVolumeInformationW` succeeds is listed: a drive without media,
  an unformatted (RAW) volume and a locked BitLocker volume are left out.
  `MountPaths` are its drive letters and mounted folders from
  `GetVolumePathNamesForVolumeNameW`; `FileSystem` and the label come from
  `GetVolumeInformationW`, `IsReadOnly` from `FILE_READ_ONLY_VOLUME`, `Size`
  from `GetDiskFreeSpaceExW`. The name is the label, then the drive's name with
  the size, then the first mount path.
- **Drives.** `IOCTL_STORAGE_GET_DEVICE_NUMBER` on a handle to the volume opened
  without access rights (or the first extent of
  `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS` for a dynamic volume) names its disk,
  optical or floppy drive, which is matched against the present
  `GUID_DEVINTERFACE_DISK`, `CDROM` and `FLOPPY` interfaces. `DriveId` is the
  drive's device instance ID and `DriveName` its friendly name.
- **Flags.** `IsSystem` is the volume Windows runs from, the EFI system,
  Microsoft reserved and recovery partitions, and partitions the platform
  requires (`IOCTL_DISK_GET_PARTITION_INFO_EX`). `CanEject` is a device node
  with `CM_DEVCAP_REMOVABLE` at the drive or above it, such as the USB
  mass-storage device of a USB stick's disk; never on the disk the system runs
  from, since a virtual machine's SCSI controller can be removable.
  `IsRemovable` is `CanEject` or a removable or optical drive type.
  `CanMount` and `CanUnmount` are always false.
- **Mount and unmount.** Windows mounts every volume it recognizes itself and
  gives it its drive letter; dismounting needs an administrator and the volume
  is mounted again on its next access. `MountAsync` returns a mounted volume as
  it is and `UnmountAsync` of a volume without a mount path succeeds, as the
  contract asks; otherwise both are `Unavailable(BackendUnavailable)`.
- **Eject.** `CM_Request_Device_EjectW` on that removable device node, with a
  veto buffer so that Windows reports a veto instead of showing its own
  notification. Windows dismounts the drive's volumes as part of the removal; a
  program with a file open on one vetoes it.
- **Watching.** `CM_Register_Notification` for `GUID_DEVINTERFACE_VOLUME` hears
  volumes arrive and leave; the watch then lists again after 300 ms, as a drive
  letter follows its volume a moment later. Drive letters, mounted folders,
  labels and media in a drive that stays present have no such notification, so
  the watch also lists every two seconds and reports the differences.

## macOS

The provider in Runic.Platform.MacOS uses Disk Arbitration, which Finder and
Disk Utility use. It calls only C functions with function-pointer callbacks on a
serial dispatch queue of its own: no AppKit, window, blocks or Objective-C
messages.

- **Session.** The first request creates a `DASession`, registers the
  disk-appeared, disk-disappeared, description-changed and idle callbacks and
  sets the queue. The idle callback marks the end of the first round of
  appearances; a listing waits for it (at most ten seconds). Each callback copies
  the disk's description (`DADiskCopyDescription`), so a listing reads no native
  state. Disposal unregisters the callbacks, unschedules the session and drains
  the queue.
- **Listing.** A disk with `kDADiskDescriptionVolumeKindKey` or a mountable
  volume is a volume; whole disks and APFS containers without a filesystem are
  not. `Id` is the BSD name. `DriveId` is the BSD name of the topmost whole
  `IOMedia` above the disk in the I/O Registry, so an APFS volume belongs to the
  drive's own disk rather than its synthesized container; `DriveName` is that
  disk's vendor and model. The name is the volume name, then the drive's name
  with the size, then the BSD name. `IsReadOnly` is the media not writable,
  `IsRemovable` the drive removable, ejectable or external.
- **System volumes.** The volume at `/`, those mounted under `/System/` (the
  startup disk's Data, Preboot and VM volumes, and Cryptex images), those
  mounted hidden from Finder (`MNT_DONTBROWSE`, as for simulator runtimes), the
  unmounted volumes of their drives (such as the system volume under its sealed
  snapshot and Recovery) and EFI system partitions are `IsSystem`. The provider
  never mounts or unmounts them and never ejects a drive with such a mounted
  volume.
- **Mount, unmount, eject.** `DADiskMount` at the default location under
  `/Volumes`, `DADiskUnmount` and `DADiskEject` of the drive's whole disk, after
  each mounted volume of the drive is unmounted. Disk Arbitration asks its
  dissenters first: an application with a file open on the volume, or one that
  refuses, returns a dissenter whose status the outcomes table maps. Mounting
  and unmounting the user's external volumes needs no authorization.
- **Watching.** Disk Arbitration reports every appearance, disappearance and
  description change, including mounts and unmounts, so the watch lists again
  only after a callback (and 100 ms more, so a burst is one listing).

## Out of scope for 1.0

Unlocking encrypted volumes, formatting and partitioning, powering off a drive,
mount options, and network locations (GVFS mounts) are candidates for 1.x.
