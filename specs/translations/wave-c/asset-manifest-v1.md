# Asset Manifest v1 publication edge

> Historical/superseded direction: the Template Manifest v1 consumer/output
> proposal recorded below is retained for compatibility history, not as a
> current release target. Current tooling rejects `--emit-template-manifest`
> and `TranslationsEmitTemplateManifest` with `RTR0065`; see the [current
> v5 artifact contract](../wave-b/canonical-artifacts.md) and [build/CLI
> contract](../wave-b/build-cli.md).

`{catalog}.asset-manifest-v1.json` is emitted whenever the `runic-translations` tool
selects at least one non-C# artifact group. Its filename and the schema at
`../schemas/asset-manifest-v1.schema.json` are the frozen v1 publication
contract.

The manifest is a compact UTF-8 JSON object with `assetManifestVersion: 1`, the
catalog ID, and ordinal-path-sorted assets. Each asset describes the exact
generated bytes through its safe relative path, lowercase SHA-256 without an
algorithm prefix, byte length, media type, and canonical locale for locale JSON
only. The manifest never lists itself and never includes generated C# outputs.

The historical Hosting.Build proposal was the consumer boundary: it could verify
every listed byte before copying or packaging it, but had to reject unknown
versions and must not reinterpret compatibility or synthesize alternate hashes.
That proposal is distinct from a hosting frontend manifest. Template and HTMX
consumers do not currently consume a separate Template Manifest v1; the retired
output group is rejected rather than emitted. The asset manifest remains the
current inventory for emitted locale/ESM asset bytes, not a grammar or template
contract.
