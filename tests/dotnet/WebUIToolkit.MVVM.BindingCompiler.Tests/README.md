# WebUIToolkit MVVM binding compiler contract tests

This dependency-free executable test project exercises the
`WebUIToolkit.MVVM.BindingCompiler` process boundary. Run it from the repository
root with:

```console
dotnet restore tests/WebUIToolkit.MVVM.BindingCompiler.Tests --locked-mode -p:WebUIToolkitLocalPackageSource=<packed-feed>
dotnet run --project tests/WebUIToolkit.MVVM.BindingCompiler.Tests --no-restore
```

The packed feed must contain the exact `WebUIToolkit.MVVM.Build` and
`WebUIToolkit.MVVM` version `1.0.0` handoff packages. Repository orchestration
creates that ignored local feed before the locked restore.

The corpus covers command exit categories, stdout/stderr separation, exact
one-based half-open `WUTMVVM` diagnostic spans, deterministic generated bytes,
viable multi-contract concatenation, argument-order independence, repeated/no-op compilation, atomic error behavior,
strict UTF-8, project-contained and unique input paths, the `--` terminator, and
all externally reachable file/count/aggregate hostile-input ceilings.

Tests invoke the compiler assembly copied by the project reference using the
current .NET host. They create isolated temporary working directories and never
depend on repository absolute paths, runtime identifiers, locale, or wall-clock
timestamps. Every contract prints one `PASS` or `FAIL` line followed by an exact
execution total; the process exits nonzero if any contract fails.

The committed `packages.lock.json` is generated by an ordinary RID-free restore.
Any future Native-AOT smoke publish must instead use the ignored
`obj/aot.packages.lock.json`; runtime-specific graphs do not belong in the
committed lock.
