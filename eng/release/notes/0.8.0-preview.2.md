# Runic SDK 0.8.0-preview.2

Install matching `0.8.0-preview.2` packages from NuGet and npm. Command Line
versions remain independent of this SDK.

## Tools

`dotnet-runic`, the project creator (`Runic.Create`), the asset packer and the
Windows administration verifier use Runic Command Line 0.7.0-preview.1 (see its
[release notes](https://github.com/Runic-Artifex/runic-cli-sdk/blob/main/eng/release/notes/0.7.0-preview.1.md)).
Their JSON payloads are unchanged:

- `runic.create/1` keeps its PascalCase properties (`Name`, `Directory`,
  `Version`, `Options`, `Commands`, `ReproduceCommand`, `Created`). Since Runic
  Command Line 0.6.0-preview.3, generated result codecs apply the JSON context's
  options, and the creator's context asked for camelCase; it now names each
  property explicitly. `runic.application.tool/1`,
  `runic.assets.pack-result/1` and `runic.administration.verify/1` name theirs
  explicitly too.
- `Runic.Create` still asks its questions only when standard output is a
  terminal; with redirected output it uses the defaults, as before.

## Views

- `dotnet publish --no-build -p:PublishAot=true` after a matching
  `dotnet build` works in a Runic Views application. NativeAOT publishing
  schedules `CoreCompile` again, and Bridge generation then built the
  generator and the bootstrap pass, which `--no-build` refuses with
  `NETSDK1085`
  ([#278](https://github.com/Runic-Artifex/runic-sdk/issues/278)). With
  `NoBuild=true` the build now reuses the Bridge code that the earlier build
  generated, and reports the new `RUNICBRIDGE022` when it is missing. The Nix
  builder still publishes NativeAOT applications without `--no-build`, so it
  keeps working with earlier `Runic.Application.Views` versions.
