## Runic Inspect for translated text (#956)

Runic Inspect now shows the messages of generated `m.*()` calls that a
selected element shows: catalog, key, locale, the text as authored, and the
`.rmf2` file:line, with an "open in editor" link. `describe(element)` returns
them as `messages`.

- **Markers only while selecting.** Turning select mode on asks Runic
  Translations (`@runic-artifex/vite-plugin-runic-translations` 0.12 or later
  under `vite dev`) to put an invisible marker in front of each message's
  text, and the page renders again, as on a language switch. Turning it off
  renders the plain text again. Outside select mode, and in every build, the
  page's text is exactly as before.
- **Text and attributes.** Markers are read from the element's text and from
  `title`, `aria-label`, `placeholder`, `alt` and an input's value. They take
  no width, so the layout does not change while selecting.
- **Open in editor.** The source location comes from the Translations dev
  server's message API. `/__runic/open` accepts
  `{ "message": { catalog, key, locale } }`, asks the same API, and opens only
  the `.rmf2`/`.mf2` source it names, never a path from the page. The open
  action is now also there with `runic({ sourceMap: false })` unless Runic
  Inspect is off.
- **Re-rendering** uses the text helpers that follow the text-change channel
  (below): `useTextLocale` in React and Vue, Svelte's `useTextLocale`, and
  Angular's `textLocaleSignal`.

With an earlier Translations plugin the overview has no messages and its notes
say why. `vite build` output is byte-identical with and without Runic Inspect.
