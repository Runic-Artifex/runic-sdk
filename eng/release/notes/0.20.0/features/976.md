## Runic Inspect: a button's command before its first click (#976)

Runic Inspect now shows the command a button calls, with its C# handler,
before the button was used. The development server reads the element's
component file and follows its event handlers to the client calls they reach:
directly (`client.save()`), through `useCommand`, `useOperation`,
`injectCommand` and `injectOperation`, and through functions, variables and
class members of the same file. The overview marks such a command "from the
source, not called yet" and links the line that calls the client. It works
for React (JSX/TSX), Vue single-file components (`@click`, `<script setup>`
and the Options API), Svelte 5 (`onclick` and `on:click`) and Angular
templates (`(click)`, inline and `templateUrl`).

Under the Angular CLI, `runicDevSessionProxy()` now answers `/__runic/handlers`,
`/__runic/sources` and `/__runic/open` as well, so Runic Inspect shows C#
handlers and pre-click commands with `ng serve` too; `dotnet runic dev` now
passes the source map's path to the Angular development server as it does to
Vite. The proxy's new options `sourceMap` and `inspect: false` turn them off.

Calls made in other files (a store, a service, a custom hook) are still learned
on the element's first click, and the overview names the import the handler
uses. Served modules are unchanged: the analysis answers
`GET /__runic/handlers?file=…` for pages of this machine and frontend files
below the root, and `vite build` output is byte-identical with and without it.
`runic({ inspect: false })` turns it off.
