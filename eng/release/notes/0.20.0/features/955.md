## Runic Inspect: select an element and see how it is connected (#955)

Under `vite dev` and `dotnet runic dev`, press **Alt+Shift+X** in the page to
turn on **Runic Inspect**, a select mode of the
`@runic-artifex/vite-plugin-runic` development client. Hover outlines an
element; clicking it shows an overview, without running the page's own
handler for that click:

- its framework component and the components around it, with a link to the
  source: the element's JSX line in React 19 (from `_debugStack` through the
  module's source map), the element's line in Svelte 5, the component file in
  Vue 3 and the component class in Angular 17.1+;
- the commands it calls, with their C# handlers (such as the
  `[RelayCommand]` method) and file:line from the development source map
  (#951), and their availability (`canSave`);
- the ViewModel members it sets, and state members it shows, with their
  current values and C# members;
- its recent Bridge calls with duration, outcome and revision (#953);
- the texts its ViewModel sent as text references, with catalog, key and
  locale.

C# locations, Translations messages and frontend files open in the editor
through `/__runic/open`, which opens a frontend file only when Vite serves it
to the page. An element's commands are found in its component's source before
any click (#976, below) and learned from the calls it makes. For agents and
tests,
`globalThis[Symbol.for("runic.vite.inspect")].describe(element)` returns the
overview as data. Runic Inspect is plain DOM, so it works in every engine
`dotnet runic dev` runs (installed browser, WebView2, WKWebView, WebKitGTK).
It lives in the development client only: `vite build` output is
byte-identical with and without it, and `runic({ inspect: false })` turns it
off.
