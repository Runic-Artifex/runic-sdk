## Bridge errors and warnings while you type, with code fixes (#962)

`Runic.Application.Views` ships Roslyn analyzers for the Bridge rules that the
source alone shows. Until now the Bridge generator, a build step that IDEs skip
in their design-time builds, reported them only after a build. Visual Studio,
Rider and VS Code's C# extension now report them while you type, with the
generator's ID, message and help link. Examples are a command named `NewCommand`
or `ThenCommand` (`RUNICBRIDGE004`), a command without the `Command` suffix or a
plain `ICommand` without `[RunicCommandInput]` (`RUNICBRIDGE009`), and a
`ViewRequest<T>`, interaction, navigation slot or `[RunicCollection]` with a
public setter. Code fixes rename the command, or its CommunityToolkit
`[RelayCommand]` method, make the setter private, or make a Window, View or
ViewModel public. Projects that reference `Runic.Application.Views` through a
host adapter get the analyzers too. The
[diagnostics catalog](https://github.com/Runic-Artifex/runic-sdk/blob/v0.20.0/docs/diagnostics.md#errors-and-warnings-while-you-type)
lists the rules.

The analyzers also report errors that compare a ViewModel with the rest of the
application: two ViewModels with the same Bridge name, a second View with the
same contract, a slot whose `[RunicViewContract]` or content no View presents,
and a ReactiveUI member without the Runic ReactiveUI adapter of its flavor
(`RUNICBRIDGE004`, `006`, `008`, `025`, `070`). Builds don't change for errors:
the generator still checks every rule and runs before the compiler, so a build
reports each error once.

The warnings `RUNICBRIDGE013` (a ViewModel without a View that a slot admits),
`028` and `039` (`[RunicOperationRetirement]` or `[RunicOperationClose]` that
reaches no operation) and `034` (a misplaced `[RunicPresentationScoped]`) now
come from the analyzer, while you type and in the build, for the project's own
code. The generator leaves them to it, so each is reported once. As compiler
warnings they now follow `.editorconfig` severities, `#pragma warning disable`
and `TreatWarningsAsErrors`, as the diagnostics catalog always described: a
project that treats warnings as errors and has one of these warnings now fails
to build, where the generator's warning did not fail it. Suppress the warning
with `NoWarn` or `WarningsNotAsErrors`, or fix the declaration. Like other
compiler warnings, they are not repeated by a build that finds the project up to
date.
