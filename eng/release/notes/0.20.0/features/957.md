## Edit a translation on the page (#957)

Runic Inspect's overview has an **Edit** action for each message of a selected
text. The panel shows the message's MF2 source in every locale (base locale
first, starting with the one the page shows), its inputs, plural and selector
variants with the locale's plural categories, and its markup.

- **Save writes the source.** Save (or Ctrl+Enter) sends the text with the
  file hash it was read from to Runic Translations' in-page editing API
  (`@runic-artifex/vite-plugin-runic-translations` 0.12 in project mode). Only
  that entry of the `.rmf2`/`.mf2` file changes; comments and formatting stay.
  The page shows the new text in place, without a reload, and the card keeps
  its selection.
- **Refusals in the panel.** A text that does not compile shows its RTR
  diagnostics and writes nothing. A file that changed since it was read shows
  its current text, with **Reapply my text** and **Use the file's text**.
- **Keyboard.** The panel is reachable with Tab, Ctrl+Enter saves, and Esc
  closes it and returns to the message's Edit button. It is plain DOM, so it
  works in every engine `dotnet runic dev` runs.

**From another machine.** `runic({ allow })` and the `RUNIC_DEV_ALLOW`
environment variable name hosts and networks (addresses, IPv4/IPv6 CIDR such as
a Tailscale network, host names) whose pages may read `/__runic/sources` and
`/__runic/handlers`; `runicDevSessionProxy({ allow })` does the same under the
Angular CLI. Runic Translations' editing API reads the same variable, so one
setting covers both. Without it, both stay loopback-only, as before.
`/__runic/open` always stays loopback-only, because it launches the editor on
the development machine; a page opened from another machine shows locations
without links and says why. Same-origin checks are unchanged.

`vite build` output is byte-identical with and without Runic Inspect, the
editor and the allow list.
