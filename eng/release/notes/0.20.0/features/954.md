## The dock's Bridge call timeline, and the dock on by default in the template (#954)

The Runic panel of the Vite DevTools dock has a **Bridge calls** card: each call
a generated client makes, the newest first, with the C# that ran for it from
the development source map (#951) and how long the page waited for it:

```text
command EditorViewModel.save → SaveAsync() 23 ms
```

- Its **Open** button opens the handler (a command's `[RelayCommand]` method, a
  setter, …) in your editor. It opens only what `/__runic/open` would, a
  location in a file the source map lists, with the same editor choice
  (launch-editor, the package behind Vite's `/__open-in-editor`, now a
  dependency of the plugin).
- A failed call shows .NET's exception, with a button for each stack frame in a
  file of the source map, which opens that line. The **Last failure** card
  links the same frames. `/__runic/open` therefore opens any line of a file the
  map lists, not only the map's own locations; it still opens nothing else.
- When a reply carries .NET's own timing of the handler, the row shows it as
  `C# <n> ms` next to the page's duration.
- The history is as long as the timeline (`maxTimelineEntries`, 200 by
  default) and checked like it. `/__runic/state` lists the calls (`calls`)
  without failures and without paths.

The dock now also appears under `dotnet runic dev`, where the window's document
is the .NET host's page and the dock's own loader looked for its script on the
wrong origin: the development client loads it from Vite's development server.
With `runic({ html: false })` (SvelteKit) the client loads it too, and the
dock's HTML hook, which SvelteKit warned about, is removed.

`dotnet new runic-app` registers the dock (`DevTools()` from
`@vitejs/devtools` 0.7.6) in `Frontend/vite.config.ts` of every frontend that
Vite builds: React, Vue, Svelte, SvelteKit and Angular with
`--angular-build vite`. The Angular CLI runs no Vite plugins and has no dock.
`vite build`, and so the application's build, publish and packages, contain no
part of it. To turn it off, delete the `DevTools(),` line. The first time a page
opens the dock, it asks for the one-time code that Vite DevTools prints in the
`dotnet runic dev` output.

Applications created from an earlier template: add `"@vitejs/devtools": "0.7.6"`
to `devDependencies`, `import { DevTools } from "@vitejs/devtools";` and
`DevTools()` to the Vite plugins.
