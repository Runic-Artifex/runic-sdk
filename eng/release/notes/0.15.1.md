# Runic SDK 0.15.1

Install matching `0.15.1` packages from NuGet and npm;
`Runic.Application.Views.CsWebUi` is `0.15.1-preview.1`. Command Line versions
remain independent of this SDK.

This patch release fixes a Svelte `useView` bug that could make an application
call a command without end and run out of memory
([#791](https://github.com/Runic-Artifex/runic-sdk/issues/791)). It changes no
Runic API.

## Fixes

- Svelte `useView`: `client`, `error` and `pending` notify their readers only
  when their own value changes; only `state` follows each published state
  ([#791](https://github.com/Runic-Artifex/runic-sdk/issues/791)). Before, an
  `$effect` that read only `client` ran again with every state, so an effect
  that called a command whose answer changed the state called it again without
  end, until the page ran out of memory. `useCommand`, `useOperation`,
  `useLatestOperation`, `useField` and `useTextField` likewise notify a reader
  of one member only when that member changes. React `useView`, Vue `useView`
  and Angular `injectView` already behaved this way; tests now cover them.
- `Runic.Desktop.NativeServer`: the `runic-server` crate it builds carries the
  SDK version. In 0.15.0 the crate still said 0.14.0, so a build from source
  showed `runic-server 0.14.0` although it compiled the 0.15.0 code
  ([#792](https://github.com/Runic-Artifex/runic-sdk/pull/792)).

## What to update

- Raise the Runic package versions in your project to `0.15.1`. Only Svelte
  applications are affected by the `useView` fix; everything else is unchanged.
