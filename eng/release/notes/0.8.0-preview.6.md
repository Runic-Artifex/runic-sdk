# Runic SDK 0.8.0-preview.6

Install matching `0.8.0-preview.6` packages from NuGet and npm. Command Line
versions remain independent of this SDK.

## Behaviour changes

- A call, snapshot read or mount of a View that the page disposed, or that .NET
  released (navigation replaced it, its slot changed or its window is closing),
  now rejects with the new `BridgeErrorKind` `released` instead of
  `disconnected`. These rejections are no longer reported to
  `onBridgeDiagnostic` as errors, because they are expected around every
  navigation. `disconnected` now means only that the Bridge is not connected to
  .NET. Match `released` for a replaced or closed View and `disconnected` for a
  lost Bridge, or use `onBridgeConnection`; an exhaustive `switch` over
  `BridgeErrorKind` needs a `released` case. In `@runic-artifex/views-effect`
  these failures are the new `ViewReleased` instead of `ViewDisconnected`, and
  operation `retry` does not retry them
  ([#411](https://github.com/Runic-Artifex/runic-sdk/pull/411)).
- When every caller of a shared, token-bearing `BackAsync` has cancelled while
  its departure guard runs, the region is no longer busy once the last caller
  gets `Rejected(Cancelled)`. A request made after that caller resumed is
  admitted in a `RejectWhileBusy` region instead of `Rejected(Busy)`; it waits
  for the cancelled guard to end, and the cancelled Back never commits.
  `region.WhenIdleAsync()` follows `IsBusy` and so no longer waits for that
  guard; `RunicNavigator.WhenIdleAsync()` still does
  ([#419](https://github.com/Runic-Artifex/runic-sdk/pull/419)).
- CS-WebUI registers more services as unavailable: the volumes
  (`DesktopVolumes.Unavailable(ProviderNotConfigured)`,
  [#409](https://github.com/Runic-Artifex/runic-sdk/pull/409)), the application
  database (`DesktopApplications.Unavailable(ProviderNotConfigured)`,
  [#410](https://github.com/Runic-Artifex/runic-sdk/pull/410)) and thumbnails
  (`DesktopThumbnails.Unavailable(ProviderNotConfigured)`,
  [#416](https://github.com/Runic-Artifex/runic-sdk/pull/416)).

## Navigation

- A region or navigator guard can run before the pages' own departure guards
  ([#413](https://github.com/Runic-Artifex/runic-sdk/pull/413)). Register it
  with `new NavigationRegionGuardOptions { Order = NavigationRegionGuardOrder.BeforeEntries }`
  for a precondition such as "no navigation while an operation runs", which
  should refuse before a page asks "Discard the unsaved changes?". If it vetoes,
  no page guard is asked. This also applies to WPF's `GuardWindowClose` and a
  Runic View's `CanCloseAsync`. The default, `AfterEntries`, keeps the current
  order. `AskOnRetain` and `AskOnClearHistory` apply either way, and a veto is
  still `Rejected(Guard)` with no `By` entry.
- **Runic.Navigation.Wpf**: `NavigationHost.RetainViews` keeps the view of each
  retained entry and shows it again on Back or BackTo, so state that lives only
  in the view, such as scroll positions, the caret and selection, expanded tree
  nodes and grid column widths, survives. It is an inherited attached property:
  set it on a host, or as `NavigationHost.RetainViews="True"` on a window. A host
  that loads again with the same region and current entry keeps its view, so
  pages with child regions keep theirs too. Kept views are dropped when their
  entry retires, the region empties or the host's `Region` changes, and their
  `Unloaded`/`Loaded` events are raised again. The default, a new view whenever
  an entry becomes current, is unchanged
  ([#421](https://github.com/Runic-Artifex/runic-sdk/pull/421)).

## Views

- `onBridgeConnection(listener, { lostAfter })` reports `connecting`,
  `connected`, `reconnecting` and `lost` as the connection to the .NET host
  changes, so a page learns within about 250 ms that the host ended, without
  making a call. `lost` (after `lostAfter`, default 5000 ms) is not terminal.
  Runic Desktop and CS-WebUI host scripts implement the new optional
  `RunicBridgeClient.onConnectionChange`, and the mock Bridge reports
  `disconnect()`/`reconnect()`
  ([#411](https://github.com/Runic-Artifex/runic-sdk/pull/411)).
- RUNICBRIDGE013 no longer warns about a ViewModel without a View of its own
  that a base class's View presents. A content property, ViewModel collection or
  `NavigationRegion<TContent>` slot presents such a subclass through the View of
  a base class the slot admits; the warning now applies only to ViewModels that
  no View presents, so a project that suppressed RUNICBRIDGE013 for this case can
  remove the `NoWarn`
  ([#408](https://github.com/Runic-Artifex/runic-sdk/pull/408)).

## Desktop applications

- New `IDesktopApplications` (Runic.Platform) is the desktop's application
  database. It determines a file's content type by name or by name and content,
  lists the installed applications and the ones that open a type (the default
  first), reads and sets the user's default application, launches an installed
  application with paths or URIs, and returns themed icons as PNG or SVG bytes.
  `AddRunicPlatformServices()` registers `PlatformServices.CreateApplications()`,
  and `DesktopApplications.Unavailable(reason)` serves hosts without a provider
  ([#410](https://github.com/Runic-Artifex/runic-sdk/pull/410)).
- **Linux.** `PortalPlatformProvider.CreateApplications()` and
  `PortalApplication.CreateApplications()` read the freedesktop.org desktop
  entries, shared MIME-info database, `mimeapps.list` files and icon themes
  without GIO. Launches never go through a shell, and `DBusActivatable`
  applications are activated over D-Bus. Inside Flatpak and Snap the application
  methods return `Unavailable(BackendUnavailable)`; content types and icons still
  work ([#410](https://github.com/Runic-Artifex/runic-sdk/pull/410)).
- **Windows.** `WindowsPlatformProvider.CreateApplications()` reads the shell's
  associations: content types from the registry (a MIME type, or the extension
  such as `.txt`), the handlers and default for a type or URL scheme, the Start
  menu's applications, and icons as PNG. A file launches through the
  application's own registration for the file's type (`ShellExecuteEx` with that
  class); URIs and folders go to the shell's association handler. No command
  line is built and no command shell runs. Windows lets only the user choose
  defaults, so `SetDefaultApplicationAsync` reports `PermissionDenied` with a
  diagnostic that points to `ms-settings:defaultapps`
  ([#417](https://github.com/Runic-Artifex/runic-sdk/pull/417)).
- **macOS.** `MacOSPlatformProvider.CreateApplications()` uses Launch Services
  with uniform type identifiers: handlers, defaults, launches by bundle
  identifier, icons as PNG and the applications in the Applications folders.
  macOS asks the user to confirm a `SetDefaultApplicationAsync`; the request
  waits, and a refusal is `UserDismissed`
  ([#417](https://github.com/Runic-Artifex/runic-sdk/pull/417)).

## Volumes

- New `IDesktopVolumes` (Runic.Platform) lists the desktop's storage volumes,
  such as USB sticks, SD cards and other disks, mounts, unmounts and ejects them,
  and reports them as they appear, change and disappear. A watch starts with a
  snapshot of every volume. `AddRunicPlatformServices()` registers it, and
  `DesktopVolumes.Unavailable(reason)` serves hosts without a provider. See the
  [volumes design](https://github.com/Runic-Artifex/runic-sdk/blob/main/specs/platform/volumes.md)
  ([#409](https://github.com/Runic-Artifex/runic-sdk/pull/409)).
- **Linux.** `PortalPlatformProvider.CreateVolumes()` uses UDisks2 on the system
  bus, which asks Polkit for authorization: a refusal is `PermissionDenied`, a
  dismissed prompt `UserDismissed`. Inside Flatpak, add
  `--system-talk-name=org.freedesktop.UDisks2`. Runic.Platform.Linux.Portal now
  depends on Runic.Platform.Linux.DBus
  ([#409](https://github.com/Runic-Artifex/runic-sdk/pull/409)).
- **Windows.** `WindowsPlatformProvider.CreateVolumes()` lists every volume with
  a recognized filesystem, at its drive letters and mounted folders, and reports
  volumes as they arrive, change and leave. `EjectAsync` safely removes the
  drive, as "Safely Remove Hardware" does; a program that keeps a file open on
  the drive makes it `Failed(ResourceBusy)`, and the disk Windows runs from is
  never ejected. Windows mounts volumes itself: `MountAsync` returns an already
  mounted volume, `UnmountAsync` of a volume that isn't mounted succeeds, and
  otherwise both report `Unavailable(BackendUnavailable)`. Locked BitLocker
  volumes and drives without media are not listed
  ([#414](https://github.com/Runic-Artifex/runic-sdk/pull/414)).
- **macOS.** `MacOSPlatformProvider.CreateVolumes()` uses Disk Arbitration, as
  Finder does. It mounts at the default location under `/Volumes`, unmounts, and
  ejects a drive after unmounting its volumes. An application with a file open
  on the volume, or one that refuses through Disk Arbitration, makes an unmount
  or eject `Failed(ResourceBusy)`. `Id` is the BSD name, and `DriveId` names the
  drive's physical disk, also for APFS volumes. The startup disk's volumes and
  the images macOS mounts for itself (Cryptex and simulator runtimes) are marked
  `IsSystem`, and the provider never mounts, unmounts or ejects them
  ([#420](https://github.com/Runic-Artifex/runic-sdk/pull/420)).

## Thumbnails

- New `IDesktopThumbnails.GetThumbnailAsync(path, size)` (Runic.Platform)
  returns the thumbnail the file manager shows, as PNG bytes with its size, or
  `null` when the file has none; it never returns an icon instead.
  `AddRunicPlatformServices()` registers `PlatformServices.CreateThumbnails()`.
  Linux reads the freedesktop.org thumbnail cache and, on a miss, asks the
  session's `org.freedesktop.thumbnails.Thumbnailer1` (such as Tumbler). GNOME
  and KDE run no thumbnailer service, so there only thumbnails their file
  managers already made are returned. Inside Flatpak, add
  `--filesystem=xdg-cache/thumbnails:ro` and
  `--talk-name=org.freedesktop.thumbnails.Thumbnailer1`. Windows uses the
  shell's thumbnail providers and macOS Quick Look
  ([#416](https://github.com/Runic-Artifex/runic-sdk/pull/416)).
