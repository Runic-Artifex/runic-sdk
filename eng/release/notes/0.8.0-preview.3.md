# Runic SDK 0.8.0-preview.3

Install matching `0.8.0-preview.3` packages from NuGet and npm. Command Line
versions remain independent of this SDK.

A command line can now hand its work to an application's running instance and
print the reply: `ApplicationInstance` forwards a launch that waits for
messages and an exit status over the single-instance socket. The change is
additive.

## Replies to forwarded launches

A launch forwarded to an application's running instance can now wait for its
reply over the same single-instance socket: a stream of messages and an exit
status. A command line can hand its work to a running instance, such as a
windowless application behind a status icon, print its output, and cancel it
with Ctrl+C. The change is additive; one-way forwarding is unchanged.

- `ApplicationInstance.ClaimAsync(applicationId, launch, ApplicationInstanceOptions, cancellationToken)`
  with `ReplyToLaunches = true` forwards a launch that waits. The claim's
  `ApplicationInstanceClaim.Forwarded.Reply` (`IForwardedLaunchReply`) reads the
  messages (`ReadMessagesAsync`), the exit status (`WaitForExitAsync`, a
  `PlatformResult<int>`) and asks the running instance to cancel
  (`CancelAsync`). Disposing it, or cancelling a read, closes the connection,
  which cancels the launch in the running instance.
- In the running instance, claimed with the same option, such launches carry
  `ApplicationLaunch.Reply` (`IApplicationLaunchReply`): `WriteAsync` sends a
  UTF-8 message of at most 1 MiB, `CompleteAsync` the exit status, and
  `Cancelled` reports a cancel request, a launching process that went away, or
  the instance ending. Writes wait for a launching process that does not read.
- When the running instance ends before the exit status, the reply reports
  `Failed(IoError)`. An instance that does not reply, including one built with
  0.8.0-preview.2 or earlier, refuses such a launch without handling it, and the
  claim fails with `ResourceBusy` and an `ApplicationInstance` diagnostic.
