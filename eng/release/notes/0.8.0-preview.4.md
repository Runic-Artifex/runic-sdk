# Runic SDK 0.8.0-preview.4

Install matching `0.8.0-preview.4` packages from NuGet and npm. Command Line
versions remain independent of this SDK.

## Privileged actions

`PrivilegedActionDeclaration` compiles its `ArgumentPattern` on the first
`AcceptsArguments` (or `CreateArgumentVector`) instead of when it is created.
The `NonBacktracking` regex cost tens of milliseconds under the JIT (45 ms in
one application) in every process that read the generated `PrivilegedActions`
class, such as a status icon at startup. Matching is unchanged. `RunicPrivilegedAction` items are still checked
at build time (`RUNICPA008`); a declaration written by hand with an invalid
pattern now throws `ArgumentException` or `NotSupportedException` from that
first check rather than from the `ArgumentPattern` initializer.

## Serve-only mode on Runic Desktop

- A line on standard input ends the Windows serving at that moment. A Window
  the application opens after it serves until the next line; before, the first
  line was read once per process, so such a Window closed at once.
- `PlatformServices.PresentAsync(IRunicWindow, context, cancellationToken)`
  brings a Window forward on any host. In serve-only mode, where
  `DesktopBridgeWindow<TViewModel>.NativeOwner` throws because there is no
  presentation, and for a Window on another host, it reports
  `OwnerUnavailable`. The change is additive.
- The redirect from a directory to its index page, such as from the URL that
  serve-only mode prints to `index.html`, keeps the query string
  ([#313](https://github.com/Runic-Artifex/runic-sdk/issues/313)). A served page
  that reads its route from `location.search` opened on the index without it.
  The browser keeps the fragment, which the server never receives.
- A Window can serve application files that are not part of its frontend
  build, such as icons from a cache, in a native window and in serve-only mode
  alike ([#313](https://github.com/Runic-Artifex/runic-sdk/issues/313)).
  `RunicDesktopHost.Resources` chooses a `ContentHandler` for each Window as it
  opens, and becomes the new `DesktopSurfaceOptions.Resources` of its surface,
  which is asked for what the content has no file for, before 404. Before, a
  page could only load such files as data URLs through its ViewModel.
- A served Window can end with its last browser tab
  ([#317](https://github.com/Runic-Artifex/runic-sdk/issues/317)).
  `RunicDesktopHost.GetSurface(window)` returns a Window's surface without
  naming its ViewModel type, and the new `DesktopSurface.ConnectionCount`
  counts its connected pages; a connection event's handler already sees the
  count with that event. Counting the events yourself could go wrong, since a
  connection that loses its admission right after its token check is reported
  disconnected without having been reported connected. The changes are
  additive.

## Runic Desktop on Linux

Found while porting nix-manager to Runic
([#313](https://github.com/Runic-Artifex/runic-sdk/issues/313),
[#318](https://github.com/Runic-Artifex/runic-sdk/issues/318)). The changes are
additive: `RunicDesktopHost.OpenWindowAsync<TWindow>(options, activation, cancellationToken)`
and `DesktopWindowHostOptions.ReportDiagnostic` are new. The activation follows
the options, so existing calls with one argument still open as before.

- A Window opened for a launch or a click can get focus.
  `RunicDesktopHost.OpenWindowAsync<TWindow>(options, activation, cancellationToken)`
  opens the Window as `host.OpenWindowAsync<TWindow>(options)` does, then
  presents it with the desktop's activation token or startup ID, such as
  `ApplicationLaunch.PlatformContext` of a launch the running instance
  received. Before, KWin and other Wayland compositors opened such a Window
  behind the active one, because nothing passed it the token. A hidden window, a
  served one and an installed browser are not presented. An open Window is
  brought forward with `PlatformServices.PresentAsync(window, context)` as
  before. The status-icon example opens its Window this way.
- A crashed WebKitGTK web process no longer leaves a blank or frozen window that
  logs nothing. The embedded window, with GTK 3 or GTK 4, reloads its page and
  reports `web-process-terminated` to `DesktopHostOptions.DiagnosticSink` and the
  logger as the new event 3010, `EmbeddedWindowDiagnostic`, a warning. After
  three reloads within a minute it stops reloading, and the diagnostic is an
  error. A process the application ended itself is reported without a reload. A
  custom `IDesktopWindowHost` reports its own events through the new
  `DesktopWindowHostOptions.ReportDiagnostic`.
- The Runic.Desktop README's
  [Accessibility](https://github.com/Runic-Artifex/runic-sdk/blob/main/packages/dotnet/Runic.Desktop/README.md#accessibility)
  section describes two WebKitGTK 2.54.1 limitations.
  Live regions and changed accessible names or descriptions are silent under
  Orca, because WebKitGTK sends no AT-SPI event for them; report changes through
  native semantics instead, such as a spin button whose value Orca reads. A
  list item whose only content is a button whose last node has no box, such as
  whitespace or the comments Svelte inserts, aborts the web process when Orca
  reads it, with GTK 3 and GTK 4; give such list items `display: contents` and
  their position with `aria-setsize` and `aria-posinset`.

## Nix packaging

- `buildRunicApplication` with `nativeAot = true` sets `PublishAot` for
  `projectFile` alone, as if its project file set it, instead of passing
  `-p:PublishAot=true` to every project. `testProjectFile` is restored with its
  usual lock file and runs under the JIT, without a NativeAOT lock file or
  `TreatAsLocalProperty="PublishAot"`.
- The Nix guide's note on NativeAOT lock files is corrected: whether the
  runtime's section lists `runtime.<rid>.Microsoft.DotNet.ILCompiler` depends
  on whether restore took the compiler package from nuget.org or from the .NET
  SDK in nixpkgs; both build.
