# Runic SDK 0.11.0

Install matching `0.11.0` packages from NuGet and npm;
`Runic.Application.Views.CsWebUi` is `0.11.0-preview.1`.
Command Line versions remain independent of this SDK.

0.11.0 is the last release that adds API before 1.0. Every API it adds is final
for 1.0: none is experimental and no npm package has an `./experimental` entry.
Next come the release candidates `1.0.0-rc.N`, which take only fixes,
stabilization and documentation, and then 1.0.0. See
[Versioning and support from 1.0](https://github.com/Runic-Artifex/runic-sdk/blob/v0.11.0/eng/release/README.md#versioning-and-support-from-10).

Everything is additive against 0.10.0: package validation passes against the
0.10.0 baselines without suppressions, no public API is removed, and Views
protocol 3 is unchanged. Some defaults change as security fixes or because a
feature now works where it reported unsupported before; see
[Upgrading](#upgrading), [Behaviour changes](#behaviour-changes) and
[Security](#security).

Highlights:

- **Menus:** native menu bars on Windows and GTK, the Linux global menu (X11
  and KDE Plasma Wayland), native context menus, and a headless in-page menu bar
  for the application's own components on Runic Desktop and CS-WebUI.
- **Platform services:** global shortcuts, message boxes, network status,
  clipboard formats beyond text, taskbar and Dock badges and progress, monitors
  and full screen, file drag-out, trash and volume management, binary secrets,
  URL scheme and file type registration and D-Bus activation.
- **Views:** wire-key command parameters (`[RunicCommandKey]`), a configurable
  Bridge input limit, an operation retirement policy for navigation entries,
  `RunAsync` for ReactiveUI commands, an embedded frontend
  (`RunicApplicationFrontendDelivery=Embedded`), and a Bridge that works under a
  Content-Security-Policy without `'unsafe-eval'`.
- **npm:** `AbortSignal` and `Symbol.dispose` support, an Effect client layer,
  `useBridgeConnection`, `useMenuBar` and Node 26.
- **Tools and templates:** `dotnet runic package` (MSIX, `.app`/DMG, Flatpak,
  AppImage, deb, rpm), `dotnet runic assets pack`, a SvelteKit frontend and a
  `runic-view` item template.

## Upgrading

Update every Runic NuGet and npm package to 0.11.0 together and rebuild. Code
that compiled against 0.10.0 compiles unchanged, unless a new warning meets
`TreatWarningsAsErrors` (see [Behaviour changes](#behaviour-changes)).
Regenerated TypeScript clients need `@runic-artifex/views` 0.11; clients
generated by 0.10 keep working with the 0.11 runtime
([#523](https://github.com/Runic-Artifex/runic-sdk/pull/523)). Check these if
they apply to you; details are in [Behaviour changes](#behaviour-changes):

- TypeScript: the `.d.ts` files reference the `esnext.disposable` library and
  need TypeScript 5.2 or later
  ([#523](https://github.com/Runic-Artifex/runic-sdk/pull/523)).
- A declared menu bar is now shown in Windows and GTK windows and can move into
  the Linux global menu. Set `MenuBarPresentation` to `Page` or `None`, or
  `LinuxDesktopOptions.GlobalMenu = false`, to keep the old look
  ([#553](https://github.com/Runic-Artifex/runic-sdk/pull/553),
  [#556](https://github.com/Runic-Artifex/runic-sdk/pull/556),
  [#569](https://github.com/Runic-Artifex/runic-sdk/pull/569)).
- Asset archives leave out `.git` and `.env*`; `RunicAssetsDefaultExcludes=false`
  packs them ([#538](https://github.com/Runic-Artifex/runic-sdk/pull/538)).
- `dotnet runic dev` with `runic()` needs `@runic-artifex/vite-plugin-runic`
  0.11; an Angular frontend that declares the plugin needs
  `runicDevSessionProxy()` in its `proxyConfig`
  ([#546](https://github.com/Runic-Artifex/runic-sdk/pull/546),
  [#547](https://github.com/Runic-Artifex/runic-sdk/pull/547)).
- CS-WebUI: update any copy of `runic-cswebui.js` kept outside `www/`
  ([#561](https://github.com/Runic-Artifex/runic-sdk/pull/561)).
- Remote WMI needs a DNS or NetBIOS server name; an IP address fails
  ([#588](https://github.com/Runic-Artifex/runic-sdk/pull/588)).
- Flatpak: add `--talk-name=com.canonical.AppMenu.Registrar` so that the bar can
  move into KDE Plasma's global menu
  ([#569](https://github.com/Runic-Artifex/runic-sdk/pull/569)).
- Recommended: remove `'unsafe-eval'` from your pages' Content-Security-Policy;
  see [Security](#security)
  ([#562](https://github.com/Runic-Artifex/runic-sdk/pull/562)).

### Compatibility

- **Runic Command Line 0.9.0.** `dotnet runic`, `Runic.Create`, the Runic Assets
  packer and the Windows administration verifier use Runic Command Line 0.9.0,
  released on 2026-10-22. It adds outcome presenters, opt-in response files and
  more NativeAOT runtimes; its one behaviour change concerns custom outcome
  sinks. The tools behave as in 0.10.0
  ([#524](https://github.com/Runic-Artifex/runic-sdk/pull/524)). No SDK library
  package depends on Command Line.
- **Runic Translations 0.8.0**, released on 2026-10-22, depends on Runic Command
  Line `[0.9.0, 0.10)`, the minor the SDK tools use, and on no Runic SDK package.
  Its Translations Editor is built on Runic SDK 0.10.0.
- **CsWebUi.** `Runic.Application.Views.CsWebUi` requires CsWebUi
  2.5.0-beta.4.8 or later (was 2.5.0-beta.4.7)
  ([#587](https://github.com/Runic-Artifex/runic-sdk/pull/587)).
- **Node.** `@runic-artifex/sveltekit`, `@runic-artifex/vite-plugin-runic` and
  the starters accept Node 24.18+ and Node 26 (`^24.18.0 || ^26.0.0`).
  `dotnet runic doctor` warns on Node 26 instead of failing; Node 24 stays the
  certified version
  ([#523](https://github.com/Runic-Artifex/runic-sdk/pull/523),
  [#527](https://github.com/Runic-Artifex/runic-sdk/pull/527)).
- **Runic.Desktop** now depends on `Runic.Platform.Linux.DBus` (exact version)
  and Tmds.DBus.Protocol on every OS, so WPF applications ship those two managed
  assemblies too, unused off Linux
  ([#569](https://github.com/Runic-Artifex/runic-sdk/pull/569)).

## New APIs

### Menus

- **Presentation and placement.** `DesktopWindowOptions.MenuBarPresentation`
  (`DesktopMenuBarPresentation`, closed): `Native`, the default, shows
  `DesktopHostOptions.MenuBar` natively, `Page` leaves it to the page, `None`
  shows no bar; the host matches the items' shortcuts with all three.
  `DesktopWindow.MenuBarPlacement` (`None`, `Window`, `Global`, `Page`; open)
  and `MenuBarPlacementChanged` report where the bar is.
  `DesktopWindow.TryExecuteMenuItemAsync(item)` runs an item through the one
  command path of the bar, shortcuts and the in-page bar
  ([#533](https://github.com/Runic-Artifex/runic-sdk/pull/533)).
- **Menu model** (`Runic.Platform`): `DesktopMenuItem.CommandParameter`,
  `AccessKey` and `RadioGroup`, `DesktopMenu.AccessKey`, and
  `DesktopStatusIconActivation.CommandParameter`. Status icon menus are unique
  by command id and parameter
  ([#533](https://github.com/Runic-Artifex/runic-sdk/pull/533),
  [#569](https://github.com/Runic-Artifex/runic-sdk/pull/569)).
- **Native bars** on macOS, Windows (in the window, with access keys, Alt and
  F10) and GTK 3 and GTK 4 (above the page), with check and radio items and
  right-to-left mirroring. Declared shortcuts run their items when the page
  leaves the key alone; the OS's reserved shortcuts stay the page's
  ([#553](https://github.com/Runic-Artifex/runic-sdk/pull/553),
  [#556](https://github.com/Runic-Artifex/runic-sdk/pull/556)).
- **Linux global menu.** A GTK window exports its bar as
  `com.canonical.dbusmenu` and puts it into the desktop's global menu on X11
  (KDE Plasma; Xfce, MATE and Budgie with vala-panel-appmenu) and on KDE Plasma
  Wayland (`org_kde_kwin_appmenu`). `LinuxDesktopOptions.GlobalMenu` (default
  `true`) and `DesktopWindowHostOptions.GlobalMenu` turn it off
  ([#569](https://github.com/Runic-Artifex/runic-sdk/pull/569),
  [#580](https://github.com/Runic-Artifex/runic-sdk/pull/580)).
- **Context menus.** `DesktopWindow.ShowContextMenuAsync(items, options)` and
  `IWindowPlatformServices.ShowContextMenuAsync` (default member) show a native
  menu at the pointer or a page point (`DesktopContextMenuOptions`) and return
  the chosen `DesktopMenuItem` or `null`: macOS, Windows, GTK 3, GTK 4 and WPF
  ([#533](https://github.com/Runic-Artifex/runic-sdk/pull/533),
  [#553](https://github.com/Runic-Artifex/runic-sdk/pull/553),
  [#556](https://github.com/Runic-Artifex/runic-sdk/pull/556)).
- **Capabilities and SPI.** `DesktopWindowCapabilities.MenuBar` and
  `ContextMenu`, `PlatformCapabilityIds.MenuBar` (`platform.menuBar`) and
  `ContextMenu` (`platform.contextMenu`). Custom window hosts implement
  `IDesktopMenuWindowHost` and read `DesktopWindowHostOptions.MenuBarPresentation`
  ([#533](https://github.com/Runic-Artifex/runic-sdk/pull/533)).
- **macOS standard menu titles.** `DesktopHostOptions.StandardMenuTitles`
  (`DesktopStandardMenuTitles`) lets the application translate the standard
  menus Runic adds
  ([#535](https://github.com/Runic-Artifex/runic-sdk/pull/535)).
- **In-page menu bar.** `createMenuBarController()` (`@runic-artifex/views`)
  follows a window's declared bar as headless state for the application's own
  menubar component; `invoke(item)` answers `executed`, `disabled` or `stale`.
  Shortcuts stay with Runic, or with the page under `shortcuts: "app"`
  (`handleKeyDown`). It emits `focus` and `open` requests and `accessKeyHints`
  on Windows and Linux; `splitAccessKey` splits a label for underlining;
  `installMockMenuBar` serves a bar on the mock Bridge. Windows serve the
  reserved `__runicMenuBar*` routes
  ([menu-bar-page.md](https://github.com/Runic-Artifex/runic-sdk/blob/v0.11.0/specs/desktop/menu-bar-page.md))
  ([#563](https://github.com/Runic-Artifex/runic-sdk/pull/563)).
- **Adapters.** `useMenuBar(options?)` (React, Vue, Svelte) and
  `injectMenuBar(options?)` (Angular) return `{ state, invoke, handleKeyDown }`
  and take `onRequest`. The READMEs show the bar with Base UI, Reka UI, Bits UI
  and the CDK Menu; Runic ships no menubar component
  ([#564](https://github.com/Runic-Artifex/runic-sdk/pull/564),
  [#568](https://github.com/Runic-Artifex/runic-sdk/pull/568)).
- **CS-WebUI.** `RunicCsWebUiHostOptions.MenuBar`, `RunicCsWebUiHost.MenuBar`
  and `SetMenuBar(menus)` declare a bar that pages render with the same
  controller; the Window's root ViewModel (`IRunicMenuCommandSource`) runs the
  items ([#572](https://github.com/Runic-Artifex/runic-sdk/pull/572)).
- New diagnostics `menu-radio-checked`, `menu-bar-page-native`,
  `menu-bar-failed`, `menu-title-invalid`, `global-menu-failed` and
  `global-menu-permission`; log events 3014–3017 and 2102
  ([#533](https://github.com/Runic-Artifex/runic-sdk/pull/533),
  [#569](https://github.com/Runic-Artifex/runic-sdk/pull/569)).

  packs the frontend into the application assembly with Runic.Assets. Runic

- `RunicApplicationFrontendPackageManager` with a value other than `npm`,
  `pnpm` or `bun` warns with `RUNICBRIDGE029` where it changes what runs; before,
  the build silently used npm
  ([#525](https://github.com/Runic-Artifex/runic-sdk/pull/525)).
- `RunicAssetsDefaultExcludes` (default `true`); see
  [Behaviour changes](#behaviour-changes).
- `RunicPackageIcon`, `RunicPackageName` and `RunicPackagingDirectory` for
  `dotnet runic package`; `RunicApplicationFileTypes`,
  `RunicApplicationWebLinkHosts` and `RunicApplicationDBusActivatable` declare
  file types, web link hosts and D-Bus activation in the package manifests
  ([#549](https://github.com/Runic-Artifex/runic-sdk/pull/549),
  [#550](https://github.com/Runic-Artifex/runic-sdk/pull/550),
  [#551](https://github.com/Runic-Artifex/runic-sdk/pull/551),
  [#577](https://github.com/Runic-Artifex/runic-sdk/pull/577)).

### Platform and Runtime

- **Helpers.** `PlatformResult<T>.Succeeded`, `TryGetValue(out T)` and
  `Match(…)`, and `PickerResult<T>.TryGetValue` and `Match` ([#602](https://github.com/Runic-Artifex/runic-sdk/pull/602)); `ApplicationInstance.ClaimAsync(applicationId, args[, options])`
  takes `Main`'s arguments; an MSIX-packaged application passes
  `DesktopPlatformServices.GetLaunch(args)` instead, because its protocol and file
  activations do not arrive in `args`. `DesktopServiceStatus.Get(service)` (and
  `IDesktopServiceStatus`) reports whether an application-scoped service can be
  used at all. `DesktopAppearance.TextScale` is the desktop's text size factor
  (Windows, GNOME). `IDesktopThumbnails.GetThumbnailAsync(path, size, scale,
  cancellationToken)` asks for high-density thumbnails
  ([#515](https://github.com/Runic-Artifex/runic-sdk/pull/515),
  [#516](https://github.com/Runic-Artifex/runic-sdk/pull/516)).
- **Notifications.** `DesktopNotificationActivation.IsTrusted` is `true` when
  the activation matches a notification the application showed.
  `PortalDiagnostic.Severity` (`PortalDiagnosticSeverity`, open) says whether a
  portal message reports a problem
  ([#515](https://github.com/Runic-Artifex/runic-sdk/pull/515),
  [#516](https://github.com/Runic-Artifex/runic-sdk/pull/516)).
- **Announcements.** `IWindowPlatformServices.AnnounceAsync(message,
  PlatformAnnouncementPriority, …)` (default member; `Polite`, `Assertive`)
  announces a message to the screen reader on Runic Desktop and WPF windows
  ([#510](https://github.com/Runic-Artifex/runic-sdk/pull/510)).
- **File dialogs.** `FileDialogFilter.MimeTypes` (macOS, Linux),
  `PickerResult<T>.Selected.SelectedFilter`, the macOS filter pop-up
  (`ShowFilterChoice`) and `IFileDialogs.OpenDirectoriesAsync` for several
  directories (`IDirectoryLeaseList`)
  ([#530](https://github.com/Runic-Artifex/runic-sdk/pull/530),
  [#532](https://github.com/Runic-Artifex/runic-sdk/pull/532)).
- **Trash and volumes.** `IDesktopTrash.MoveAllToTrashAsync` with progress,
  `ListAsync`, `RestoreAsync` (never replaces anything) and `EmptyAsync` on
  Windows and unsandboxed Linux. `DesktopVolume.IsEncrypted` and `UnlockMethod`;
  `IDesktopVolumes.UnlockAsync(id)` (BitLocker prompt),
  `UnlockAsync(id, passphrase, token)` (APFS, LUKS) and `MountAsync(id,
  DesktopVolumeMountOptions, token)`; Windows optical drives eject
  ([#530](https://github.com/Runic-Artifex/runic-sdk/pull/530),
  [#531](https://github.com/Runic-Artifex/runic-sdk/pull/531),
  [#532](https://github.com/Runic-Artifex/runic-sdk/pull/532)).
- **Secret storage.** `IDesktopSecretStore.GetBytesAsync`/`SetBytesAsync` store
  binary secrets up to 64 KiB. `DesktopSecretStoreOptions`
  (`AllowUserInteraction`, `RequireEncryption`, `UseDataProtectionKeychain`)
  goes to new `CreateSecretStore(options)` overloads of each provider and of
  `DesktopPlatformServices`
  ([#554](https://github.com/Runic-Artifex/runic-sdk/pull/554)). On Linux they
  work with the Secret Service, and sandboxes without it use the Secret portal
  in libsecret's file format
  ([#559](https://github.com/Runic-Artifex/runic-sdk/pull/559)).
- **Activation.** `IDesktopOpenRegistration` registers URL schemes and file
  types for the current user and never becomes the default (macOS
  `LSRegisterURL`, Windows `HKCU\Software\Classes`, Linux desktop entry).
  `DesktopOpenOptions.WebLinkHosts` turns `https` links to the application's
  hosts into open requests (universal links, app URI handlers).
  `PortalApplication.ExportApplicationAsync` serves D-Bus activation;
  `WindowsPlatformProvider.GetLaunch(args)` reads MSIX activations, and MSIX
  login startup uses the manifest's `StartupTask`. `IDesktopFileBookmarks` keeps
  file access across launches (macOS security-scoped bookmarks)
  ([#549](https://github.com/Runic-Artifex/runic-sdk/pull/549),
  [#550](https://github.com/Runic-Artifex/runic-sdk/pull/550),
  [#551](https://github.com/Runic-Artifex/runic-sdk/pull/551)).
- **Message boxes and network status.** `IWindowPlatformServices.MessageBoxes`
  (`IDesktopMessageBoxes.ShowAsync(DesktopMessageBox)`) shows a native message
  box owned by the window: a task dialog, an `NSAlert` sheet, `GtkMessageDialog`
  or `GtkAlertDialog`. `IDesktopNetworkStatus` reads and watches
  `DesktopNetworkState` (available, `Connectivity`, `IsMetered`)
  ([#555](https://github.com/Runic-Artifex/runic-sdk/pull/555),
  [#560](https://github.com/Runic-Artifex/runic-sdk/pull/560)).
- **Clipboard, badges and progress.** `IDesktopClipboard : ITextClipboard`
  reads and writes HTML, RTF, PNG and file lists, and watches the formats (never
  the content). `IWindowPlatformServices.SetBadgeAsync` and `SetProgressAsync`
  use the Windows taskbar, the macOS Dock and the Unity launcher API on Linux
  ([#570](https://github.com/Runic-Artifex/runic-sdk/pull/570),
  [#571](https://github.com/Runic-Artifex/runic-sdk/pull/571)).
- **Global shortcuts.** `IDesktopGlobalShortcuts` binds named actions to keys
  that work while another application has the focus. `BindAsync` reports each
  as `Bound`, `Unbound` (the default value), `Conflict` or `Refused`; `ListAsync`, `ConfigureAsync`,
  `Activated` and `BindingsChanged` complete it. Windows `RegisterHotKey`, macOS
  Carbon hot keys, and the Linux GlobalShortcuts portal
  ([#565](https://github.com/Runic-Artifex/runic-sdk/pull/565),
  [#567](https://github.com/Runic-Artifex/runic-sdk/pull/567)).
- **Monitors and drag out.** `IDesktopMonitors` lists and watches
  `DesktopMonitor`s; `IWindowPlatformServices.Monitors` (`ListAsync`, `WatchAsync`).
  `IWindowPlatformServices.StartDragAsync(DesktopDragData)` (default member).
  See [Runic Desktop and GTK 4](#runic-desktop-and-gtk-4)
  ([#535](https://github.com/Runic-Artifex/runic-sdk/pull/535),
  [#557](https://github.com/Runic-Artifex/runic-sdk/pull/557)).

### Navigation

- `NavigationRequestOptions.RetainView` decides per entry whether a
  presentation keeps that entry's view while it is retained;
  `NavigationEntry.RetainView` reports it
  ([#574](https://github.com/Runic-Artifex/runic-sdk/pull/574)).
- `INavigationPresentation.ForgetAsync` (default member) lets a presentation
  hold back the release of retired content; `NavigationRequestOptions.Requester`
  rejects a late request from an entry that is no longer current
  ([#536](https://github.com/Runic-Artifex/runic-sdk/pull/536)).
- `Runic.Navigation.ReactiveUI` and `.Reactive`
  ([#512](https://github.com/Runic-Artifex/runic-sdk/pull/512)):
  `region.WhenHistoryChanged()` observes the region's retained history;
  `ReactiveNavigationRegionGuard.WithInteraction(interaction, prompt,
  hasUnsavedChanges, discard)` creates a region guard that asks through a
  ReactiveUI `Interaction`; new warning `RUNICNAV002` for both flavors in one
  project without a Views ReactiveUI adapter.

### Views (.NET)

- **Wire-key command parameters.** `[RunicCommandKey(nameof(FindItem))]`
  presents a command whose parameter has no wire form, such as
  `ReactiveCommand<Item, RxVoid>`. The generated client sends the key, .NET
  resolves it with the named method (synchronous or asynchronous) and evaluates
  `CanExecute` with the resolved object. An unknown key is rejected with reason
  `unresolved-key`. ReactiveUI (both flavors), CommunityToolkit and `ICommand`.
  Misuse is `RUNICBRIDGE027`
  ([#526](https://github.com/Runic-Artifex/runic-sdk/pull/526),
  [#528](https://github.com/Runic-Artifex/runic-sdk/pull/528); fixes
  [#472](https://github.com/Runic-Artifex/runic-sdk/issues/472)).
- **Bridge input limit.** `MaximumInputBytes` on `RunicWindowOptions`,
  `RunicDesktopHostOptions`, `RunicCsWebUiHostOptions`,
  `WindowContentSessionOptions` and `RunicWindowTestHostOptions`: 1 MiB by
  default, from 1 KiB to 64 MiB
  ([#507](https://github.com/Runic-Artifex/runic-sdk/pull/507)).
- **Operation retirement.** `[RunicOperationRetirement(Keep | Cancel | Drain)]`
  declares what happens to an operation when the navigation entry whose page
  started it retires; `Cancel` and `Drain` defer the page's disposal until the
  operation ended. Event 1017, warning `RUNICBRIDGE028`
  ([#536](https://github.com/Runic-Artifex/runic-sdk/pull/536); fixes
  [#284](https://github.com/Runic-Artifex/runic-sdk/issues/284)).
- **ReactiveUI.** `command.RunAsync(input, cancellationToken)` runs a command
  from hand-written code as a generated Bridge call does: it completes after
  zero or more values, cancelling disposes the execution, and a failure is
  rethrown and never logged as event 1042. `ReactiveSchedulers.For(object
  viewModel)` schedules on the model context the ViewModel is bound to. The
  Views.ReactiveUI guide has a "Which call to use" section
  ([#511](https://github.com/Runic-Artifex/runic-sdk/pull/511); fixes
  [#471](https://github.com/Runic-Artifex/runic-sdk/issues/471)).
- **Read-your-writes.** A command's, setter's or checked write's reply reaches
  the page after the state frames the call produced on every View of the window,
  so code after `await view.command()` can read another View's `snapshot`
  ([#585](https://github.com/Runic-Artifex/runic-sdk/pull/585)).
- `RunicFailureException<TFailure>` carries a typed `Failure`
  (`RunicFailureException` is no longer sealed); the interaction exceptions get
  the standard constructors. `IBridgeUtf8Transport.PublishUtf8Async` receives
  state frames as UTF-8. `RunicPathChange.Entries` names the changed paths
  (`RunicPathChangeEntry`, `RunicPathChangeKind`, open)
  ([#517](https://github.com/Runic-Artifex/runic-sdk/pull/517)).
- `RunicFileDrop.Effect` (`RunicDropEffect`) and `RunicFileDrop.PromisedFiles`
  (`RunicPromisedFile`)
  ([#557](https://github.com/Runic-Artifex/runic-sdk/pull/557)).
- [`docs/runicbridge-diagnostics.json`](https://github.com/Runic-Artifex/runic-sdk/blob/v0.11.0/docs/runicbridge-diagnostics.json)
  lists every `RUNICBRIDGE` code with `id`, `severity` and `title` (schema
  version 1)
  ([#518](https://github.com/Runic-Artifex/runic-sdk/pull/518)).

### Views npm packages, wire and generated clients

- **`AbortSignal`.** `connect<Name>({ signal })`, `waitForBridge({ signal })`
  and an operation's `wait({ signal })` and `outcome({ signal })` reject with
  `signal.reason` when it aborts first. An aborted connect releases what it had
  connected; aborting an operation wait sends no cancellation
  ([#523](https://github.com/Runic-Artifex/runic-sdk/pull/523)).
- **`using`.** Generated clients and the controllers from
  `createViewController`, `createCommandController`,
  `createOperationController`, `createLatestOperationController` and
  `createCollectionViewportController` have `[Symbol.dispose]()` where the
  engine has `Symbol.dispose`
  ([#523](https://github.com/Runic-Artifex/runic-sdk/pull/523)).
- **`@runic-artifex/views-effect`.** `createEffectAction` returns an action with
  `[Symbol.asyncDispose]()`. `clientLayer(service, source)` provides a connected
  client as an Effect 4 `Context.Service` through a scoped `Layer`
  ([#523](https://github.com/Runic-Artifex/runic-sdk/pull/523)).
- **Wire-key commands.** Generated clients of `[RunicCommandKey]` commands take
  the key; `BridgeErrorReason` `unresolved-key` is now sent. Generated mocks take
  `resolveKey`, and `failNext(method, { kind: "rejected", reason })` injects a
  rejection with a reason (`MockErrorFailure.reason`)
  ([#526](https://github.com/Runic-Artifex/runic-sdk/pull/526),
  [#528](https://github.com/Runic-Artifex/runic-sdk/pull/528)).
- `shortcutFromEvent(event, options?)` returns the `DesktopShortcut` text for a
  `keydown` event, so a settings page can record a key for a global shortcut
  ([#565](https://github.com/Runic-Artifex/runic-sdk/pull/565)).
- `createMenuBarController`, `splitAccessKey` and `installMockMenuBar`; see
  [Menus](#menus).
- `@runic-artifex/views` registers `start` on the page's
  `runic.views.connection` channel, so a reader that sets `requested` (such as
  the Vite development client) observes the connection from page load
  ([#537](https://github.com/Runic-Artifex/runic-sdk/pull/537)).

### Framework adapters, SvelteKit and the Vite plugin

### Runic Desktop and GTK 4

- **Window visibility and close.** `DesktopWindow.SetVisibleAsync(bool)`,
  `HideAsync()` and `ShowAsync()` hide and show an embedded window without closing it (capability
  `Visibility`). `DesktopWindow.Closed` is raised once after the window closed,
  whatever closed it (event 3013 for a throwing handler)
  ([#508](https://github.com/Runic-Artifex/runic-sdk/pull/508)).
- **Monitors and full screen.** `DesktopHost.Monitors`;
  `DesktopWindowOptions.MonitorId` and `DesktopWindow.MoveToMonitorAsync` place a
  window on a monitor (capability `MonitorPlacement`; GTK on X11 only);
  `DesktopWindowState.MonitorId`. `DesktopWindow.SetFullScreenAsync(bool)`
  (capability `FullScreen`), and `DesktopWindowPlacement.FullScreen` restores a
  full-screen placement. Custom hosts implement `IDesktopPlacementWindowHost` and
  `IDesktopWindowHostFactory.Monitors`
  ([#535](https://github.com/Runic-Artifex/runic-sdk/pull/535),
  [#539](https://github.com/Runic-Artifex/runic-sdk/pull/539)).
- **Right to left and language** (opt-in). `DesktopWindowOptions.LayoutDirection`
  mirrors the window frame on Windows and the GTK widgets on GTK 3 and GTK 4
  ([#389](https://github.com/Runic-Artifex/runic-sdk/issues/389)).
  `DesktopWindowOptions.Language` (BCP 47) sets the WebView2 language and
  WebKitGTK's preferred languages. macOS and installed browsers ignore both
  ([#535](https://github.com/Runic-Artifex/runic-sdk/pull/535),
  [#539](https://github.com/Runic-Artifex/runic-sdk/pull/539)).
- **GTK 4 on X11** positions windows: `X`/`Y`, `MoveAsync` and saved placements
  ([#508](https://github.com/Runic-Artifex/runic-sdk/pull/508)).
- **File drag-out.** `DesktopWindow.StartDragAsync(DesktopDragData)` starts a
  native drag of files, text or URIs and returns the drop's effect (capability
  `FileDrag`; WebView2, WKWebView, GTK 3 and GTK 4). The paths come from the
  application, never the page. Custom hosts implement
  `IDesktopDragSourceWindowHost`
  ([#557](https://github.com/Runic-Artifex/runic-sdk/pull/557),
  [#566](https://github.com/Runic-Artifex/runic-sdk/pull/566),
  [#590](https://github.com/Runic-Artifex/runic-sdk/pull/590)).
- **Drops.** `DesktopFileDropEventArgs.Effect` and `PromisedFiles` (macOS file
  promises as read leases); the page attribute
  `data-runic-drop-effect="copy|move|link|none"` sets the drop effect; drops
  into same-origin iframes are delivered
  ([#557](https://github.com/Runic-Artifex/runic-sdk/pull/557),
  [#566](https://github.com/Runic-Artifex/runic-sdk/pull/566)).
- **Content-Security-Policy.** `DesktopSurfaceOptions.ContentSecurityPolicy`
  sends a policy with the surface's pages. The Views Bridge no longer needs
  `'unsafe-eval'`
  ([#541](https://github.com/Runic-Artifex/runic-sdk/pull/541),
  [#558](https://github.com/Runic-Artifex/runic-sdk/pull/558)).
- Menus, context menus and the global menu: see [Menus](#menus).
- On Windows, `DesktopWindow.AnnounceAsync` speaks through a hidden live region
  in the page while the page has the keyboard focus, so NVDA says it
  ([#584](https://github.com/Runic-Artifex/runic-sdk/pull/584)).

## Behaviour changes

- **Menu bars are shown by default.** A declared `DesktopHostOptions.MenuBar`
  now shows in Windows (WebView2) and GTK 3 and GTK 4 windows, which reported
  `menu-bar-unsupported` before; the client area shrinks by the bar's height.
  Declared shortcuts run their items on every presentation when the page does
  not call `preventDefault()`, and on Windows the browser's own accelerator for
  a declared key (F5, Ctrl+P, Ctrl+F) no longer acts. With `Page` or `None`,
  Alt or F10 alone no longer enters Windows' system-menu mode. Use
  `MenuBarPresentation = Page` or `None` to keep the bar out of the window
  ([#533](https://github.com/Runic-Artifex/runic-sdk/pull/533),
  [#553](https://github.com/Runic-Artifex/runic-sdk/pull/553),
  [#556](https://github.com/Runic-Artifex/runic-sdk/pull/556)).
  - `Validate` reports `menu-bar-unsupported` only for `Native` windows without
    a bar, and the reserved shortcuts per OS (Windows and Linux: Ctrl+Z/Y/X/C/V/A,
    Ctrl+Shift+Z, Alt+F4, F10).
  - The child of a `Native`, decorated GTK window (`NativeHandle`) is a vertical
    `GtkBox` holding the bar and the web view, even without a bar. Code that
    took the web view as the window's child takes the box's last child.
  - A throwing menu command target is logged as event 3014 instead of being
    swallowed on macOS; Views.Desktop menu commands receive the item's
    `CommandParameter` instead of `null`.
- **The Linux global menu takes the bar.** On X11 and on KDE Plasma Wayland, a
  GTK window's bar moves into the global menu while
  `com.canonical.AppMenu.Registrar` is owned. `LinuxDesktopOptions.GlobalMenu =
  false` keeps it in the window
  ([#569](https://github.com/Runic-Artifex/runic-sdk/pull/569),
  [#580](https://github.com/Runic-Artifex/runic-sdk/pull/580)).
- **Status icons.** Menus accept repeated command ids with different
  `CommandParameter`s. Calls with the wrong signature answer `InvalidArgs`, and
  more than 32 activations waiting for a slow `Activated` handler are dropped
  (`status-icon-activations-dropped`)
  ([#514](https://github.com/Runic-Artifex/runic-sdk/pull/514),
  [#569](https://github.com/Runic-Artifex/runic-sdk/pull/569)).
- **Bridge input limits.** Setter values and command arguments, unlimited
  before, are limited to the window's input limit (1 MiB by default). Checked
  writes, operation starts and interactions move from a fixed 64 KiB to the same
  limit, counted in UTF-8 bytes, so inputs up to 1 MiB are now accepted. Number
  strings are limited to 4 096 characters, a window runs at most 64 awaited
  command calls at once, and mounts are limited (token 256 characters, 64
  presentations per route and connection). Excess input is answered
  `rejected`/`invalid-input` or `invalid`. Raise `MaximumInputBytes` if a page
  legitimately sends more
  ([#507](https://github.com/Runic-Artifex/runic-sdk/pull/507)).
- **The validation summary no longer duplicates messages.** For a
  `ReactiveValidationObject`, a property rule's message no longer appears at
  `[]`, which now holds only object-level rules. A Toolkit
  `ObservableValidator`'s object-level result that names Bridge members is
  reported once, by its member. `hasErrors` and the `…Errors` arrays are
  unchanged ([#506](https://github.com/Runic-Artifex/runic-sdk/pull/506)).
- **Replies follow their state frames.** A reply can wait, at most 5 s, until
  the call's state frames on other Views were sent; before, those usually
  arrived after the reply
  ([#585](https://github.com/Runic-Artifex/runic-sdk/pull/585)).
- **No string evaluation for Bridge state.** Runic Desktop and CS-WebUI send
  Views state as raw data to the reserved `__runicViewsPush` instead of a
  script, and CS-WebUI continues cancelled navigations through
  `__runicContinueNavigation`. Pages see the same `__{route}Changed(state)`
  call; a `"__proto__"` key becomes an own property. A `runic-cswebui.js` from
  before this release receives no state
  ([#558](https://github.com/Runic-Artifex/runic-sdk/pull/558),
  [#561](https://github.com/Runic-Artifex/runic-sdk/pull/561)).
- **Framing and media.** Surface responses send `Content-Security-Policy:
  frame-ancestors 'self'` (plus `AdditionalOrigins`) and `X-Frame-Options:
  SAMEORIGIN`; a content handler's own policy is sent as a second header. A
  surface framed under another origin gets no Bridge credential. WKWebView
  denies camera and microphone without `MediaCapture` instead of prompting,
  WebKitGTK denies them while a cross-origin subframe exists, and Chromium-based
  browsers ask the user instead of granting
  ([#504](https://github.com/Runic-Artifex/runic-sdk/pull/504),
  [#541](https://github.com/Runic-Artifex/runic-sdk/pull/541)).
- **Asset archives leave out `.git` and `.env*`** at any depth (packer,
  `assets pack`, `RunicAssetsDist`); such an entry point is `RAS1002`. Source
  maps warn with `RAS1005`. `RunicAssetsDefaultExcludes=false` or
  `--no-default-excludes` restores the old behaviour
  ([#538](https://github.com/Runic-Artifex/runic-sdk/pull/538)).
- **`dotnet runic dev`.** With `runic()` in the Vite configuration, readiness
  needs `@runic-artifex/vite-plugin-runic` 0.11; an Angular project that
  declares the plugin needs `runicDevSessionProxy()` in its `proxyConfig`.
  Otherwise readiness times out with `RAPPDEV1007`. A window whose page has no
  Bridge is reloaded by navigating its WebView, and dynamic `import()` of
  relative or root paths in inline scripts goes to the development server
  ([#527](https://github.com/Runic-Artifex/runic-sdk/pull/527),
  [#546](https://github.com/Runic-Artifex/runic-sdk/pull/546),
  [#547](https://github.com/Runic-Artifex/runic-sdk/pull/547),
  [#586](https://github.com/Runic-Artifex/runic-sdk/pull/586)).
- **`dotnet runic doctor`** warns on Node 26 instead of failing, and
  `--fail-on warn` also fails on the new checks. The human `Help for <code>`
  line follows the fault line
  ([#527](https://github.com/Runic-Artifex/runic-sdk/pull/527),
  [#545](https://github.com/Runic-Artifex/runic-sdk/pull/545)).
- **New warnings** `RUNICNAV002`, `RUNICBRIDGE029` and `RUNICDBUS013` fail
  builds with `TreatWarningsAsErrors`
  ([#512](https://github.com/Runic-Artifex/runic-sdk/pull/512),
  [#513](https://github.com/Runic-Artifex/runic-sdk/pull/513),
  [#525](https://github.com/Runic-Artifex/runic-sdk/pull/525)).
- **npm.** Regenerated clients return
  `Promise<<Name>Client & globalThis.Disposable>`, and the `.d.ts` files need
  TypeScript 5.2 or later. An operation start rejected as `unavailable` sets
  `BridgeError.reason`. Under `vite dev` with the plugin's development client,
  the connection is observed from page load
  ([#523](https://github.com/Runic-Artifex/runic-sdk/pull/523),
  [#528](https://github.com/Runic-Artifex/runic-sdk/pull/528),
  [#537](https://github.com/Runic-Artifex/runic-sdk/pull/537)).
- **Windows and placements.** A placement saved full-screen restores
  full-screen (0.10 placements restore as before). On Windows `IsFullScreen` is
  also `true` after `SetFullScreenAsync(true)`. A macOS `Kiosk` window enters
  full screen. GTK 4 on X11 applies saved positions and `X`/`Y`. The connection
  timeout counts from the page's first request, so a page that never connects
  can take up to twice `ConnectionTimeout` to fail
  ([#508](https://github.com/Runic-Artifex/runic-sdk/pull/508),
  [#535](https://github.com/Runic-Artifex/runic-sdk/pull/535),
  [#539](https://github.com/Runic-Artifex/runic-sdk/pull/539),
  [#573](https://github.com/Runic-Artifex/runic-sdk/pull/573)).
- **Drops.** Same-origin iframe drops raise `FilesDropped`; macOS promised files
  raise an event with `PromisedFiles` and possibly empty `Paths`; GTK reports the
  negotiated `Effect` instead of always `Copy`
  ([#557](https://github.com/Runic-Artifex/runic-sdk/pull/557),
  [#566](https://github.com/Runic-Artifex/runic-sdk/pull/566)).
- **Capability snapshots** gain the new `platform.*` keys (directories, menus,
  monitors, drag, message boxes, clipboard data, taskbar). Code that compares
  the whole key set updates it
  ([#530](https://github.com/Runic-Artifex/runic-sdk/pull/530),
  [#533](https://github.com/Runic-Artifex/runic-sdk/pull/533),
  [#535](https://github.com/Runic-Artifex/runic-sdk/pull/535),
  [#555](https://github.com/Runic-Artifex/runic-sdk/pull/555),
  [#557](https://github.com/Runic-Artifex/runic-sdk/pull/557),
  [#570](https://github.com/Runic-Artifex/runic-sdk/pull/570)).
- **Platform services that now work.** WPF `AnnounceAsync` returns `Success`
  instead of `Unavailable`; MSIX login startup drives the manifest's
  `StartupTask`. Windows lists locked BitLocker volumes and macOS reports locked
  APFS volumes (`IsLocked`, `MountAsync` is `Failed(Locked)`); Windows optical
  volumes can eject; UDisks2 `OptionNotPermitted` is `Failed(InvalidData)`.
  Linux trash writes `directorysizes`
  ([#510](https://github.com/Runic-Artifex/runic-sdk/pull/510),
  [#531](https://github.com/Runic-Artifex/runic-sdk/pull/531),
  [#532](https://github.com/Runic-Artifex/runic-sdk/pull/532),
  [#550](https://github.com/Runic-Artifex/runic-sdk/pull/550)).
- **Linux secrets in sandboxes.** A Flatpak or Snap without Secret Service
  permission stores secrets through the Secret portal instead of reporting
  `Unavailable(BackendUnavailable)`
  ([#559](https://github.com/Runic-Artifex/runic-sdk/pull/559)). The first
  call after the portal starts is retried once when xdg-desktop-portal has not
  yet exported its Secret interface
  ([#599](https://github.com/Runic-Artifex/runic-sdk/pull/599)).
- **Windows saves** create the staging file with the replaced file's DACL
  instead of the folder's inherited ACL
  ([#515](https://github.com/Runic-Artifex/runic-sdk/pull/515)).
- **Linux portal.** Notification activations that match no notification the
  process showed keep only `http`, `https` or `mailto` links and are untrusted.
  Portal diagnostics are logged at their `Severity` (several `status-icon-*`,
  `login-startup-*` and `desktop-application-*` codes become Warning). One
  session connection per desktop identity; a pending request ends as
  unavailable when the portal exits. Exported D-Bus objects run at most 16
  calls with 64 waiting and refuse more with `LimitsExceeded`; raise
  `MaxConcurrentCalls` for calls that wait for a user
  ([#516](https://github.com/Runic-Artifex/runic-sdk/pull/516),
  [#521](https://github.com/Runic-Artifex/runic-sdk/pull/521),
  [#522](https://github.com/Runic-Artifex/runic-sdk/pull/522)).
- **Windows administration.** A firewall update that would produce an unscoped
  inbound allow rule throws `ArgumentException`; delete renames the checked
  rule before removing it. Remote WMI uses Kerberos with no NTLM fallback: name
  the server by DNS or NetBIOS name
  ([#588](https://github.com/Runic-Artifex/runic-sdk/pull/588)).
- **CS-WebUI.** An application-supplied WebUI library logs event 2101 once. A
  stalled client no longer holds back other windows
  ([#505](https://github.com/Runic-Artifex/runic-sdk/pull/505),
  [#587](https://github.com/Runic-Artifex/runic-sdk/pull/587)).
- **Templates.** New projects write `packages.lock.json`, refuse `eval` and
  `new Function` outside `Development`, and package with `dotnet runic package`.
  Existing projects are unchanged; a page dependency that evaluates strings
  needs `'unsafe-eval'` back
  ([#527](https://github.com/Runic-Artifex/runic-sdk/pull/527),
  [#562](https://github.com/Runic-Artifex/runic-sdk/pull/562),
  [#578](https://github.com/Runic-Artifex/runic-sdk/pull/578)).

## Security

These come from the security review before 1.0. None needs action unless noted.

- **SEC-05, SEC-10, SEC-11, SEC-24, SEC-37: framing, media and the
  credential.** Other origins can no longer frame the application, and frames
  under foreign documents get no Bridge credential. Camera and microphone are
  granted only to the presented origin on every embedded host, and installed
  browsers ask the user. The credential is compared in constant time. Sibling
  surfaces share an origin in an installed browser; use
  `DesktopSurfaceOptions.UseIsolatedListener` for less-trusted content
  ([#504](https://github.com/Runic-Artifex/runic-sdk/pull/504)).
- **SEC-22, SEC-23: CS-WebUI.** The README's "Security" section treats
  `SetPublic(true)`, serve-only and multi-client mode and an own WebUI build as
  security decisions. With a WebUI older than `efac0e24`, concurrent Bridge
  calls could run with each other's arguments
  ([#505](https://github.com/Runic-Artifex/runic-sdk/pull/505)).
- **SEC-15, SEC-16, SEC-25, SEC-26, SEC-27: Bridge input.** One size limit for
  all Bridge inputs, bounded number parsing, a cap on concurrent awaited
  commands and mount limits
  ([#507](https://github.com/Runic-Artifex/runic-sdk/pull/507)).
- **SEC-17: D-Bus.** The Linux status icon checks call signatures and bounds
  queued calls and activations; every exported `DBusObject` bounds its calls.
  Tray and global menu items can still be chosen by any session-bus peer: don't
  bind destructive actions to them without a confirmation
  ([#514](https://github.com/Runic-Artifex/runic-sdk/pull/514),
  [#521](https://github.com/Runic-Artifex/runic-sdk/pull/521),
  [#569](https://github.com/Runic-Artifex/runic-sdk/pull/569)).
- **SEC-28: Windows saves.** A save's temporary file had the folder's
  permissions, so a private file's new content could briefly be read by others
  in a shared folder. It now gets the target's
  ([#515](https://github.com/Runic-Artifex/runic-sdk/pull/515)).
- **SEC-09: notification activations.** Another session-bus process could send
  an activation with a link of its choice. Unmatched Linux activations are
  untrusted and keep only links the application could open anyway. **Action:**
  check the identifiers of activations with `IsTrusted == false` against your
  own state ([#516](https://github.com/Runic-Artifex/runic-sdk/pull/516)).
- **SEC-29: Linux secrets.** `RequireEncryption` (opt-in) refuses a Secret
  Service that offers only a `plain` session. Any process of the same user on
  the session bus can read every Secret Service item. Windows large secrets are
  DPAPI-encrypted files bound to their credential
  ([#554](https://github.com/Runic-Artifex/runic-sdk/pull/554)).
- **SEC-31: NuGet lock files.** Generated projects always write
  `packages.lock.json`; before, only `--nix` projects did
  ([#527](https://github.com/Runic-Artifex/runic-sdk/pull/527)).
- **SEC-32: asset archives.** `.git` and `.env*` files in build output could be
  embedded and served to web content. They are left out by default, and source
  maps warn ([#538](https://github.com/Runic-Artifex/runic-sdk/pull/538)).
- **SEC-12, SEC-33: `dotnet runic dev`.** A process that bound the reserved
  port first could have its page served as the application's entry. `dev` now
  confirms the session with every frontend the template generates. **Action:**
  a project created before 0.11 is checked only once it uses `runic()`,
  `runicDevSession()` or `runicDevSessionProxy()`
  ([#546](https://github.com/Runic-Artifex/runic-sdk/pull/546),
  [#547](https://github.com/Runic-Artifex/runic-sdk/pull/547)).
- **Content-Security-Policy.** Asset hosting, Desktop surfaces and the Views
  hosts take a policy, the Bridge no longer needs `'unsafe-eval'`, and new
  projects send a strict policy outside development. **Action (recommended):**
  add a policy to existing applications or drop `'unsafe-eval'` from it
  ([#541](https://github.com/Runic-Artifex/runic-sdk/pull/541),
  [#558](https://github.com/Runic-Artifex/runic-sdk/pull/558),
  [#561](https://github.com/Runic-Artifex/runic-sdk/pull/561),
  [#562](https://github.com/Runic-Artifex/runic-sdk/pull/562)).
- **SEC-14, SEC-30: Windows administration.** A firewall update can no longer
  create an inbound allow rule that create refuses, delete removes only the
  checked rule, and remote WMI authenticates the server with Kerberos first
  ([#588](https://github.com/Runic-Artifex/runic-sdk/pull/588)).
- **Guide and supply chain.** The new
  [security guide](https://github.com/Runic-Artifex/runic-sdk/blob/v0.11.0/docs/security.md)
  says what Runic protects by default and what an application checks itself.
  `SECURITY.md` states the pre-1.0 policy: security fixes ship as a patch of
  the latest minor. CI checks `PackageDownload` content hashes
  ([#540](https://github.com/Runic-Artifex/runic-sdk/pull/540)).

## Fixes

- A late call into a large View tree that was just released, such as a row's
  first `Snapshot` after its list page was left, is answered as released
  instead of `capability-not-admitted`/`failed`. Released routes are remembered
  in groups, one per release (up to 256 groups and 16 384 routes)
  ([#503](https://github.com/Runic-Artifex/runic-sdk/pull/503); fixes
  [#490](https://github.com/Runic-Artifex/runic-sdk/issues/490)).
- The `validation` summary no longer lists each ReactiveUI.Validation message
  twice; a `ReactiveValidationObject` is read through its `ValidationContext`.
  A CommunityToolkit `ObservableValidator`'s messages no longer appear twice
  ([#506](https://github.com/Runic-Artifex/runic-sdk/pull/506); fixes
  [#478](https://github.com/Runic-Artifex/runic-sdk/issues/478)).
- A setter value out of its type's range is answered `rejected`/`invalid-input`
  instead of `failed` with an error log
  ([#507](https://github.com/Runic-Artifex/runic-sdk/pull/507)).
- A ReactiveUI command cancelled after its page detached no longer ends the
  process when it reports the cancellation on `ThrownExceptions` without a
  subscriber
  ([#544](https://github.com/Runic-Artifex/runic-sdk/pull/544)).
- A page whose ReactiveUI operation is declared `Cancel` or `Drain` is disposed
  only after the command's work ended, not as soon as it reported `cancelled`
  ([#548](https://github.com/Runic-Artifex/runic-sdk/pull/548)).
- A ReactiveUI failure that `RunAsync` or a Bridge call received is no longer
  sometimes logged as event 1042 too
  ([#594](https://github.com/Runic-Artifex/runic-sdk/pull/594)).
- Closing a CS-WebUI window no longer logs `BridgeSnapshotDeliveryFailed` (1011)
  with `ObjectDisposedException`
  ([#585](https://github.com/Runic-Artifex/runic-sdk/pull/585)).
- `dotnet runic dev` without a development server no longer misses a reload
  that arrives while the page is loading, and reloads a window whose page has
  no Bridge (a half-written `index.html`, a build error page) on the next change
  ([#519](https://github.com/Runic-Artifex/runic-sdk/pull/519),
  [#586](https://github.com/Runic-Artifex/runic-sdk/pull/586); fixes
  [#520](https://github.com/Runic-Artifex/runic-sdk/issues/520)).
- A browser or WebView that starts slowly and requests its page shortly before
  `ConnectionTimeout` is no longer closed while it connects
  ([#573](https://github.com/Runic-Artifex/runic-sdk/pull/573)).
- When a WebView2 page does not connect within `ConnectionTimeout`, the message
  says what WebView2 did (navigation started, completed or failed with its
  status, or a failed process)
  ([#593](https://github.com/Runic-Artifex/runic-sdk/pull/593)).
- A GTK 4 window closed natively (title bar, `gtk_window_close`) completes
  `WaitForCloseAsync` and surface disposal; a GTK 4 window closed after a drag
  out no longer hangs before GTK 4.22
  ([#590](https://github.com/Runic-Artifex/runic-sdk/pull/590)).
- The embedded web server of Runic Desktop windows is rooted at the
  application directory and no longer reloads configuration. Started in the
  home directory, it put an inotify watch on every directory below it
  ([#607](https://github.com/Runic-Artifex/runic-sdk/pull/607); fixes
  [#606](https://github.com/Runic-Artifex/runic-sdk/issues/606)).
- Windows: a clipboard another application holds open is reported
  `ResourceBusy` and retried a bounded number of times instead of failing with
  `PermissionDenied`
  ([#582](https://github.com/Runic-Artifex/runic-sdk/pull/582); see
  [#438](https://github.com/Runic-Artifex/runic-sdk/issues/438)).
- A D-Bus dictionary that repeats a key keeps the last value instead of
  throwing `ArgumentException`
  ([#583](https://github.com/Runic-Artifex/runic-sdk/pull/583)).
- CS-WebUI bundles WebUI nightly `2b35db13f`: a client that stops reading no
  longer delays state pushes and replies in other windows, and navigation
  events carry their URL
  ([#587](https://github.com/Runic-Artifex/runic-sdk/pull/587)).

## Known issues

- Orca does not speak live regions on WebKitGTK
  ([#318](https://github.com/Runic-Artifex/runic-sdk/issues/318)).
- macOS has no public Trash API for `ListAsync`, `RestoreAsync` and
  `EmptyAsync`; they report `Unavailable`. Sandboxed trashing of a symbolic link
  stays `Unavailable` (xdg-desktop-portal 1.22.1 refuses it)
  ([#531](https://github.com/Runic-Artifex/runic-sdk/pull/531),
  [#532](https://github.com/Runic-Artifex/runic-sdk/pull/532)).
- WebView2 drops carry no `PromisedFiles`, and text and URI drops raise no
  native event. GTK 4 on X11 does not cancel a drag out with Escape
  ([#557](https://github.com/Runic-Artifex/runic-sdk/pull/557),
  [#566](https://github.com/Runic-Artifex/runic-sdk/pull/566)).
- On Wayland, GTK windows cannot be positioned or moved to a monitor except by a
  full-screen placement, and monitors report no work area or primary monitor.
  macOS and installed browsers ignore `LayoutDirection` and `Language`
  ([#535](https://github.com/Runic-Artifex/runic-sdk/pull/535),
  [#539](https://github.com/Runic-Artifex/runic-sdk/pull/539)).
- The Wayland global menu needs KDE's `org_kde_kwin_appmenu`; GNOME, wlroots
  compositors and COSMIC keep the bar in the window. On macOS `Page` and `None`
  keep the declared menus in the shared application bar. Windows and Linux bars
  have no standard menus, and Windows menus stay light in dark mode
  ([#533](https://github.com/Runic-Artifex/runic-sdk/pull/533),
  [#553](https://github.com/Runic-Artifex/runic-sdk/pull/553),
  [#580](https://github.com/Runic-Artifex/runic-sdk/pull/580)).
- GTK 4 message boxes need GTK 4.10. Linux badges and progress need the
  application ID. Linux global shortcuts need a GlobalShortcuts portal backend
  (`ConfigureAsync`: interface version 2); Windows and macOS refuse some keys,
  such as F12 and ⌘Q
  ([#560](https://github.com/Runic-Artifex/runic-sdk/pull/560),
  [#565](https://github.com/Runic-Artifex/runic-sdk/pull/565),
  [#567](https://github.com/Runic-Artifex/runic-sdk/pull/567),
  [#571](https://github.com/Runic-Artifex/runic-sdk/pull/571)).
- CS-WebUI cannot read the native WebUI version, so event 2101 fires for every
  application-supplied library; such a library needs WebUI `efac0e24d` or later
  ([#587](https://github.com/Runic-Artifex/runic-sdk/pull/587)).
- `DesktopSurface.ExecuteJavaScriptAsync` and CS-WebUI's `RunJavaScript` still
  need `'unsafe-eval'`, and development servers are not covered by the
  template's policy ([#562](https://github.com/Runic-Artifex/runic-sdk/pull/562)).
- Left to manual checks, not CI: multiple monitors and mixed DPI, native dialog
  filters, BitLocker unlock, drag-out to file managers, universal links and app
  URI handlers, D-Bus activation from GNOME and KDE, and Narrator speech
  ([#529](https://github.com/Runic-Artifex/runic-sdk/pull/529),
  [#535](https://github.com/Runic-Artifex/runic-sdk/pull/535),
  [#557](https://github.com/Runic-Artifex/runic-sdk/pull/557)).
