- **A page generated from another build of its ViewModel no longer connects silently in development.** A generated
  client embeds its View's contract, `"{ViewModel}:{fingerprint}"`, but nothing compared it with the application's
  Bridge when a page connected, so a page from a stale `generated/` folder or a frontend package built from an earlier
  library decoded the state with the wrong members and codecs, without a diagnostic (#1324). With the new Views
  protocol feature `view-contract/1`, `Runic.Application.Views` names the route's contract in each `open` reply, and
  the development build of `@runic-artifex/views` compares it with the page's: on a mismatch the View fails to connect
  with a `BridgeError` saying the page and the application were generated from different builds, and one `contract`
  diagnostic (`onBridgeDiagnostic`, the Runic DevTools dock) names the View and both fingerprints. The production
  build does not list the feature and connects as before, and a .NET host before 0.24 names no contract, so its pages
  are not checked.
