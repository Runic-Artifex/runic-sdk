# Runic SDK 0.5.0-preview.1

This preview replaces the former Application Bridge with a Window/View application model. It is a breaking change for applications built with earlier previews.

## Changes

- `Runic.Application.Views` provides typed Windows, Views, DataContext, mounted View lifetimes, generated C# attachments, and ordinary TypeScript clients.
- `Runic.Application.Views.CsWebUi` and `Runic.Application.Views.CsWebUi.DependencyInjection` provide the current native window host and scoped Window construction. `Runic.Application.Views.ReactiveUI` adds ReactiveUI routing.
- The CS-WebUI dependency is updated to `2.5.0-beta.4.5`; the Reactive Notes server sample stops WebUI before disposing its native window after a client disconnect.
- The Svelte and Angular outlets are available as `@runic-artifex/views-svelte` and `@runic-artifex/views-angular`. React, Vue, and plain TypeScript can use the generated client directly.
- The React, Vue, Svelte, and Angular starter templates and `dotnet runic dev` use the selected Window/View build. The .NET build generates the TypeScript contract and frontend output.
- Independent CommandLine, Desktop, Platform, Assets, and Translations packages remain available.

## Install and migrate

Install the matching starter template with `dotnet new install Runic.Application.Templates::0.5.0-preview.1`, then create a project with `dotnet new runic-app-svelte -n MyApp` (or choose `runic-app-react`, `runic-app-vue`, or `runic-app-angular`). Run `dotnet tool restore` in the generated project before `dotnet runic dev`.

Existing preview applications must replace old `Runic.Application`, `Runic.Application.Bridge`, and their host packages with the Views packages. Define an explicit partial `RunicWindow<TViewModel>`, and use typed `RunicView<TViewModel>` contracts for mounted content. Replace old npm Bridge clients and tooling with the generated TypeScript modules and the Views outlet for the chosen framework. There is no compatibility adapter or automatic fallback.

## Known limits

- CS-WebUI retains native route registrations until a window closes. Applications should reuse page identities for long-lived windows.
- View selection currently uses explicit concrete contracts. Dynamic routed lists, interface-based DataContext selection, and derived-model dispatch are not yet part of the generated contract.
- An edit to a generated contract still needs a restart and reconnect. .NET Hot Reload can cover supported method-body and getter edits, but does not replace contract regeneration.
- CS-WebUI is the Views host in this preview. A richer Runic Desktop host adapter and native dialogs, menus, and tray integration are not included.
- The Translations Editor supports one browser client per `serve` window. Its facade serializes calls and rejects mismatched responses, but concurrent independent clients can interleave response data. Multi-client response isolation needs richer generated command results.
