# Runic SDK 0.7.0-preview.10

Install matching `0.7.0-preview.10` packages from NuGet and npm. Command Line
versions remain independent of this SDK.

## Views

- A ViewModel, View or type named like a binding that the generated TypeScript
  client declares for its own use no longer breaks `tsc`
  ([#258](https://github.com/Runic-Artifex/runic-sdk/issues/258)). Before, a
  `WireViewModel` generated a public `WireState` that clashed with the
  client's internal `WireState` type (TS2395, TS2456). So did `ViewViewModel`
  (`ViewClient`, `connectView`), a `BridgeViewModel` with an interaction or a
  Stream command `StreamCommand` (`BridgeInteractionContext`,
  `BridgeStreamOperation`), a `BridgeValidationViewModel` with validation
  (`BridgeValidationState`), `TypedViewViewModel` in its mock
  (`mockTypedView`), a ViewModel that presents another named like its own
  `…References` page cache, and a record named `bridgeWire`. Such a module now
  uses `_WireState`, imports `ViewClient as _ViewClient`, and so on; the
  exported names are unchanged, and every other generated module is unchanged.
- The generated C# bridges and the `AddRunicBridges`/`AddRunicViews`
  registration name every Runic and dependency injection type with `global::`,
  so a type in the ViewModel's namespace named like one of them, such as
  `PropertyDescriptor<T>` or `WindowContentSession`, no longer breaks the
  build. A type named like the generated bridge, such as `CounterBridge` beside
  `CounterViewModel`, is reported as `RUNICBRIDGE004` at its declaration
  instead of as a C# error in the generated file.

## Bridge generation in WPF and Desktop applications

- The ViewModels of a single-project WPF application generate again
  ([#269](https://github.com/Runic-Artifex/runic-sdk/issues/269)). Before,
  each of them failed with `RUNICBRIDGE005` ("Could not load file or assembly
  'PresentationFramework'") when the assembly had WPF's `[ThemeInfo]` or
  `[XmlnsDefinition]` attributes, when a `[RunicIgnore]` property had a WPF
  type such as `ImageSource`, or when a method was an iterator over WPF
  objects. The generator now reads attribute names from metadata and checks
  `[RunicIgnore]`, including one inherited by an override, before it resolves
  a property's type. A ViewModel member that the Bridge exposes with a WPF
  type is reported as `RUNICBRIDGE005` at that member, and a View that cannot
  be loaded is named, instead of one assembly-wide load failure.
- An application with types from the ASP.NET Core shared framework, which every
  Runic Desktop application uses through `Runic.Desktop`, generates its Bridge
  ([#270](https://github.com/Runic-Artifex/runic-sdk/issues/270)). Before, a
  `BackgroundService` in the application assembly failed the generation with
  `RUNICBRIDGE005`. The build now passes the application's shared frameworks
  to the generator, which loads their assemblies from the installed framework
  of its own runtime version. Windows Desktop types are still skipped on every
  OS, so a Windows application generates the same Bridge when it is built on
  Linux or macOS. Any other type that cannot be loaded is skipped too, unless
  it is a Runic View or may be one (its base class is in an assembly that could
  not be loaded), and is reported as the new warning `RUNICBRIDGE020`. With
  optional generation and no Views, such a skip is `RUNICBRIDGE005` and the
  generated output is kept.
- **Breaking:** a ViewModel property that overrides a `[RunicIgnore]` base
  property is now left out of the generated Bridge too. Attributes on
  properties are inherited, and the contract fingerprint that Hot Reload
  compares already left it out, so before, the generated Bridge and the
  fingerprint disagreed for such a property. To keep it in the Bridge, remove
  `[RunicIgnore]` from the base property, or declare the derived property with
  `new` instead of `override`, so it does not inherit the attribute.

## Status icon and window presentation on Windows

- `PlatformServices.CreateStatusIcon()`, and the `IDesktopStatusIcon` that
  `AddRunicPlatformServices()` registers, now show a notification-area icon on
  Windows instead of reporting `ProviderNotConfigured`. A click or Space/Enter
  raises `Primary`, a middle click `Secondary`, and the context menu raises
  `MenuItem` for the chosen command. The icon is drawn from the state's RGBA
  images; theme names are ignored, and an icon without images shows the
  application's own icon. Windows has no attention state, so `NeedsAttention`
  shows the attention icon. The tooltip is cut to 127 characters. After
  Explorer restarts, the icon is added again. `WM_CLOSE` from another process
  leaves the icon in place; when the session ends, the icon is removed.
- `PlatformServices.PresentAsync` now restores a minimized or hidden Desktop
  window on Windows and brings it to the foreground, instead of reporting
  `ProviderNotConfigured`. `ApplicationInstance.ClaimAsync` lets the running
  instance take the foreground before it forwards a second launch, so the
  status icon sample's second launch brings its window forward. When Windows
  still refuses the foreground, the taskbar button flashes and the result is
  `Failed(PermissionDenied)`.

  WPF windows have no `PresentAsync` path yet
  ([#267](https://github.com/Runic-Artifex/runic-sdk/issues/267)).

## Watching files from ViewModels

- `RunicPathWatcher` (Runic.Application.Views) watches files, symbolic links,
  directory entries and a Git checkout's `HEAD`, and calls back in a turn of the
  model context, so a ViewModel refreshes when `/run/current-system` is
  re-pointed, a profile generation is added or a branch moves, instead of when a
  page connects. `RunicWatchTarget.Link` follows a link's whole chain and
  reports a re-pointed link even when it was replaced by a rename;
  `RunicWatchTarget.GitHead` reads `HEAD`, loose refs and `packed-refs` without
  starting `git`, also in linked worktrees, with symbolic refs and with the
  reftable format. Events are debounced and compared with the targets'
  previous state. A directory deleted and created again, as by `rm -rf` and
  `git clone`, is watched again at once. Problems such as a missing directory,
  a checkout that is not a repository, lost events or an exhausted inotify
  limit reach a callback, and the watcher polls where events cannot be
  trusted, including network, FUSE and virtiofs file systems. See
  [Watching files](https://github.com/Runic-Artifex/runic-sdk/blob/v0.7.0-preview.10/packages/dotnet/Runic.Application.Views/README.md#watching-files).
- `RunicPathWatchTester` (Runic.Application.Testing) runs watchers on a fake
  clock, awaits their next change, and reports a change of a path a test cannot
  modify.

## macOS desktop services

- `PlatformServices.CreateStatusIcon` and the `IDesktopStatusIcon` that
  `AddRunicPlatformServices` registers show an `NSStatusItem` in the macOS
  menu bar, with or without an open window, instead of reporting
  `ProviderNotConfigured`. A click raises the primary activation, and a right
  click or a Control-click opens the menu built from the state, and so does
  VoiceOver's show-menu action. Monochrome
  images become template images, which the menu bar tints for light and dark
  mode, and `NeedsAttention` shows the attention icon. An icon with only a
  theme name shows its title, because macOS has no icon theme. A windowless
  application without a bundle has no Dock icon until it opens a window; a
  bundle that never wants one sets `LSUIElement`.
- `PlatformServices.CreateLoginStartup` registers the application bundle as a
  login item with `SMAppService` on macOS 13 and later. A login item that waits
  for the user's approval, or that the user turned off in System Settings,
  reports `PermissionDenied` with a diagnostic that names the setting. A
  process outside an application bundle reports `BackendUnavailable`. macOS
  starts the bundle without the request's arguments.
- `PlatformServices.PresentAsync` activates the application and brings a
  Desktop window forward on macOS, also a hidden or minimized one.
- The Desktop event loop on macOS now handles AppKit events and the main
  dispatch queue while no window is open, which the status icon of a
  windowless application needs. Without it a macOS status icon reports
  `BackendUnavailable` instead of waiting.

## Runic Desktop keyboard and zoom

- Command and + or =, Command and − and Command and 0 zoom the page of a Runic
  Desktop window on macOS in the browser steps of Linux, from 30 % to 300 %,
  and reset it ([#259](https://github.com/Runic-Artifex/runic-sdk/issues/259)).
  The host adds them to the View menu of the main menu, which it creates when
  the application has none. The page receives each key first: a page that
  handles one itself calls `preventDefault()`, and the window then does not
  zoom. A trackpad pinch magnifies the page, as in Safari. The web view now has
  keyboard focus when the window opens, so keys reach the page without a click
  first.
- The macOS host also adds the standard application menu (About, Hide, Hide
  Others, Show All and Quit), an Edit menu (Undo, Redo, Cut, Copy, Paste and
  Select All) and a Window menu, completing AppKit's empty default menu, unless
  the application supplies its own main menu
  ([#272](https://github.com/Runic-Artifex/runic-sdk/issues/272)). Command and
  A, C and V now select, copy and paste in text fields of a Runic Desktop
  window on macOS, and the other editing keys use the same standard actions.
  Quit asks every window to close, as its close button does, so close guards
  apply.

## Privileged actions

- New package `Runic.Platform.Linux.Polkit` and the `IDesktopPrivilegedActions`
  contract in `Runic.Platform` run a step the application declared at build
  time as root, after Polkit's authentication prompt. Declare each action once
  as a `RunicPrivilegedAction` item with its program, verb, message and allowed
  arguments; Runic.Platform's build targets validate the items and write a
  `PrivilegedActions` class for both the application and the privileged
  program, and Runic.Platform.Linux.Polkit writes the Polkit policy to
  `share/polkit-1/actions/` in the output and publish directories. Install the policy with the application. Actions take an argument
  vector, never a shell command line, stream their output, and report denied,
  dismissed and unavailable authorization as distinct results. The privileged
  program uses `PolkitHelper.Match`, which resets the working directory, umask,
  signals and limits pkexec takes over from the caller and refuses to act
  unless pkexec started it as root. Windows and macOS have no provider yet and
  report unavailable. See the
  [package guide](https://github.com/Runic-Artifex/runic-sdk/blob/v0.7.0-preview.10/packages/dotnet/Runic.Platform.Linux.Polkit/README.md)
  and the [design and security review](https://github.com/Runic-Artifex/runic-sdk/blob/v0.7.0-preview.10/specs/platform/privileged-operations.md).
