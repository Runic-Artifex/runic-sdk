# Runic SDK 0.7.0-preview.10

Install matching `0.7.0-preview.10` packages from NuGet and npm. Command Line
versions remain independent of this SDK.

## Views

- A ViewModel, View or type named like a binding that the generated TypeScript
  client declares for its own use no longer breaks `tsc`
  ([#258](https://github.com/Runic-Artifex/runic-sdk/issues/258)). Before, a
  `WireViewModel` generated a public `WireState` that clashed with the
  client's internal `WireState` type (TS2395, TS2456). So did `ViewViewModel`
  (`ViewClient`, `connectView`), a `BridgeViewModel` with an interaction or a
  Stream command `StreamCommand` (`BridgeInteractionContext`,
  `BridgeStreamOperation`), a `BridgeValidationViewModel` with validation
  (`BridgeValidationState`), `TypedViewViewModel` in its mock
  (`mockTypedView`), a ViewModel that presents another named like its own
  `…References` page cache, and a record named `bridgeWire`. Such a module now
  uses `_WireState`, imports `ViewClient as _ViewClient`, and so on; the
  exported names are unchanged, and every other generated module is unchanged.
- The generated C# bridges and the `AddRunicBridges`/`AddRunicViews`
  registration name every Runic and dependency injection type with `global::`,
  so a type in the ViewModel's namespace named like one of them, such as
  `PropertyDescriptor<T>` or `WindowContentSession`, no longer breaks the
  build. A type named like the generated bridge, such as `CounterBridge` beside
  `CounterViewModel`, is reported as `RUNICBRIDGE004` at its declaration
  instead of as a C# error in the generated file.
