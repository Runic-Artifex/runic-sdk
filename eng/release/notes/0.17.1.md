# Runic SDK 0.17.1

Install matching `0.17.1` packages from NuGet and npm;
`Runic.Application.Views.CsWebUi` is `0.17.1-preview.1`.
Tested with Runic Translations 0.9.1 and Runic Command Line 0.11.0.

This patch release lets a NativeAOT application that links a Rust static library
of its own use the native Desktop server
([#859](https://github.com/Runic-Artifex/runic-sdk/issues/859)). It adds one
MSBuild property and one build diagnostic, and changes no Runic API.

## Desktop

- `Runic.Desktop.NativeServer`: a NativeAOT application that links a Rust
  static library of its own can use the native server
  ([#859](https://github.com/Runic-Artifex/runic-sdk/issues/859)). Before, the
  publish always linked the server's static library, and with a second Rust
  static library the link failed on duplicate symbols of Rust's standard
  library (`rust_eh_personality`, `std::panicking::EMPTY_PANIC`,
  `ARGV_INIT_ARRAY`). The new MSBuild property
  `RunicDesktopNativeServerLinkage` chooses how a NativeAOT publish gets the
  server: `Static` links the static library as before and stays the default,
  `Shared` puts the shared library beside the executable, and `Application`
  leaves the server to the application's own static library, which depends on
  the `runic-server` crate at the `v0.17.1` tag and exports its C functions, so
  the program keeps one standard library and one executable. Any other value
  fails with
  [`RUNICDESK006`](https://github.com/Runic-Artifex/runic-sdk/blob/v0.17.1/docs/diagnostics.md#runicdesk006).
  With `RunicDesktopNativeServerLibraryDirectory`, as `buildRunicApplication`
  sets it, a NativeAOT build now copies the shared library to the build output
  as a JIT build does, and the publish leaves it out unless it is `Shared`. See
  [NativeAOT and an application's own Rust library](https://github.com/Runic-Artifex/runic-sdk/blob/v0.17.1/packages/dotnet/Runic.Desktop.NativeServer/README.md#nativeaot-and-an-applications-own-rust-library).

## What to update

- Raise the Runic package versions in your project to `0.17.1`. Nothing changes
  for an application that does not set `RunicDesktopNativeServerLinkage`.
- An application on `Runic.Desktop.Kestrel` only because its own Rust static
  library could not link beside the native server can move to
  `Runic.Desktop.NativeServer` with `RunicDesktopNativeServerLinkage` set to
  `Application` or `Shared`.
