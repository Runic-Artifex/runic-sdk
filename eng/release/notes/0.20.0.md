# Runic SDK 0.20.0

Install matching `0.20.0` packages from NuGet and npm;
`Runic.Application.Views.CsWebUi` is `0.20.0-preview.1`.

## `@runic-artifex/angular` in the Angular Package Format (#945)

`@runic-artifex/angular` is built with ng-packagr and published in the Angular
Package Format: one partially compiled FESM bundle per entry point under
`dist/fesm2022/`, with its typings under `dist/types/`, in place of the per-file
`ngc` output under `dist/esm/`. Imports don't change: `@runic-artifex/angular`,
`@runic-artifex/angular/forms` and `@runic-artifex/angular/experimental` export
the same API, and the Angular CLI builds and tests an application with them as
before. Bundlers that run the Angular linker only on APF files now link the
package too: a production `vite build` with `@analogjs/vite-plugin-angular`
failed in the browser with "JIT compiler unavailable" and now renders the page.

## Bridge errors while you type, with code fixes (#962)

`Runic.Application.Views` ships Roslyn analyzers for the Bridge rules that the
source alone shows. Until now the Bridge generator, a build step that IDEs skip
in their design-time builds, reported them only after a build. Visual Studio,
Rider and VS Code's C# extension now report them while you type, with the
generator's ID, message and help link. Examples are a command named `NewCommand`
or `ThenCommand` (`RUNICBRIDGE004`), a command without the `Command` suffix or a
plain `ICommand` without `[RunicCommandInput]` (`RUNICBRIDGE009`), and a
`ViewRequest<T>`, interaction, navigation slot or `[RunicCollection]` with a
public setter. Code fixes rename the command, or its CommunityToolkit
`[RelayCommand]` method, make the setter private, or make a Window, View or
ViewModel public. Projects that reference `Runic.Application.Views` through a
host adapter get the analyzers too. The
[diagnostics catalog](https://github.com/Runic-Artifex/runic-sdk/blob/v0.20.0/docs/diagnostics.md#errors-while-you-type)
lists the rules.

Builds don't change: the generator still checks every rule and runs before the
compiler, so a build reports each error once.
