- Under `dotnet runic dev` with a Vite or Angular development server, a URL that the
  page builds at run time relative to its document, such as
  `<img src="brand/logo.svg">`, a file of Vite's `publicDir` or one that a Vite
  plugin's middleware serves, no longer 404s on the Window's origin (#1085). Runic
  Desktop forwards a `GET` or `HEAD` that neither `www/` nor the application's
  `Resources` answer to the development server, and CS-WebUI redirects it there.
  The Vite DevTools dock loads its script, its connection file and its icon from the
  server only, so its button shows its icon again (#1086): the development document
  points the dock's loader at the server, and the Window's listener redirects
  root-relative paths outside every Window, such as `/__devtools-assets/`, to the
  same path on the server.
  - This works only in the `Development` environment, with the server address that
    `dev` passes (`RUNIC_APPLICATION_VITE_DEV_SERVER` or
    `RUNIC_APPLICATION_FRONTEND_DEV_SERVER`, a loopback `http:` origin). Only `GET`
    and `HEAD` requests are passed on, from a loopback peer with a loopback `Host`,
    and only same-origin or user-initiated fetches (`Sec-Fetch-Site`); on CS-WebUI,
    WebUI's own cookie check and a loopback-only window stand for these. Cookies and
    `Origin` are not forwarded, only successful answers come back, and Vite's
    `/__open-in-editor` is never passed on. WebSockets are not forwarded; Vite's
    client connects to the server itself.
  - A Window that an IDE starts under `dotnet runic dev --no-window` does not get
    the server's address yet, so it still answers 404 for these paths.
