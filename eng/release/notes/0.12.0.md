# Runic SDK 0.12.0

Install matching `0.12.0` packages from NuGet and npm;
`Runic.Application.Views.CsWebUi` is `0.12.0-preview.1`.
Command Line versions remain independent of this SDK.

0.12.0 is a release for macOS. It comes before the release candidates because
better macOS support was worth breaking changes, and a minor release before 1.0
may break (D044, D045). Runic Desktop now owns the AppKit application on macOS:
`DesktopEventLoop.Run` runs `[NSApp run]` with Runic's application delegate,
every quit takes one cancellable path, and window coordinates use a top-left
origin like the other platforms. Packaging can sandbox an application, build a
Mac App Store `.pkg`, and lays out and signs bundles correctly; `dotnet run`
starts a development bundle. Intel Macs (`osx-x64`) and universal bundles are no
longer supported. After 0.12.0 come the release candidates `1.0.0-rc.N`, which
take only fixes, stabilization and documentation, and then 1.0.0. See
[Versioning and support from 1.0](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/eng/release/README.md#versioning-and-support-from-10).

Every API 0.12.0 adds is final for 1.0: none is experimental. No public API is
removed: package validation passes against the 0.11.0 baselines without
suppressions, and Views protocol 3 is unchanged. The breaking changes are
behaviour on macOS, the supported macOS architectures and the layout of macOS
packages; see [Upgrading](#upgrading) and [Breaking changes](#breaking-changes).

Highlights:

- **macOS lifecycle:** AppKit's own run loop instead of a polling loop, one quit
  path for Command and Q, Dock › Quit and logout with `ConfirmQuitAsync`,
  `ReopenRequested`, a Dock menu, a forwarding application delegate, and
  `DesktopEventLoop.InvokeOnMainThreadAsync` for applications without a window.
- **macOS windows:** top-left coordinates in points with migration of saved
  placements, a hidden or transparent title bar with CSS drag regions, frameless
  windows that take keyboard input, downloads, and a light or dark override
  (`ColorScheme`, also on Windows).
- **Documents:** document leases that save back to an opened file as often as
  the application saves, on Windows, Linux and macOS, including the App Sandbox;
  bookmarks from leases.
- **macOS packaging:** opt-in App Sandbox, provisioning profiles and `.pkg`
  installers for the Mac App Store, system file types with the right rank,
  camera and microphone usage strings, resources in `Contents/Resources` and
  nested code signed inside out; `dotnet run` runs from an ad-hoc signed
  development bundle.
- **Elsewhere:** the build tools roll forward to a newer .NET, the Nix flake
  creates projects and installs file types, and a Flatpak reaches the global menu.

## Upgrading

Update every Runic NuGet and npm package to 0.12.0 together and rebuild. Code
that compiled against 0.11.0 compiles unchanged. Outside macOS only file saves
change behaviour. Check these if they apply to you; the
[migration guide](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/docs/migration-1.0.md#from-011-to-012)
has before and after snippets:

- macOS: quitting cancels `host.ShutdownRequested`, also with no window open. An
  application that keeps running without a window sets
  `HandlesShutdownWithoutWindow` and ends on the token; save prompts move to
  `ConfirmQuitAsync` or the close guards
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- macOS: an application that sets `NSApp.delegate` itself passes its delegate as
  `DesktopHostOptions.MacOS.ForwardingApplicationDelegate` instead
  ([#628](https://github.com/Runic-Artifex/runic-sdk/pull/628),
  [#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- macOS: positions the application computes itself (from `NSScreen` frames, or
  stored outside `DesktopWindowPlacement`) are flipped to top-left. Saved
  placements need nothing
  ([#637](https://github.com/Runic-Artifex/runic-sdk/pull/637)).
- macOS: publish and package for `osx-arm64` only; `osx-x64` and universal
  bundles are refused
  ([#625](https://github.com/Runic-Artifex/runic-sdk/pull/625)).
- macOS packaging: a `macos/Info.plist` override adds `{{UsageDescriptions}}`
  when the project sets a camera or microphone usage description, and
  `{{ApplicationCategory}}` for `RunicMacApplicationCategory`; a
  `macos/entitlements.plist` override adds `{{Entitlements}}` for `--sandbox`,
  `--provisioning-profile` and the usage descriptions. Files that are not code
  move to `Contents/Resources`
  ([#627](https://github.com/Runic-Artifex/runic-sdk/pull/627),
  [#633](https://github.com/Runic-Artifex/runic-sdk/pull/633)).
- macOS: `dotnet run`, `dotnet watch` and `dotnet runic dev` start a development
  bundle; `<RunicMacDevelopmentBundle>false</RunicMacDevelopmentBundle>` runs the
  build output as before
  ([#634](https://github.com/Runic-Artifex/runic-sdk/pull/634)).
- Windows: a save whose target another program holds open without delete
  sharing is `NotCommitted(ResourceBusy)` instead of `CommitUnknown(IOError)`
  ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)).

### Compatibility

- **macOS 15 or later on Apple silicon (`osx-arm64`).** Intel Macs (`osx-x64`)
  are not a Runic target, and `dotnet runic package macos` builds no universal
  bundle. macOS 15 stays the documented minimum, the oldest macOS .NET 10
  supports; no Runic API needs a newer one. CI tests only the latest macOS on
  Apple silicon (today macOS 26)
  ([#625](https://github.com/Runic-Artifex/runic-sdk/pull/625); D045.7,
  D046.3).
- **Runic Command Line 0.9.0.** The SDK tools use the same Command Line as in
  0.11.0. No SDK library package depends on Command Line.
- **.NET.** .NET 10 remains the tested runtime. The build tools (the Bridge
  generator, the assets packer, `dotnet-runic` and `runic-create`) roll forward
  to a newer major runtime, so an application builds on a machine with only a
  newer .NET SDK, such as .NET 11
  ([#620](https://github.com/Runic-Artifex/runic-sdk/pull/620); fixes
  [#614](https://github.com/Runic-Artifex/runic-sdk/issues/614)).
- **Angular.** The Angular starter uses `@angular/build` and `@angular/cli`
  22.2.4 ([#620](https://github.com/Runic-Artifex/runic-sdk/pull/620)).
- **Release channels.** From `1.0.0-rc.1` on, npm `latest` stays on 0.12.0 until 1.0.0 is published,
  release candidates are GitHub prereleases and 1.0.0 is a release, and
  `Runic.Application.Views.CsWebUi` keeps a `-preview.N` version of the release's
  number (`1.0.0-preview.1` with `1.0.0-rc.1`)
  ([#617](https://github.com/Runic-Artifex/runic-sdk/pull/617)).

## New APIs

### macOS lifecycle

- **Quitting.** `DesktopHostOptions.ConfirmQuitAsync`
  (`Func<DesktopQuitRequest, CancellationToken, ValueTask<bool>>`) is asked
  before any window closes when the user quits. `DesktopQuitRequest.Source`
  (`DesktopQuitSource`, open: `Menu`, `Dock`, `System`, `Signal`) says what
  asked. With `HandleShutdownSignals`, Ctrl+C, SIGTERM and SIGHUP ask it too
  (`Signal`) on every platform. See
  [Behaviour changes](#behaviour-changes) for the quit path
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- **Reopen and the Dock menu.** `DesktopHost.ReopenRequested`
  (`DesktopReopenEventArgs.HasVisibleWindows`) occurs when the user clicks the
  Dock icon or opens the running application again.
  `DesktopHostOptions.MacOS` (`MacOSDesktopOptions`) takes `DockMenu`, items,
  separators and submenus whose commands run through `host.MenuCommands`
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- **Forwarding delegate.** `MacOSDesktopOptions.ForwardingApplicationDelegate`
  (an Objective-C object as `nint`) receives every application delegate message
  Runic's delegate does not handle, and is asked for continued activities that
  are not universal links, a Dock menu when `DockMenu` is empty, and reopen
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- **Main thread without a window.**
  `DesktopEventLoop.InvokeOnMainThreadAsync(Action, CancellationToken)` and
  `InvokeOnMainThreadAsync<T>(Func<T>, CancellationToken)` run AppKit calls on
  the main thread while `DesktopEventLoop.Run` runs, for example from an
  application behind a status icon. They run in order with Runic's own
  main-thread work, also while a menu tracks or a modal panel runs. Before `Run`
  they throw `InvalidOperationException`; on Windows and Linux
  `PlatformNotSupportedException`
  ([#636](https://github.com/Runic-Artifex/runic-sdk/pull/636); D046.2).
- New log events 3018 `DesktopQuitRequested` (Information), 3019
  `DesktopQuitConfirmationFailed` and 3020 `DesktopReopenHandlerFailed` (Error)
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629); D046.1).

See the Runic.Desktop README,
[Quitting, reopening and the Dock menu on macOS](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/packages/dotnet/Runic.Desktop/README.md#quitting-reopening-and-the-dock-menu-on-macos).

### Runic Desktop windows

- **Coordinates.** `DesktopWindowPlacement.Origin` (`DesktopCoordinateOrigin?`,
  open: `TopLeft`, `BottomLeft`) tells a placement saved before 0.12 from one
  with a top-left origin. Every built-in host writes `TopLeft`; `null` is a
  placement saved by 0.11. See [Breaking changes](#breaking-changes)
  ([#637](https://github.com/Runic-Artifex/runic-sdk/pull/637)).
- **Title bar on macOS.** `DesktopWindowOptions.MacOS` (`MacOSWindowOptions`)
  with `TitleBar` (`MacOSTitleBarStyle`, open: `Default`, `Hidden`,
  `Transparent`) lays a transparent title bar over the page and keeps the
  traffic lights; `TrafficLightPosition` (`System.Drawing.Point?`) moves them.
  Frameless and kiosk windows ignore both and `Validate` warns with
  `window-option-unsupported`; invalid values are `window-option-invalid`.
  Windows, Linux, installed browsers and custom window hosts ignore them
  ([#639](https://github.com/Runic-Artifex/runic-sdk/pull/639)).
- **Drag regions on macOS.** A window with a `Hidden` or `Transparent` title bar,
  and a `Frameless` window, moves by the CSS that Electron uses:
  `app-region: drag` and `no-drag` (also `-webkit-app-region` and
  `--app-region`), with the system's double-click action. The hit test runs in
  the application's process, without a Bridge call. A stylesheet of another
  origin or a CSSOM rule needs `--app-region`
  ([#639](https://github.com/Runic-Artifex/runic-sdk/pull/639)).
- **Light and dark.** `DesktopWindowOptions.ColorScheme` and
  `DesktopWindowHostOptions.ColorScheme` (`Runic.Platform.DesktopColorScheme`)
  force an embedded window light or dark; `NoPreference`, the default, follows
  the system. The page's `prefers-color-scheme` follows, and so does the window:
  `NSWindow.appearance` on macOS, the WebView2 profile's preferred color scheme
  (runtime 114 or later) and the dark title bar on Windows. The WPF
  `RunicWebView` applies it to its WebView2. GTK windows and installed browsers
  ignore it, and `DesktopHost.Validate` warns with `color-scheme-unsupported`
  ([#640](https://github.com/Runic-Artifex/runic-sdk/pull/640)).
- **Document conventions on macOS.**
  `DesktopWindow.SetRepresentedFileAsync(path)` shows the title bar's proxy icon
  and `SetDocumentEditedAsync(edited)` the unsaved-changes dot. `DesktopHost.NoteRecentDocumentAsync(path)` and
  `ClearRecentDocumentsAsync()` keep Open Recent and the Dock's recent documents.
  `MacOSDesktopOptions.OpenRecentMenu` adds Open Recent, built with public API,
  to the standard File menu; a chosen document's path arrives as an open
  request, and a sandboxed application reopens it from its own bookmark.
  `DesktopStandardMenuTitles.OpenRecent` and `ClearMenu` translate it. All of
  them do nothing on Windows and Linux. See the Runic.Desktop README,
  [Document apps on macOS](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/packages/dotnet/Runic.Desktop/README.md#document-apps-on-macos)
  ([#641](https://github.com/Runic-Artifex/runic-sdk/pull/641)).

### Platform and Runtime

- **Document leases.** `IFileDialogs.OpenDocumentAsync(OpenFileOptions)` and
  `SaveDocumentAsync(SaveFileOptions)` return an `IDocumentFileLease`
  (`ISaveFileLease` with `LocalPath` and `OpenReadAsync`) that reads the current
  file on each `OpenReadAsync` and saves back to it as often as the application
  saves (Ctrl+S, autosave). `PlatformCapabilityIds.FilesOpenDocument`
  (`platform.files.openDocument`) reports whether a window's dialogs return
  documents. Windows, Linux (GTK and the FileChooser portal, through document
  portal views) and macOS
  ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624),
  [#632](https://github.com/Runic-Artifex/runic-sdk/pull/632); fixes
  [#613](https://github.com/Runic-Artifex/runic-sdk/issues/613)).
- **Bookmarks from leases.** `ISaveFileLease.CreateBookmarkAsync` returns a
  bookmark of a dialog lease's file, and
  `IDesktopFileBookmarks.OpenDocumentAsync(bookmark)` reopens it as a document
  lease, for recent files. On macOS these are `NSURL` bookmarks, security-scoped
  in the App Sandbox, and the lease keeps the scope's access until it is disposed
  ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624),
  [#632](https://github.com/Runic-Artifex/runic-sdk/pull/632)).
- **Custom picker backends.** `IPickerBackend.SupportsDocumentAccess` (default
  `false`); `NativePickerBackend.OpenDocumentAsync`, `SaveDocumentAsync` and
  `SupportsDocumentAccess` (`true`). The new interface members are default
  members that answer `Unavailable(BackendUnavailable)`
  ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)).

See the Runic.Platform README,
[Document apps](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/packages/dotnet/Runic.Platform/README.md#document-apps).

### Command-line tools

- **App Sandbox.** `dotnet runic package macos --sandbox` signs the bundle with
  the entitlements Runic Desktop needs: the sandbox, loopback server and client,
  user-selected files read-write and app-scoped bookmarks. Sandboxing stays
  opt-in (D045.5). An `entitlements.plist` override without `{{Entitlements}}`
  that lacks a required key, repeats a key or turns the sandbox off fails with
  `RAPPPKG1006`
  ([#627](https://github.com/Runic-Artifex/runic-sdk/pull/627)).
- **Mac App Store.** `--provisioning-profile <file>` (with `--sign`) embeds a
  profile and adds its application and team identifiers to the entitlements;
  `--pkg` also writes an installer package with `productbuild`, which
  `--installer-sign` signs and `--notary-profile` notarizes. Nothing is
  uploaded (D045.6). New payload `format` value `pkg`; an unsigned `.pkg` warns
  `RAPPPKG2001`. The icon set includes the 1024 px icon
  ([#627](https://github.com/Runic-Artifex/runic-sdk/pull/627)).
- **Manifest fields.** `{{Entitlements}}` (`macos/entitlements.plist`),
  `{{ApplicationCategory}}` and `{{UsageDescriptions}}` (`macos/Info.plist`); the
  template manifests use all three
  ([#627](https://github.com/Runic-Artifex/runic-sdk/pull/627),
  [#633](https://github.com/Runic-Artifex/runic-sdk/pull/633)).
- **Development bundle.** On macOS, `dotnet run`, `dotnet watch` and
  `dotnet runic dev` start the application from an ad-hoc signed bundle in
  `obj/…/runic-macos/<AssemblyName>.app`, so notifications, login startup, open
  registration and the URL schemes and file types of `Info.plist` work while
  developing. The bundle declares file types with the `Alternate` rank and
  exports none; `AppContext.BaseDirectory` stays the build output. It is signed
  again only when the host, the output's entries or `Info.plist` change
  ([#634](https://github.com/Runic-Artifex/runic-sdk/pull/634)).

See [Packaging](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/docs/packaging.md#macos)
and the Runic.Platform.MacOS README,
[Development bundle](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/packages/dotnet/Runic.Platform.MacOS/README.md#development-bundle).

## Experimental APIs

None. 0.12.0 adds no experimental .NET API and no npm `./experimental` entry.

## Behaviour changes

The breaking ones are also listed under [Breaking changes](#breaking-changes).

- **macOS run loop.** `DesktopEventLoop.Run` (both overloads) creates `NSApp`
  and Runic's application delegate before the application's code runs, then runs
  `[NSApp run]` on the main thread; the 5 ms polling loop is gone, and
  `finishLaunching` is sent once. Runic's main-thread work goes through the main
  dispatch queue and runs in every run loop mode, also during menu tracking,
  live resize and modal panels, so it can run while a menu or panel is open.
  `Run(Func<Task>)` creates `NSApp` also for tools that use no AppKit service
  ([#628](https://github.com/Runic-Artifex/runic-sdk/pull/628)).
- **macOS open requests.** Under `DesktopEventLoop.Run`, Runic's delegate
  receives the open-documents and get-URL Apple events and universal links from
  the start and keeps up to 64 of them, in order, until the application creates
  its open requests. `MacOSPlatformProvider.CreateOpenRequests` then works on any
  thread and after the first window or status icon instead of throwing; the
  launch's own open event arrives after the launch's arguments
  ([#628](https://github.com/Runic-Artifex/runic-sdk/pull/628)).
- **macOS quit path.** Command and Q (any `terminate:`), Dock › Quit, a script's
  quit Apple event and logout, restart or shutdown take one path, also with no
  window open: `ConfirmQuitAsync`, then each window's close guard in turn, then
  `host.ShutdownRequested` is cancelled and the remaining windows close; the
  quit completes when the application's code returns. Before, Command and Q only
  asked each window to close, and the Dock, scripts and logout ended the process
  from AppKit, skipping close guards and `ShutdownRequested`. A refusal keeps the
  application running and cancels a logout. A quit with no surface and without
  `HandlesShutdownWithoutWindow` terminates the process after
  `ShutdownRequested` is cancelled, as a signal does
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- **macOS coordinates.** `MoveAsync`, `X` and `Y` of `DesktopWindowOptions`,
  `DesktopWindowState` and `DesktopWindowPlacement`, and `DesktopMonitor.Bounds`
  and `WorkArea` are points measured right and down from the primary screen's
  top-left corner, as on Windows and Linux. Placements saved by 0.11 restore at
  the same place once and are reported top-left from then on. `ResizeAsync`
  keeps the top-left corner instead of the bottom-left one
  ([#637](https://github.com/Runic-Artifex/runic-sdk/pull/637)).
- **Saves.** `ISaveFileLease.BeginWriteAsync` is repeatable for every save
  lease, including `SaveFileAsync`'s: a new write begins once the previous
  commit finished, whatever its outcome, or its transaction was disposed; while
  one is open it is `Failed(ResourceBusy)`. Before, every later call was
  `Failed(ResourceBusy)`. A commit compares the file with the content the
  application last saw: the selection, then each committed write and each
  `OpenReadAsync` of a document; after `CommitUnknown` both the previous and the
  staged content count as its own. GTK and the FileChooser portal treat opened
  files, not only saved ones, as document portal views, so they save back
  ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)).
- **Windows saves.** A target held open without delete sharing
  (`ERROR_UNABLE_TO_REMOVE_REPLACED`, 1175) is `NotCommitted(ResourceBusy)`
  instead of `CommitUnknown(IOError)`: the file was not replaced
  ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)).
- **Sandboxed macOS saves.** In the App Sandbox, file dialog selections now save:
  a lease stages each write in the volume's item replacement directory and
  replaces the file with `NSFileManager replaceItemAtURL:`, so
  `platform.files.save` is available and `BeginWriteAsync` no longer returns
  `Unavailable(AtomicReplaceUnavailable)` there
  ([#632](https://github.com/Runic-Artifex/runic-sdk/pull/632)).
- **macOS downloads.** With `DesktopWebContentPolicy.AllowDownloads`, the macOS
  window downloads through WKDownload, as the other embedded windows do; see
  [Fixes](#fixes). With downloads refused (the default), an attachment
  response of a type WebKit can show is cancelled instead of shown in the
  window, as on Linux
  ([#638](https://github.com/Runic-Artifex/runic-sdk/pull/638)).
- **macOS keyboard focus.** Every window is a Runic `NSWindow` subclass that can
  become the key and main window, so frameless, kiosk and non-resizable
  frameless windows take keyboard input
  ([#639](https://github.com/Runic-Artifex/runic-sdk/pull/639)).
- **Placements** written by every built-in host carry `Origin = TopLeft`
  (`"Origin":0` in JSON); 0.11 readers ignore it
  ([#637](https://github.com/Runic-Artifex/runic-sdk/pull/637)).
- **macOS packages.** System file types are declared with the `Alternate` rank
  instead of being exported as the application's own; files that are not code
  move to `Contents/Resources`; nested code is signed with the hardened runtime,
  deepest first, and verified with `codesign --verify --deep --strict`
  ([#633](https://github.com/Runic-Artifex/runic-sdk/pull/633)).
- **`dotnet run` on macOS** starts the development bundle; the process has a
  bundle identifier, and macOS keeps one set of permissions for it and the
  shipped application
  ([#634](https://github.com/Runic-Artifex/runic-sdk/pull/634)).
- **`osx-x64`.** `dotnet runic doctor --runtime osx-x64` fails `target-rid`
  (was a warning); `dotnet runic package` refuses `osx-x64` and several
  `--runtime` values for any target with `RAPPPKG1004`
  ([#625](https://github.com/Runic-Artifex/runic-sdk/pull/625)).
- **Capability snapshots** gain `platform.files.openDocument`. Code that
  compares the whole key set updates it
  ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)).
- **macOS volume watch.** When a disk is ejected and macOS gives its BSD name
  (such as `disk18s1`) to another disk before the next listing,
  `IDesktopVolumes.WatchAsync` reports `Removed` and then `Added` instead of one
  `Changed`. A mount, unmount, rename or unlock of the same disk is still a
  `Changed`, and `DesktopVolume.Id` is still the BSD name
  ([#646](https://github.com/Runic-Artifex/runic-sdk/pull/646)).

## Breaking changes

0.12.0 breaks only where better macOS support needed it (D045). No public API
is removed or changed; the tables give what code and packaging changes, and the
[migration guide](https://github.com/Runic-Artifex/runic-sdk/blob/v0.12.0/docs/migration-1.0.md#from-011-to-012)
has snippets.

### macOS lifecycle

- **One quit path.** Quitting asks `ConfirmQuitAsync` and the close guards and
  cancels `ShutdownRequested`, also for the Dock, scripts and logout, and with
  no window open
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- **Runic owns the application delegate.** An application that sets
  `NSApp.delegate` replaces Runic's delegate and loses open events, universal
  links, quitting, reopening and the Dock menu
  ([#628](https://github.com/Runic-Artifex/runic-sdk/pull/628),
  [#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).
- **Run-loop timing and open-request ordering** change as described in
  [Behaviour changes](#behaviour-changes)
  ([#628](https://github.com/Runic-Artifex/runic-sdk/pull/628)).

| Before | After |
| --- | --- |
| Command and Q asked each window to close; the application ended when its code returned | `ConfirmQuitAsync`, then each close guard, then `ShutdownRequested` is cancelled and the remaining windows close |
| Dock › Quit, a script's quit event and logout ended the process from AppKit (`exit`), skipping close guards and `ShutdownRequested` | The same path as Command and Q; a refusal keeps the application running and cancels a logout |
| A quit with no window open did nothing | `ShutdownRequested` is cancelled; with `HandlesShutdownWithoutWindow = false` and no surface, the process is then terminated |
| Save prompts in close guards only, never on logout | `DesktopHostOptions.ConfirmQuitAsync` (also asked on Ctrl+C, SIGTERM and SIGHUP when set) |
| `NSApp.delegate = myDelegate` | `DesktopHostOptions.MacOS = new() { ForwardingApplicationDelegate = myDelegate }` |
| `CreateOpenRequests` on the main thread before the first window or status icon, else `InvalidOperationException` | Under `DesktopEventLoop.Run`, on any thread at any time; earlier events are kept (up to 64) |
| Native callbacks and main-thread work ran between 5 ms polls, in the default run loop mode only | Inside `[NSApp run]` in every mode, also while a menu tracks or a modal panel runs |

### macOS windows

- **Top-left coordinates** in points from the primary screen's top-left corner;
  saved placements migrate once
  ([#637](https://github.com/Runic-Artifex/runic-sdk/pull/637)).

| Before | After |
| --- | --- |
| `MoveAsync(x, y)`, `DesktopWindowOptions.X`/`Y`: AppKit points, the frame's bottom-left corner measured up from the primary screen's bottom | The frame's top-left corner measured down from the primary screen's top. `MoveAsync(workArea.X, workArea.Y)` puts the title bar below the menu bar |
| `DesktopWindowState.X`/`Y` and `Placement`: bottom-left, no `Origin` | Top-left, `Placement.Origin = DesktopCoordinateOrigin.TopLeft` |
| `DesktopMonitor.Bounds`/`WorkArea`: `Y` is the bottom edge | `Y` is the top edge; a monitor above the primary has a negative `Y`; the primary's `WorkArea.Y` is the menu bar's height |
| Saved placements | Nothing to do: a placement without `Origin` opens where it did and is reported top-left from then on |
| Positions computed from `NSScreen` or `NSWindow` frames | Flip them, `top = primaryScreenHeight - (bottom + frameHeight)`, or set `Origin = DesktopCoordinateOrigin.BottomLeft` on the placement |
| `ResizeAsync` kept the bottom-left corner; the window grew upward | It keeps the top-left corner |

### macOS architectures and packaging

- **Intel Macs and universal bundles are removed** from the support statement,
  `eng/support.json`, packaging and templates
  ([#625](https://github.com/Runic-Artifex/runic-sdk/pull/625); D045.7).
- **Bundle layout, file types and signing** change in `dotnet runic package
  macos` ([#633](https://github.com/Runic-Artifex/runic-sdk/pull/633)).
- **The development bundle** changes what `dotnet run` starts
  ([#634](https://github.com/Runic-Artifex/runic-sdk/pull/634)).

| Before | After |
| --- | --- |
| `dotnet publish -r osx-x64`, `dotnet runic package macos --runtime osx-x64` | `osx-arm64`. `package` refuses `osx-x64` with `RAPPPKG1004` (exit 2); `dotnet runic doctor --runtime osx-x64` fails `target-rid`. A plain `dotnet publish -r osx-x64` is not checked (D046.4) |
| `dotnet runic package macos --runtime osx-arm64,osx-x64` built a universal bundle with `lipo` | Refused with `RAPPPKG1004`: every target takes one runtime identifier |
| `.txt`, `.md`, `.png` and other system types in `RunicApplicationFileTypes` exported as `<ApplicationId>.<ext>` with rank `Owner` | They name the system type with rank `Alternate`. `RunicMacFileTypeHandlerRank=Default` asks to be the default; `RunicMacFileTypeIdentifiers` names a type the built-in list does not know. Other extensions stay exported with `Owner` |
| Every published file in `Contents/MacOS` | Only Mach-O files; the others move to `Contents/Resources`, with a relative symbolic link left in `Contents/MacOS`. `AppContext.BaseDirectory` lookups work unchanged; code that enumerates `Contents/MacOS` sees links |
| `macos/Info.plist` override without `{{UsageDescriptions}}` | Add it when the project sets `RunicMacCameraUsageDescription` or `RunicMacMicrophoneUsageDescription`; otherwise `RAPPPKG1006` |
| Nested libraries and executables: signing the bundle failed or left them unsigned | Each is signed with the hardened runtime, deepest first; in the sandbox nested executables get `app-sandbox` and `com.apple.security.inherit` |
| `dotnet run`, `dotnet watch`, `dotnet runic dev` ran `bin/…/<AssemblyName>` | They run `obj/…/runic-macos/<AssemblyName>.app/Contents/MacOS/<AssemblyName>`. `<RunicMacDevelopmentBundle>false</RunicMacDevelopmentBundle>` restores the old behaviour. Launch profiles with `commandName: Executable` and IDEs that start the output directly are unaffected |

### Saves and downloads

| Before | After |
| --- | --- |
| Windows: replacing a file another program holds open without delete sharing was `CommitUnknown(IOError)` | `NotCommitted(ResourceBusy)`: the file was not replaced; try again later ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)) |
| A second `BeginWriteAsync` on a save lease was `Failed(ResourceBusy)` | A new write begins once the previous one committed or was disposed; `Failed(ResourceBusy)` only while one is open ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)) |
| A commit compared with the file as selected | With the content the application last saw: the last committed write or document read ([#624](https://github.com/Runic-Artifex/runic-sdk/pull/624)) |
| macOS App Sandbox: `platform.files.save` unavailable, `BeginWriteAsync` `Unavailable(AtomicReplaceUnavailable)` | Available; selections save through item replacement ([#632](https://github.com/Runic-Artifex/runic-sdk/pull/632)) |
| macOS, downloads refused: an attachment WebKit can show was shown in the window | Cancelled, as on Linux ([#638](https://github.com/Runic-Artifex/runic-sdk/pull/638)) |

## Security

This release fixes no finding of the security review. None of these needs
action unless noted.

- **Downloads on macOS** are saved only with `AllowDownloads`, never replace a
  file, have path separators, control characters and leading dots removed from
  their names, and carry the web-download quarantine mark with the source URL,
  so Gatekeeper checks them
  ([#638](https://github.com/Runic-Artifex/runic-sdk/pull/638)).
- **App Sandbox.** `--sandbox` grants only the entitlements Runic Desktop needs;
  an override cannot turn the sandbox off or drop a required key without
  `RAPPPKG1006`. **Action:** a sandboxed application that sets `AllowDownloads`
  adds `com.apple.security.files.downloads.read-write` to its override
  ([#627](https://github.com/Runic-Artifex/runic-sdk/pull/627),
  [#638](https://github.com/Runic-Artifex/runic-sdk/pull/638)).
- **Nested code** in a macOS bundle is signed with the hardened runtime, so a
  notarized bundle no longer carries unsigned libraries
  ([#633](https://github.com/Runic-Artifex/runic-sdk/pull/633)).
- **Quitting** no longer ends a macOS process from AppKit without the close
  guards, so a logout cannot skip a save prompt
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629)).

## Fixes

- macOS: `DesktopWebContentPolicy.AllowDownloads` now downloads in the WKWebView
  window (WKDownload). `<a download>` links, `blob:` and `data:` exports and
  `Content-Disposition: attachment` responses are saved to the user's Downloads
  folder under WebKit's suggested name and never replace a file
  (`name (1).ext`). A window that disallows downloads or has closed cancels the
  download before it gets a destination
  ([#638](https://github.com/Runic-Artifex/runic-sdk/pull/638)).
- macOS: a frameless, kiosk or non-resizable frameless window becomes the key
  window and takes keyboard input
  ([#639](https://github.com/Runic-Artifex/runic-sdk/pull/639)).
- macOS: `dotnet runic package macos` signs bundles with nested libraries and
  executables, which failed or left them unsigned
  ([#633](https://github.com/Runic-Artifex/runic-sdk/pull/633)).
- macOS: notifications, login startup and open registration work under
  `dotnet run` instead of reporting `Unavailable`
  ([#634](https://github.com/Runic-Artifex/runic-sdk/pull/634)).
- macOS: work queued from a page or the application runs while a context menu is
  open instead of waiting until it closes
  ([#628](https://github.com/Runic-Artifex/runic-sdk/pull/628)).
- A View whose page a navigator retired while the browser was unmounting it is
  released in the window's model turn, as the View lifetime hooks document,
  instead of on the navigator's thread
  ([#621](https://github.com/Runic-Artifex/runic-sdk/pull/621)).
- Desktop Bridge: a newer page connection no longer closes a silent older socket
  and is then turned away anyway; a socket that ended before its token check
  frees the connection at once; a silent socket is closed even when the
  application's logger throws while reporting it
  ([#622](https://github.com/Runic-Artifex/runic-sdk/pull/622)).
- Disposing a development asset source while a refresh is ending no longer
  throws `ObjectDisposedException`, for example on shutdown during
  `dotnet runic dev`
  ([#623](https://github.com/Runic-Artifex/runic-sdk/pull/623)).
- Windows: when a WebView2 page does not connect within `ConnectionTimeout`, the
  message also gives the WebView2 runtime version, whether and how the first
  document request started and ended, and, when no request reached the server,
  how long a loopback connect and a write to the profile folder took
  ([#635](https://github.com/Runic-Artifex/runic-sdk/pull/635)).
- Flatpak manifests that `dotnet runic package` writes grant
  `--talk-name=com.canonical.AppMenu.Registrar`, so the Linux global menu works
  inside a Flatpak; hand-written manifests still need it
  ([#612](https://github.com/Runic-Artifex/runic-sdk/pull/612)).
- A Nix package built with `buildRunicApplication` opens its documents and links
  from the desktop ([#618](https://github.com/Runic-Artifex/runic-sdk/pull/618);
  fixes [#616](https://github.com/Runic-Artifex/runic-sdk/issues/616)).
- Views (npm): a command or setter whose member name ends in `Snapshot` (such
  as `CreateSnapshot`, or the setter of `LastSnapshot`) no longer fails with a `protocol` diagnostic; only
  snapshot reads (the connect read and the recovery read) check the host's
  protocol ([#644](https://github.com/Runic-Artifex/runic-sdk/pull/644); fixes
  [#642](https://github.com/Runic-Artifex/runic-sdk/issues/642)).
- Angular: the deprecated `RunicViewOutlet` is the same class as `ViewOutlet` instead of a second
  component with the same selector, so applications that import
  `@runic-artifex/angular` no longer log NG0912 in development mode. The name,
  its generic type, its use in `imports` and its deprecation are unchanged
  ([#645](https://github.com/Runic-Artifex/runic-sdk/pull/645); fixes
  [#643](https://github.com/Runic-Artifex/runic-sdk/issues/643)).
- macOS: the volume watch no longer loses a removal when another disk takes
  over the ejected disk's BSD name; 0.11 reported the pair as one `Changed`. See
  [Behaviour changes](#behaviour-changes)
  ([#646](https://github.com/Runic-Artifex/runic-sdk/pull/646); found by
  [#626](https://github.com/Runic-Artifex/runic-sdk/pull/626)).
- Tests and CI only, no product change: flaky macOS checks (VoiceOver value
  steps, `hdiutil attach` EAGAIN, a coalesced volume removal, a port race), Linux
  checks (drag-out stage log, template install wait, CS-WebUI burst diagnostics)
  and the Secret portal fake
  ([#611](https://github.com/Runic-Artifex/runic-sdk/pull/611),
  [#626](https://github.com/Runic-Artifex/runic-sdk/pull/626),
  [#631](https://github.com/Runic-Artifex/runic-sdk/pull/631)).

## Known issues

- macOS 15 is documented but not tested: CI runs only the latest macOS on Apple
  silicon (D046.3).
- In the macOS App Sandbox a document cannot create sibling files such as lock
  files or a backup beside it, and recent files need
  `com.apple.security.files.bookmarks.app-scope` (added by `--sandbox`). Saving
  a file chosen in a panel outside the container is checked by hand, not in CI
  ([#632](https://github.com/Runic-Artifex/runic-sdk/pull/632)).
- The development bundle cannot carry restricted entitlements: test universal
  links and the data-protection keychain with
  `dotnet runic package macos --sign … --provisioning-profile …`
  ([#634](https://github.com/Runic-Artifex/runic-sdk/pull/634)).
- `ColorScheme` is a WebView2 profile setting: windows that share a
  `ProfilePath` show the scheme set last. `WpfBridgeView` and `RunicViewHost` do
  not expose it
  ([#640](https://github.com/Runic-Artifex/runic-sdk/pull/640)).
- Drag regions apply in the top-level page only, not in frames or while the page
  is pinch-magnified ([#639](https://github.com/Runic-Artifex/runic-sdk/pull/639)).
- `InvokeOnMainThreadAsync` has no GTK 4 equivalent on Linux
  ([#636](https://github.com/Runic-Artifex/runic-sdk/pull/636)).
- The Angular starter still overrides `vite` to 8.3.4 until a stable
  `@angular/build` accepts Vite 8.3.3 or later
  ([#620](https://github.com/Runic-Artifex/runic-sdk/pull/620)).
- The rare Windows WebView2 timeout "no request reached the server" is diagnosed,
  not fixed; the new trace says where the next one stalls
  ([#635](https://github.com/Runic-Artifex/runic-sdk/pull/635)).
- Left to the maintainer's Mac checklist, not CI: real logout and restart with
  unsaved changes, the Dock menu and Dock clicks, idle wake-ups, multiple
  monitors with 0.11 placements, title-bar drags and snapping, and camera and
  microphone prompts
  ([#629](https://github.com/Runic-Artifex/runic-sdk/pull/629),
  [#633](https://github.com/Runic-Artifex/runic-sdk/pull/633),
  [#637](https://github.com/Runic-Artifex/runic-sdk/pull/637),
  [#639](https://github.com/Runic-Artifex/runic-sdk/pull/639); D045.9). So are
  reopening from Open Recent in a sandboxed bundle through the application's own
  bookmark, and the proxy icon of a lease's `LocalPath`
  ([#641](https://github.com/Runic-Artifex/runic-sdk/pull/641)).
- Orca does not speak live regions on WebKitGTK
  ([#318](https://github.com/Runic-Artifex/runic-sdk/issues/318)).
