# Runic SDK 0.7.0-preview.4

## Views

- A project that references `Runic.Application` (or builds in-repo) but declares
  no Runic Window or View, for example one that only uses the navigator, now
  builds without `<RunicBridgeBuildEnabled>false</RunicBridgeBuildEnabled>`. When
  bridge generation is on only by default and the assembly has no Window or View,
  the build generates nothing and skips the frontend install, build and copy
  steps. `RUNICBRIDGE006` remains an error when the project sets
  `RunicBridgeBuildEnabled` to `true`, has a frontend `package.json`, declares
  `RunicBridgeFrontendInput` items, or sets `RunicBridgeCompositionType` or
  `RunicBridgeModelAssembly`. Projects that reference a host adapter
  (`Runic.Application.CsWebUi` or `Runic.Application.Desktop`) still always require
  generation.

## Navigation (experimental)

- `RunicNavigator.ModelContext` is public, and `RunicNavigator.UnretiredEntryCount`
  replaces the `UnretiredEntryCount()` extension method of
  `Runic.Application.Testing`. Replace `navigator.UnretiredEntryCount()` with
  `navigator.UnretiredEntryCount`. `RetainedContentModelCount()` is unchanged.
- `INavigationRegion` and `INavigationEntry` are content-type-independent views
  of `NavigationRegion<TContent>` and `NavigationEntry<TContent>`, for hosts that
  present a region without knowing its content type. `NavigationRegion<TContent>.Navigator`
  is public.
- `RunicNavigator.AttachPresentation(INavigationPresentation)` lets a presentation
  forget retiring owned content. The Views runtime uses it to bind a window
  session; applications don't call it. Each attached presentation is called
  separately, so a throwing one is logged (1064, step `Forget`) without skipping
  the others.
- The navigator logs under the category `Runic.Navigation`
  (`RunicNavigator.LogCategory`) instead of `Runic.Application.Views`. Event IDs
  are unchanged. `RunicNavigator.Services` is public.
- When a window session's own model context fails to shut down in the
  background, event 1033 is now logged with the session's logger (category
  `Runic.Application.Views`).
