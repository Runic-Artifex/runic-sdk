# Runic SDK 0.9.0

Install matching `0.9.0` packages from NuGet and npm;
`Runic.Application.Views.CsWebUi` is `0.9.0-preview.1`. Command Line versions
remain independent of this SDK.

Versions no longer carry a `-preview.N` suffix. Until 1.0, a new minor version
(`0.10.0`) may contain breaking changes and a patch version (`0.9.1`) only fixes
or adds; `Runic.Application.Views.CsWebUi` stays a prerelease while the CS-WebUI
release it depends on is one. See
[Versioning and support from 1.0](https://github.com/Runic-Artifex/runic-sdk/blob/v0.9.0/eng/release/README.md#versioning-and-support-from-10).

This release applies the 1.0 public API review to every package. It renames
types, members, build properties, npm entries and wire tokens, hides plumbing
that applications should not call, and moves APIs that may still change behind
experimental IDs and `./experimental` entries. It contains many breaking
changes; see [Upgrading](#upgrading). The
[release policy](https://github.com/Runic-Artifex/runic-sdk/blob/v0.9.0/eng/release/README.md#versioning-and-support-from-10)
now states the compatibility rules that apply from 1.0.

## Upgrading

Rebuild after updating: generated Bridge code, generated TypeScript clients and
generated mocks change with this release. Package validation, the `PublicAPI`
files and each pull request's description list the changes in full; the tables
below cover what application code usually touches.

### Build properties and build errors

- The 0.7.0-preview.6 build property and item names (`RunicBridge*`,
  `RunicViewsWindowProject`, `RunicBridgeFrontendInput`) no longer apply.
  `RUNICBRIDGE017` is now an error that names the new property; the
  [rename table](https://github.com/Runic-Artifex/runic-sdk/blob/v0.9.0/packages/dotnet/Runic.Application.Views/README.md#moved-and-renamed-since-070-preview6)
  lists them ([#452](https://github.com/Runic-Artifex/runic-sdk/pull/452)).
- Projects declare MSBuild's `ApplicationId` and `ApplicationTitle` instead of
  `RunicApplicationId` and `RunicApplicationName`. A project that sets only the
  old names fails with `RUNICBRIDGE017`. The macOS bundle identifier
  (`RunicMacBundleIdentifier`) defaults to `ApplicationId`, and the Polkit
  policy name to `ApplicationId`, then `AssemblyName`
  ([#452](https://github.com/Runic-Artifex/runic-sdk/pull/452)).
- `RunicApplicationFrontendOutputDirectory` (default `dist`) and
  `RunicApplicationFrontendWebRoot` (default `www`) now apply to `dotnet build`
  and `dotnet publish`, not only `dotnet runic dev`, and the Desktop, CS-WebUI
  and WPF hosts serve the configured web root. WPF `RunicViewHost.ContentRoot`
  now defaults to `null`, which uses that web root
  ([#452](https://github.com/Runic-Artifex/runic-sdk/pull/452)).
- The privileged-action properties and the Polkit metadata of
  `RunicPrivilegedAction` are renamed; the old names fail with the new
  `RUNICPA108` ([#452](https://github.com/Runic-Artifex/runic-sdk/pull/452)).
- Internal MSBuild names now start with `_`. The documented hook targets are
  listed in the Views and Platform READMEs
  ([#452](https://github.com/Runic-Artifex/runic-sdk/pull/452)).
- The generated composition is `<RootNamespace>.RunicViewsComposition`. Its
  namespace is the project's `RootNamespace` made a valid C# name, so a project
  such as `2048Game` builds without setting
  `RunicApplicationFrontendCompositionType`. Set that property to keep the old
  `<Project>.RunicBridgeComposition` name
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)).

### Platform and Runtime

- `PlatformFailureCode` is renumbered. `Unknown = 0` is only the default and is
  never reported, `PermissionDenied = 1` through `NotFound = 9` follow, and the
  new catch-all `Other = 10` reports native errors that no other code describes,
  which used to be `IoError`. `IoError` is renamed `IOError` and now means only
  failed input or output, such as a full disk. The set is open: keep a default
  arm ([#453](https://github.com/Runic-Artifex/runic-sdk/pull/453)).
- `PickerResult<T>.Failed`, `FileCommitResult.NotCommitted` and
  `FileCommitResult.CommitUnknown` carry the native error as `Diagnostic`, as
  `PlatformResult<T>.Failed` does
  ([#453](https://github.com/Runic-Artifex/runic-sdk/pull/453)).
- Runic's hosts now create the window services (file dialogs, clipboard, file
  launcher and presentation) for each window. `WindowsPlatformProvider`,
  `MacOSPlatformProvider` and `PortalApplication` keep only application-scoped
  factories, and `Runic.Platform.Linux` and `Runic.Platform.Linux.Gtk4` have no
  public API. Windows and macOS gain a public `CreateStatusIcon()`, and macOS a
  public `CreateLoginStartup()`, so a tray-only application no longer needs the
  WebView host ([#454](https://github.com/Runic-Artifex/runic-sdk/pull/454)).
- On Linux, `PortalApplication` is the provider: `PortalPlatformProvider` is
  removed, `CreateUnparentedInhibition()` is now the application-scoped
  `CreateInhibition()`, and `CreateVolumes()` is new. It throws
  `PlatformNotSupportedException` off Linux. In Flatpak or Snap the GTK-native
  dialogs report `Unavailable(BackendUnavailable)` instead of throwing
  ([#454](https://github.com/Runic-Artifex/runic-sdk/pull/454)).
- `WindowsPlatformProvider`, `MacOSPlatformProvider` and the Linux provider
  assemblies are annotated `[SupportedOSPlatform]`, so CA1416 flags unguarded
  cross-platform calls ([#454](https://github.com/Runic-Artifex/runic-sdk/pull/454)).
- `DesktopPlatform.OpenUrl(string)` (Runic.Desktop) is removed. It ran any
  string through the shell, so a path was executed. Use the new
  `IDesktopFileLauncher.LaunchUriAsync` (see [Opening links](#opening-links)).
  `IDesktopFileLauncher` gains that member, so a custom implementation or test
  fake adds it ([#436](https://github.com/Runic-Artifex/runic-sdk/pull/436)).
- Runic.Platform.Runtime now serves two audiences: applications
  (`ApplicationInstance`, `ApplicationInstanceOptions`, `LocalFileTransfers`)
  and the provider contract (`INativeWindowOwner`, the picker backend types and
  the two exceptions). The presentation types, the validators and
  `DesktopSettingsSource` are internal; use a Runic host
  (`AddRunicPlatformServices()`). `SecretStoreValidation.EncodeSecret`, which
  returned secret material in a mutable array, is no longer public
  ([#433](https://github.com/Runic-Artifex/runic-sdk/pull/433),
  [#453](https://github.com/Runic-Artifex/runic-sdk/pull/453)).
- `PolkitPrivilegedActions` and `WindowsPrivilegedActions` are static factory
  classes. `WindowsElevationOptions.Owner` (a window owner such as a Desktop
  window's `NativeOwner`) replaces the HWND `OwnerWindow`; a closed window leaves
  the prompt unowned ([#454](https://github.com/Runic-Artifex/runic-sdk/pull/454)).
- `PortalDiagnostic.Remediation` is optional, and the portal's diagnostic codes
  are documented as for logs only
  ([#453](https://github.com/Runic-Artifex/runic-sdk/pull/453)).

### Navigation

The navigation vocabulary no longer shares names with ReactiveUI activation,
and the region and entry are base classes that can grow in minor releases
([#455](https://github.com/Runic-Artifex/runic-sdk/pull/455)).

- `NavigationRegion` and `NavigationEntry` replace `INavigationRegion` and
  `INavigationEntry`. Only Runic.Navigation creates them.
  `NavigationRegion<TContent>` and `NavigationEntry<TContent>` derive from them
  and keep their typed members. The WPF hosts (`NavigationHost.Region`,
  `NavigationDialogHost.Region`, `NavigationSelector`) take a
  `NavigationRegion`.
- `UnhandledTurnException` is an
  `EventHandler<RunicModelTurnExceptionEventArgs>`. The sender is the context,
  and `Dropped` tells a turn dropped at close from one that threw.
- In both ReactiveUI flavors, `ReactiveSchedulers.For(context)` and
  `ReactiveSchedulers.InstallMainThreadScheduler()` replace the scheduler
  provider's constructor and static, and `ReactiveRoutedRegion<T>` is removed.
  Its log events 1040 and 1041 are retired.
- New: `LeaveConfirmation.InDialog(…, askOnRetain)` and
  `CreateBackCommand(region, canExecute: …)`, whose condition is combined with
  the region's.
- Every navigation enum and result union states whether it is open (may gain
  values in a minor release) or closed.

### Views (.NET)

- The types that generated code calls (`ViewModelBridge<T>`,
  `PropertyDescriptor<T>`, `CommandDescriptor<T>`, `BridgeWire`, `BridgeJson`,
  `BridgeOperationResult`, …) moved to `Runic.Application.Views.Generated`, and
  the ReactiveUI helpers to `Runic.Application.Views.ReactiveUI.Generated` and
  `…ReactiveUI.Reactive.Generated`. They are supported for generated code only:
  code an earlier release generated stays binary compatible within a major, but
  their source shape is not for hand-written code
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)).
- Application-facing types use the `Runic*` prefix
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)).
- Unconditional `[JsonIgnore]` and `[JsonExtensionData]` DTO members are no
  longer part of the Bridge contract. `[assembly: RunicIncludeJsonIgnored]`
  keeps them on the wire
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)).
- Failure detail is a per-window option: `RunicWindowOptions.IncludeFailureDetail`
  and `WindowContentSessionOptions.IncludeFailureDetail` replace the process-wide
  `BridgeDiagnostics.IncludeFailureDetail`. `null` follows `DOTNET_ENVIRONMENT`
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)). The Desktop and
  CS-WebUI host options set the application's default
  ([#459](https://github.com/Runic-Artifex/runic-sdk/pull/459)).
- `ReactiveRunicView<T>.OnAttached`, `OnDetached`, `OnWebMounted` and
  `OnWebUnmounted` are `protected virtual` hooks. Activation runs whether or not
  an override calls `base`
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)).
- `RunicInteractionInvocation.Enter` and the `BridgeInteractionRouter` route
  constants are internal. `Enter` let any code claim a browser client's
  identity and route interaction prompts to it. Commands that ask an
  interaction already run inside the Bridge's scope; application code keeps
  reading `RunicInteractionInvocation.Current`
  ([#433](https://github.com/Runic-Artifex/runic-sdk/pull/433)).
- `RunicWindowDiagnosticSeverity` runs `Information = 0`, `Warning = 1`,
  `Error = 2`. Code that uses the names is unchanged
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)).

### Views npm packages, wire and generated clients

- `@runic-artifex/views` has public tiers. Applications use the root entry and
  `./mock`. Generated code uses `./generated`, `./generated/wire` and the new
  `./generated/mock`. Framework bindings use the new `./bindings`. APIs that may
  still change are in `./experimental`. Every export condition has a `default`,
  and the package no longer ships source or declaration maps
  ([#458](https://github.com/Runic-Artifex/runic-sdk/pull/458)).
- Generated clients start an operation with `start<X>(input, { requestId })`
  and recover it with `recover<X>(requestId)`
  ([#458](https://github.com/Runic-Artifex/runic-sdk/pull/458)).
- `BridgeOperationUncertainError` takes `(message, { contract, requestId, route, cause })`.
  `contract` is the contract alone, and the View route it used to carry is the
  new `route`. `@runic-artifex/views-effect` `ViewOperationUncertain` carries
  `status` ([#458](https://github.com/Runic-Artifex/runic-sdk/pull/458)).
- `BridgeDiagnostic.code` is the open union `BridgeDiagnosticCode`. A stream
  page's `kind` excludes `timed-out`
  ([#458](https://github.com/Runic-Artifex/runic-sdk/pull/458)).
- The React, Vue, Svelte and Angular adapters no longer re-export core types;
  import them from `@runic-artifex/views`
  ([#458](https://github.com/Runic-Artifex/runic-sdk/pull/458)).

### Framework adapters, SvelteKit and the Vite plugin

- Experimental adapter APIs moved to each adapter's `./experimental` entry
  ([#461](https://github.com/Runic-Artifex/runic-sdk/pull/461)).
- `@runic-artifex/svelte`'s `./views` entry is removed; `useView`,
  `useCommand`, `useOperation`, `ViewOutlet` and the rest are in the root entry
  ([#461](https://github.com/Runic-Artifex/runic-sdk/pull/461)).
- `@runic-artifex/vue` `useCommand` and `useOperation` return shallow refs, so
  the handle can be destructured. Read `pending.value` in script; templates
  unwrap them ([#461](https://github.com/Runic-Artifex/runic-sdk/pull/461)).
- `@runic-artifex/sveltekit`: `runicAdapter` options are typed per mode, so a
  field the mode ignores, such as `fallback` without `mode: "spa"`, no longer
  type-checks. The page options are exported only from
  `@runic-artifex/sveltekit/page-options`
  ([#461](https://github.com/Runic-Artifex/runic-sdk/pull/461)).
- `@runic-artifex/vite-plugin-runic`: `./client` is a side-effect import that
  forwards Views diagnostics and connection state by itself. `./virtual`, the
  state and diagnostic reporters and the HMR resource helpers are removed. The
  DevTools show the Views connection state; the operations and runtime-state
  panels are removed. A diagnostic `source` is any lowercase kebab-case string
  up to 32 characters
  ([#461](https://github.com/Runic-Artifex/runic-sdk/pull/461)).
- Peer ranges are bounded to the tested majors: `@runic-artifex/angular`
  supports Angular 22 only, `@runic-artifex/vue` needs Vue 3.5.30 or later,
  `@runic-artifex/svelte` needs Svelte 5.57.1 or later, like

### Runic Desktop and GTK 4

- The window-host provider interfaces and the Linux toolkit claim are
  experimental under `RUNICDESK100`, and the low-level presentation transport
  of `DesktopSurface` under `RUNICDESK101`. Applications that open windows
  through `DesktopHost`, select GTK 4 with `WithGtk4()` or use Runic Windows and
  Views are unaffected ([#457](https://github.com/Runic-Artifex/runic-sdk/pull/457)).
- `DesktopSurface.ExecuteJavaScriptAsync(script, cancellationToken)` replaces
  the overload with `timeout` and `responseBufferSize`. The token bounds the
  wait, and results up to 16 MiB of UTF-8 are returned whole. A larger result
  throws `DesktopException` with `LimitExceeded` (`script-result-too-large`)
  instead of being truncated
  ([#434](https://github.com/Runic-Artifex/runic-sdk/pull/434),
  [#457](https://github.com/Runic-Artifex/runic-sdk/pull/457)).
- Window sizes and `DesktopWindow.ProcessId` are `int`. A size that is not
  positive is a `window-option-invalid` validation error, and `ResizeAsync`
  throws `ArgumentOutOfRangeException` for it. Saved `DesktopWindowPlacement`
  JSON stays readable ([#457](https://github.com/Runic-Artifex/runic-sdk/pull/457)).
- Availability records report only `Diagnostics`
  ([#457](https://github.com/Runic-Artifex/runic-sdk/pull/457)).
- `StructuredPayload` and `Gtk4Application` are internal
  ([#457](https://github.com/Runic-Artifex/runic-sdk/pull/457)).
- `default(DesktopShortcut).Key` is an empty string instead of `null`
  ([#434](https://github.com/Runic-Artifex/runic-sdk/pull/434)).

### Windows administration

`Runic.Platform.Administration.Windows` applies the 1.0 API review
([#443](https://github.com/Runic-Artifex/runic-sdk/pull/443)):

- `AdministrationErrorCategory` starts with `Unknown = 0`, which is never
  reported, and adds `NotFound`; all numeric values changed. A missing service,
  share, file, directory object or WMI instance is now `NotFound` instead of
  `Unavailable`, which now means only that the machine, endpoint or a required
  component is unavailable.
- Service and share administration, domain membership and domain-controller
  discovery are asynchronous and cancellable and no longer block the caller's
  thread. A cancelled token keeps a call from starting; a started call returns
  its real result.
- Process IDs are `int`, DNS TTLs are `TimeSpan` values, A and AAAA record data
  use `IPAddress`, and Group Policy times are `DateTimeOffset`.
- The five client interfaces are removed, and `TaskTrigger` can no longer be
  subclassed.
- `WindowsDirectoryClient` reads type values by the attribute's schema syntax.
  String, number, boolean, time and DN attributes return `DirectoryValue.Text`;
  octet-string, SID and security-descriptor attributes, and attributes the
  schema does not define, return `DirectoryValue.Binary`. RootDSE values are
  `Text`. Previously every value was `Binary`, holding UTF-8 bytes for text. A
  text value that is not valid UTF-8 fails the read with `InvalidData`
  ([#450](https://github.com/Runic-Artifex/runic-sdk/pull/450)).

| Before | After |
| --- | --- |
| `AccessDenied = 0, Unavailable = 1, Conflict = 2, InvalidData = 3, NativeFailure = 4` | `Unknown = 0, AccessDenied = 1, NotFound = 2, Unavailable = 3, Conflict = 4, InvalidData = 5, NativeFailure = 6`; store names, not numbers |
| `e.Category == Unavailable` for a missing service, share or object | `e.Category == AdministrationErrorCategory.NotFound` |
| `WindowsServiceClient.Create/Update/Delete/Start/Stop/Pause/Continue/Enumerate/Find/FindStatus(…)` | `…Async(…, CancellationToken = default)`; `CreateAsync`/`UpdateAsync` keep `string? password = null` before the token |
| `WindowsShareClient.Enumerate/Find/Create/Update/Delete(…)` | `…Async(…, CancellationToken = default)` |
| `WindowsDomainClient.GetMembership()`, `DiscoverController(…)` | `GetMembershipAsync(cancellationToken)`, `DiscoverControllerAsync(…, cancellationToken)` |
| `WindowsSystemInformationClient.GetDomainMembership()` | `await new WindowsDomainClient().GetMembershipAsync()` |
| `new WindowsShareClient(server: …)`, `new WindowsDomainClient(computerName: …)` | `machineName: …` |
| `uint` process IDs (`ProcessSnapshot`, `WindowsProcessClient.Find`/`GetChildren`, `ServiceStatus.ProcessId`) | `int`; pass `Environment.ProcessId` or `Process.Id` directly |
| `new DnsRecordSpecification(key, ttlSeconds)` | `new DnsRecordSpecification(key) { TimeToLive = TimeSpan.FromSeconds(ttlSeconds) }` (default one hour) |

### D-Bus

- `DBusObjectPath` and `DBusSignature` compare by `Value`, so
  `default(DBusObjectPath)` equals `DBusObjectPath.Root` and
  `default(DBusSignature)` the empty signature. `DBusSignal`,
  `DBusPropertyChanges` and `DBusMethodCall` compare by content instead of by
  array reference ([#431](https://github.com/Runic-Artifex/runic-sdk/pull/431)).
- `DBusSignal` and `DBusPropertyChanges` are sealed classes that only the
  connection creates; their public constructors, deconstruction and `with`
  copies are gone ([#442](https://github.com/Runic-Artifex/runic-sdk/pull/442)).

  member would hide, overload or duplicate a `DBusProxy` or `DBusObject`
  member, an `object` member, the class itself or another generated member.
  Such members used to compile with the inherited member silently hidden.
  Duplicates between interfaces of one service file, previously
  `RUNICDBUS011`, are now `RUNICDBUS012`. Generated files no longer suppress
  CS0108/CS0114 ([#442](https://github.com/Runic-Artifex/runic-sdk/pull/442)).

| Before | After |

  `RUNICASSETS001` (the Linux development-directory asset source)

  ([#466](https://github.com/Runic-Artifex/runic-sdk/pull/466)).
- Experimental IDs number from 100 when their prefix already names
  diagnostics. `RUNICDBUS100` is reserved; no D-Bus API is experimental
  ([#442](https://github.com/Runic-Artifex/runic-sdk/pull/442)).
- npm packages put experimental APIs in an `./experimental` entry:
  `@runic-artifex/views`, `views-effect`, `react`, `vue`, `svelte` and
  `angular` ([#458](https://github.com/Runic-Artifex/runic-sdk/pull/458),
  [#461](https://github.com/Runic-Artifex/runic-sdk/pull/461)).

[Experimental APIs](https://github.com/Runic-Artifex/runic-sdk/blob/v0.9.0/docs/experimental.md)
lists what each ID covers, how to suppress it, and the graduated and retired
IDs.

## Opening links

- `IDesktopFileLauncher.LaunchUriAsync(Uri uri, CancellationToken cancellationToken = default)`
  opens an absolute `http`, `https` or `mailto` URI in the user's default
  browser or mail client and returns a `PlatformResult` (capability
  `platform.uris.launch`). Linux asks the OpenURI desktop portal, also inside
  Flatpak and Snap; Windows uses the shell's URL association and macOS
  `NSWorkspace`. A relative URI, a path or any other scheme throws
  `ArgumentException` before anything native runs, so a link never starts a
  program. Cancelling the portal's application chooser is
  `Failed(UserDismissed)`. A ViewModel gets the launcher from its window's
  services, as for `LaunchAsync`
  ([#436](https://github.com/Runic-Artifex/runic-sdk/pull/436)).

## Views

- Snapshot replies carry the `Runic.Application.Views` version, and the browser
  runtime reports a `version` diagnostic once per Bridge when
  `@runic-artifex/views` is a different release
  ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456),
  [#458](https://github.com/Runic-Artifex/runic-sdk/pull/458)).
- `@runic-artifex/views/mock`: `MockOperationKind` includes `expired` and
  `unknown`. `expire()` on a finished mock operation makes it report `expired`,
  as after .NET's retention runs out, and `forget()` makes the window forget its
  request id, as after a restart
  ([#467](https://github.com/Runic-Artifex/runic-sdk/pull/467)).
- `useView(source, { release })` in React, Vue and Svelte customizes how a
  connected client is released; the default is `client.dispose()`. React
  `useCommand` and `useOperation` dispose their controller on unmount, also
  under StrictMode. Angular `ViewOutlet` shows its projected content until
  content is presented
  ([#461](https://github.com/Runic-Artifex/runic-sdk/pull/461)).
- The generated composition carries `[GeneratedCode]` and
  `[ExcludeFromCodeCoverage]` ([#456](https://github.com/Runic-Artifex/runic-sdk/pull/456)).

## WPF hosting

- New `WpfPlatformServices.ForWindow(Window)` returns the Windows file dialogs,
  clipboard and launcher owned by a WPF window, for ViewModels shared with Runic
  Desktop that take `IWindowPlatformServices`. Every service reports
  `OwnerUnavailable` until the window has a handle and `OwnerClosed` after it
  closes. Call it on the window's thread
  ([#466](https://github.com/Runic-Artifex/runic-sdk/pull/466)).
- `RunicViewHost` passes its `AutomationProperties.Name` and `HelpText` to the
  web View's pane, so screen readers announce a named pane
  ([#466](https://github.com/Runic-Artifex/runic-sdk/pull/466)).
- Tab and Shift+Tab leave an embedded View at the document's last or first tab
  stop and continue to the surrounding WPF controls, instead of cycling inside
  the WebView ([#432](https://github.com/Runic-Artifex/runic-sdk/pull/432)).

## Validation

- In serve-only mode (`RUNIC_APPLICATION_SERVE_ONLY=1`), Runic Desktop's
  `ValidateWindow` no longer needs an installed browser: with a browser
  fallback, as in the default options, it skips the embedded WebView's findings
  such as `linux-embedded-backend-not-selected`
  ([#434](https://github.com/Runic-Artifex/runic-sdk/pull/434)).
- CS-WebUI `ValidateWindow` reports a `CSWEBUI_BROWSER_PATH` that names no file
  (`browser-not-found`). Whether WebUI finds another browser or the WebView
  shows only when a window opens
  ([#434](https://github.com/Runic-Artifex/runic-sdk/pull/434)).

## Fixes

- `WindowsDnsClient.UpdateAsync` no longer deletes the record when an update
  changes only the TTL; updates send only changed record data and read the
  result back. SRV records use the provider's `SRVDomainName` target, so their
  creation no longer fails and reads no longer return the zone as the target.
  `UpdateAsync` and `DeleteAsync` report `NativeFailure` when the DNS server
  reports success without applying the change
  ([#448](https://github.com/Runic-Artifex/runic-sdk/pull/448)).
- `ApplicationInstance` on Windows: the running instance always sees a
  forwarded launch with a reply leave (`Cancelled` and `Disconnected`), even
  when the launching process leaves right after the reply starts. Before, about
  one such launch in a few hundred went unnoticed
  ([#426](https://github.com/Runic-Artifex/runic-sdk/pull/426)).
- The Bridge generator no longer lists every installed .NET shared framework
  when a type's base class cannot be loaded. On a cold Windows machine that
  listing could take more than 30 seconds
  ([#423](https://github.com/Runic-Artifex/runic-sdk/pull/423)).
- Disposing a D-Bus signal subscription closes the file descriptors of signals
  it received but nobody read. Received unix-fd handles are `SafeFileHandle`s
  ([#431](https://github.com/Runic-Artifex/runic-sdk/pull/431)).
- `dotnet new runic-app --host cswebui` references
  `Runic.Application.Views.CsWebUi` with the version that package ships with,
  which a stable release sets to a prerelease version
  ([#435](https://github.com/Runic-Artifex/runic-sdk/pull/435)).
- The generated Bridge code, the bootstrap build and the frontend stamps follow
  `IntermediateOutputPath` and `BaseIntermediateOutputPath`, so
  `UseArtifactsOutput` and custom intermediate paths no longer leave them in
  `obj/`. With a runtime identifier the generated code is in that runtime
  identifier's intermediate directory; `dotnet publish --no-build` needs a build
  with the same `RuntimeIdentifier`
  ([#435](https://github.com/Runic-Artifex/runic-sdk/pull/435)).
- `<RunicAssetsDistExclude></RunicAssetsDistExclude>` now packs every file of
  `RunicAssetsDist`; the default `runic-assets.zip` comes from the new
  `buildTransitive/Runic.Assets.props`
  ([#435](https://github.com/Runic-Artifex/runic-sdk/pull/435)).
- `Runic.Assets.Desktop` sends `text/*` assets with `; charset=utf-8`, as
  `Runic.Assets.AspNetCore` does, so one archive gets the same `Content-Type` on
  both hosts ([#442](https://github.com/Runic-Artifex/runic-sdk/pull/442)).
- `RunicDesktopMinimalHost` values `yes`, `on`, `no` and `off` fail with
  `RUNICDESK001` instead of building with the switch ignored
  ([#457](https://github.com/Runic-Artifex/runic-sdk/pull/457)).
- `@runic-artifex/svelte`: `useView` and `useCollectionViewport` release their
  controller when their owner is destroyed before its first effect flush, and
  `useCommand` releases its controller with its owner. A run in flight still
  settles ([#437](https://github.com/Runic-Artifex/runic-sdk/pull/437)).
- `@runic-artifex/vue`: development builds warn when `useView`, `useCommand`,
  `useOperation` or `useCollectionViewport` runs outside an effect scope, where
  nothing releases it, and when a collection viewport's `attach` receives a
  component instance instead of a native element
  ([#437](https://github.com/Runic-Artifex/runic-sdk/pull/437)).
- `dotnet runic dev`: stopping the application on Linux reads `/proc` instead of
  running `ps`, so it waits for the application in containers and sandboxes
  without procps; when it cannot list the processes it says so and asks only the
  started process to stop
  ([#439](https://github.com/Runic-Artifex/runic-sdk/pull/439)).
- `Runic.Create` recognizes an already installed template version with a
  localized .NET SDK instead of failing with `RCREATE004`
  ([#439](https://github.com/Runic-Artifex/runic-sdk/pull/439)).

## Documentation and policy

- The [release policy](https://github.com/Runic-Artifex/runic-sdk/blob/v0.9.0/eng/release/README.md#versioning-and-support-from-10)
  states which enums and string unions may gain values (open) and which may not
  (closed), that positional records grow only through `init` properties, which
  third-party versions Runic packages accept, and every diagnostic ID family.
  Templates, log event IDs and telemetry names are part of the compatibility
  promise ([#451](https://github.com/Runic-Artifex/runic-sdk/pull/451)).
- The [diagnostics catalog](https://github.com/Runic-Artifex/runic-sdk/blob/v0.9.0/docs/diagnostics.md)
  lists every `RUNICBRIDGE` code with its severity and reporter. The
  `RunicNavigator.WhenIdleAsync` and `RunicWindowTestHost` docs match the code
  ([#440](https://github.com/Runic-Artifex/runic-sdk/pull/440)).
- The `@runic-artifex/sveltekit` README shows how to apply
  `runicPrerenderedPageOptions` and `runicSpaPageOptions`; page options can't be
  used with the hash router of a Desktop SPA. The adapter READMEs cover
  interactions, `instanceof BridgeError` and server rendering
  ([#451](https://github.com/Runic-Artifex/runic-sdk/pull/451)).
- The Runic.Assets, Runic.Application.Views and Views.Desktop READMEs explain
  when to use the Views `www/` folder and when Runic.Assets' embedded archive
  ([#442](https://github.com/Runic-Artifex/runic-sdk/pull/442)).
- The [DynamicData example](https://github.com/Runic-Artifex/runic-sdk/tree/v0.9.0/examples/dynamicdata)
  uses the fork's nuget.org packages, `RunicArtifex.DynamicData` and
  `RunicArtifex.DynamicData.Reactive`
  ([#460](https://github.com/Runic-Artifex/runic-sdk/pull/460)).
