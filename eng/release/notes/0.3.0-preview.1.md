# Runic SDK 0.3.0-preview.1

Prepared preview; not yet published. Update Runic NuGet and npm packages together
when this version becomes available. This release adds CLI improvements, Linux
GTK4 and desktop portals, Windows native fixes, and an experimental standalone
Windows administration package.

## Command-line development

Use ordinary typed methods with generated commands, help, validation, completion,
shared options and environment fallbacks. Hosted Runic applications receive the
same behavior through their CLI adapter. Add `Runic.CommandLine.Spectre` for styled
help, progress and prompts; the core remains independent of Spectre.Console.
The Node/Bun `runic-bridge` CLI uses Effect CLI with matching conventions.

Non-nullable scalar options without a C# default are required. Use a nullable
parameter or explicit default for optional inputs. See [CLI migration details](cli-follow-up.md).

## Desktop and platform services

Linux applications explicitly select GTK3/WebKitGTK 4.1 or GTK4/WebKitGTK 6.
GTK4 uses the optional `Runic.Desktop.Gtk4` and `Runic.Platform.Linux.Gtk4` packages.
Enter GTK4 through `Gtk4Application.Run` on the OS main thread before top-level
`await`. GTK3 remains supported; implicit WebKitGTK 4.0 fallback is removed.

Linux file dialogs use XDG portals, allowing the desktop to select its preferred
chooser. GTK-native dialogs remain explicitly available to unsandboxed consumers.
A sandbox document grant does not grant sibling-directory access: an atomic save
may return `AtomicReplaceUnavailable` without changing the destination. See
[GTK4 and portal migration details](gtk4-portals-follow-up.md).

Desktop services include notifications and activation, file/application handoff,
appearance settings and inhibition. Linux notification applications need a valid
registered desktop identity for reliable notification history and activation.

Windows NativeAOT uses the statically linked WebView2 loader by default, so the
application executable does not need an adjacent WebView2Loader.dll. The Edge
WebView2 Runtime must still be installed. Windows WebView2 windows now use
per-monitor V2 DPI awareness on their owned UI thread and resize when display
scale changes. The platform file picker uses generated unmanaged CsWin32 bindings.

## Windows administration (experimental)

`Runic.Platform.Administration.Windows` offers standalone clients for shortcuts,
services, processes, tasks, firewall, directory services, inventory, networks,
shares, DNS and Group Policy. It does not require a Runic application/desktop host
and does not elevate automatically. Generated native bindings are private build
dependencies; ordinary Windows platform consumers do not acquire the administration
package or its LDAP dependency.

Windows x64 read-only/native inspection and temporary shortcut roundtrips pass in
JIT and NativeAOT. Administrative mutation, AD, DNS and GPMC scenarios remain
implemented but not natively accepted. Use disposable fixtures for those operations;
see the package's verification guide. This preview does not claim production
readiness for those scenarios or ARM64/x86 support.

## Known limitations

- Windows IME is best effort. Its strict Pinyin test is disabled; revisit with
  newer Windows/WebView2 versions in December 2026 or later.
- Windows scaling tests cover 100%, 125%, 150%, 175% and a live 125% to 150% change.
  Separate monitors with different DPI and 200% remain unverified on this VM.
- Narrator checks cover labels/roles and non-silent audio, not independent speech
  recognition or pronunciation quality.
- macOS native platform changes remain untested on a real Mac.
- Printing is deferred until a concrete consumer need.

Linux automation now uses reproducible managed NixOS containers for GNOME and
Plasma, including Wayland/X11, accessibility, input, portals and sandbox checks.
These checks cover the tested environments, not every Linux distribution or
hardware configuration.
