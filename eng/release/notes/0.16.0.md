# Runic SDK 0.16.0

Install matching `0.16.0` packages from NuGet and npm;
`Runic.Application.Views.CsWebUi` is `0.16.0-preview.1`.
Command Line versions remain independent of this SDK.

0.16.0 lets the ViewModel reach its View, its window and the platform, and lets
tests see each of them. A ViewModel can ask its page to focus a field or scroll
to a row (sdk#796), ask the page a question and await the answer, control its
own window, open and find other windows, switch light and dark, follow the
desktop's sleep, lock and power state, and see who is connected to a CS-WebUI
window. Pages gain editable rows and nested fields, forms, translated text,
large database-backed lists, region collections such as document tabs, files
in both directions, and Back and the URL. The test host gets platform fakes,
real windows, every serve-only window's URL and the page's own errors.

Everything is additive. The new wire members are Views protocol 4 features
negotiated in `hello` (see [Views protocol 4 features](#views-protocol-4-features)),
so a 0.15 page and a 0.16 host, or the reverse, connect and behave as in 0.15.
Some existing behaviour changes; each section lists them under
**Behaviour changes**, and the
[migration guide](https://github.com/Runic-Artifex/runic-sdk/blob/v0.16.0/docs/migration-1.0.md#from-015-to-016)
collects them.

## Upgrading

Update every Runic NuGet and npm package to 0.16.0 together and rebuild, so
that the generated clients are regenerated. CS-WebUI applications need the 0.16
page and host for the [security fix](#security-connection-keys-on-cs-webui);
replace any copy of `runic-cswebui.js` that the application keeps outside
`www/`. An application that supplies its own native server library
(`RunicDesktopNativeServerLibraryDirectory`, Nix `runicServer`) builds it from
this release: its C ABI is now version 3. See the
[migration guide](https://github.com/Runic-Artifex/runic-sdk/blob/v0.16.0/docs/migration-1.0.md#from-015-to-016).

## Security: connection keys on CS-WebUI

**With a 0.16 page and host, a CS-WebUI page never acts as, or receives the
pushes of, another page that just left** (#812).

On CS-WebUI, a page that reloaded, or another browser that connected right
after a page left, could take over the connection identity of the page that had
just closed. WebUI reuses its connection slots, and without its authentication
cookie every client id is 0. WebUI also reports a close only after it has given
the slot to the next page. So a command still running for the closed page, for
example one awaiting a save, could send that page's ReactiveUI interaction
questions and operation pushes to the new page. The new page's first `receive`
could even pick up pushes that were waiting for the old one. This affects every
release since interactions shipped (0.13), in particular windows that enable
WebUI's `MultiClient`.

In 0.16:

- Each connection of a window gets an identity that no later connection
  reuses. On a transport that reuses its keys (CS-WebUI, the in-memory test
  transport) the window's key is the transport's key with a counter, such as
  `0:1#2` or `connection-1#1`; `RunicInteractionInvocation.ConnectionKey` and
  `IRunicConnections` report it.
- With the new protocol feature `request-session/1`, every request names the
  random session of its page, so another page's requests, including its
  `receive`, never act for a connection that is not its own. A request of
  another session is answered `no-hello` and logged once per connection as
  event 1019.
- **What you need for full protection:** a 0.16 page and a 0.16 host. Update
  the Runic NuGet and npm packages together, and replace any copy of
  `runic-cswebui.js` that the application keeps outside `www/`.
- **Older pages are only partly protected.** A 0.15 page on a 0.16 host is
  protected against resumed commands, but not against a new page's early
  `receive`.
- **Hand-written clients** of the Views protocol are protected only if they
  list `request-session/1` in their `hello` and send their session with each
  request. The host scripts add the session to raw `__runicBridge.request`
  calls themselves.

Runic Desktop and WPF were not affected: their connection ids never repeat.

## View requests and view questions (V, sdk#796)

### Added

- **View requests: the ViewModel reaches its web View.** A ViewModel can now ask
  its page for a presentation action without waiting for an answer: focus a
  field, scroll a row into view, scroll to the top, show a toast. Declare a
  get-only `ViewRequest<T>` and call `Raise(input)`. The page handles it with
  the generated `client.requests.<name>.handle((input, { signal }) => …)`. This
  works in both MVVM flavors and every frontend adapter. The page runs the
  handler once it has rendered everything the ViewModel changed before the
  request, so a newly added row is there to focus. A request is never replayed
  after a reconnect and never reaches another window or connection (#806, #811).
- Each request declares its `ViewRequestDelivery`:
  - `Drop` (the default) goes to the presentation that invoked the command, or
    the window's one presentation that handles it, and is otherwise dropped
    (Debug event 1120 `ViewRequestDropped`).
  - `NextMounted` keeps the latest request for the next presentation that mounts
    a handler (event 1121 `ViewRequestKept`).
  - `Broadcast` reaches every presentation of the window that handles it, on
    every connection of the window.
- **`ViewQuestion<TInput, TOutput>`** lets any ViewModel, including a
  CommunityToolkit one, ask the page and await its answer with
  `AskAsync(input, cancellationToken)`. It falls back to an optional .NET answer
  when no page can reply, and otherwise throws
  `RunicInteractionUnhandledException`.
- **Questions from menus and from outside a command.** A menu item clicked in
  the page's in-page menu bar now asks that page. Native menu-bar commands, and
  code that enters `RunicInteractionInvocation.EnterWindow(viewModel)` or
  `TryEnterWindow` (such as a timer or a notification's activation), ask the
  window's page when exactly one presentation handles the question. A command's
  question also reaches its own page on another route of the same window.
- Generator diagnostic `RUNICBRIDGE035`: a `ViewRequest` or `ViewQuestion`
  member that is not a get-only property.
- **Testing.** `RunicViewDriver.MountPresentation()` and
  `MountPresentationAsync()` act as the page: `Handle(vm => vm.Question, answer)`
  answers questions and interactions, and `TakeViewRequests()` returns the
  requests it received. The TypeScript mock gains `requests.<name>.raise(input)`.

Pages and hosts of 0.15 keep working with 0.16 ones: the producer only sends
requests to pages that list `view-requests/1`.

### Behaviour changes

- **A page now answers questions that used to fall back to .NET.** A .NET
  handler or fallback that used to answer a question asked by a command on
  another route of the window, or by a menu-bar command, is now skipped while a
  page has a handler mounted for it. This also applies to 0.15 pages on a 0.16
  host, because interaction handlers are not behind the new feature. Keep such a
  fallback only for when no page is mounted.

## Who is connected to a window (D4)

### Added

- **`IRunicConnections`**, registered per window by `AddRunicWindowService()`,
  shows a ViewModel the window's page connections and the connection that
  invoked the running command (#811).
  - `Current` lists the connections, each a `RunicConnection(ConnectionKey,
    ClientKey)`.
  - `Connected` and `Disconnected` are raised in a model turn; a throwing
    handler is logged as event 1230 `ConnectionHandlerFailed`.
  - `Caller` is the connection that sent the running command, operation or
    in-page menu click.
  - `WhenChanged()` gives ReactiveUI an observable of the list.
- In a CS-WebUI window shared with WebUI's `MultiClient`, this lets you show who
  else is viewing, or attribute an action to the page that sent it. The keys
  come from the transport, never from the page, are never reused within a
  window, and cannot be set by application code. They tell pages apart; they
  are not user identity, so `MultiClient` still needs your own authentication.
- `RunicConnectionState<T>` keeps a value per connection, such as a draft, and
  drops it when the page disconnects; a `Dispose` that throws is logged as event
  1231 `ConnectionStateDisposeFailed`.
- Runic Desktop reports its window's one page connection, which is new after
  each reload. A WPF `RunicViewHost` has no window scope and reports none.
- **Testing.** `host.Root.ForConnection("bob-tab", clientKey: "bob")` drives the
  window as a second page, `RunicViewDriver.Connection` is a driver's
  connection, and `host.Connections` lists the connections.

### Behaviour changes

- **A page's command identity ends with the command.** Work that a page's
  command starts and that outlives it, such as a timer, `Task.Run` or a
  background loop, no longer acts for that page. Its ReactiveUI interactions,
  `ViewQuestion`s and view requests follow the rules outside a command, and
  `RunicInteractionInvocation.Current` is `null` there.
  - An awaited command keeps its identity until its task completes.
  - A navigation keeps the identity of the command that started it until the
    navigation ends, so a leave guard still asks the page that clicked, also for
    `_ = region.BackAsync()` in a synchronous command.
  - The window scope (native menu bar, host shortcuts, `EnterWindow`) is
    unchanged and flows with its work.
  - An in-page menu click keeps the page until a CommunityToolkit
    `IAsyncRelayCommand`'s task completes. An async ReactiveCommand or other
    `ICommand` run by an in-page click should ask its page before its first
    `await`.
  - Enter `RunicInteractionInvocation.EnterWindow(viewModel)` for long-lived
    work that should ask the window's page.

## Window presentation and color schemes (W)

### A ViewModel controls its own Window (B1)

`IRunicWindowPresentation`, registered per Window by `AddRunicWindowService()`,
lets a ViewModel bring its Window to the front, minimize it, hide it to a status
icon and show it again, make it full-screen, mark its document edited (macOS)
and switch it between light and dark, without naming the host (#807). It reports
whether the Window is active, minimized and visible, with `ActivityChanged` and
`PropertyChanged` raised in the Window's model turns, so a ViewModel can pause
polling while the user works elsewhere; ReactiveUI uses `WhenAnyValue` or the
`ObserveActivity()` extension. It works on Runic Desktop (WebView2, WKWebView,
WebKitGTK with GTK 3 and GTK 4), in WPF through
`WpfPlatformServices.ForWindowPresentation(window)`, and on CS-WebUI as far as
WebUI allows (`PresentAsync`, and `Minimize` with `UseWebView`).

- `Features` says what a host can do, and requests a host cannot do return
  `Unavailable` instead of throwing. A host that cannot report activity counts
  as active and visible (`Features.Activity` tells real from assumed).
- Code outside the scope uses `IRunicWindow.Presentation`.
- `DesktopWindow.Activity` and `ActivityChanged` report the same for Runic
  Desktop windows, and custom window hosts add them with
  `IDesktopActivityWindowHost`. New `DesktopWindowCapabilities.Activity`,
  `ColorScheme` and `PerWindowColorScheme`.
- Log events 1130 `WindowPresentationHandlerFailed` (Views, and
  `Runic.Application.Views.Wpf`) and 3040 `WindowActivityHandlerFailed`
  (Runic Desktop).
- **Testing.** Register `RunicTestWindowPresentation` with
  `AddRunicTestWindowPresentation()`, drive the activity with
  `RunicWindowTestHost.SetWindowActivityAsync`, and wait for posted changes with
  `FlushWindowPresentationAsync`.

### Light and dark at run time (B2)

`DesktopHost.SetColorSchemeAsync` switches the whole application between light
and dark while it runs, and `DesktopWindow.SetColorSchemeAsync` switches one
window (#807). The page's `prefers-color-scheme` and the window's frame follow
without a reload: the WebView2 profile and title bar on Windows,
`NSWindow`/`NSApp.appearance` on macOS, and GTK's color-scheme settings or
libadwaita's style manager on Linux, where the scheme applies to every window of
the application. A window's own `ColorScheme` still wins; `NoPreference` follows
the application's scheme. ViewModels switch through
`IRunicWindowPresentation.SetColorSchemeAsync`. Custom window hosts add it with
`IDesktopColorSchemeWindowHost`.

On a shared scheme, which is every GTK window of the process and the windows of
one WebView2 `ProfilePath`, a window's switch changes all of them, and
`Features.PerWindowColorScheme` says which kind a window has. `ColorScheme`
reports the scheme a window actually shows. `NoPreference` returns GTK's
settings to the desktop's.

### Behaviour changes

- `DesktopWindow.FocusAsync` on Windows restores a minimized window before
  activating it, as macOS and GTK already did (#807).

## Window management (WM)

### Find, focus and open Windows for a result (B6)

`IRunicWindowService` now manages the open Windows (#814).
`FindOrOpenAsync<TWindow, TParameter>(key, parameter)` brings the Window with
that key to the front, or opens it, so "open this document" focuses the
document's Window when it is open already. `ActivateAsync(window)` shows,
restores and focuses a Window, and the dialog that blocks it. `Windows`,
`WindowsChanged` and `ObserveWindows()` list the open Windows, without
System.Reactive. `OpenForResultAsync<TWindow, TParameter, TResult>` opens a
Window and returns what its ViewModel completed through
`IRunicWindowResult<TResult>`, or no result when the user closed it. A throwing
`WindowsChanged` handler is logged as event 1181 `WindowsChangedHandlerFailed`.

The new `IRunicWindowService` members have default implementations, so an
implementation of your own still compiles; they throw `NotSupportedException`
until it implements them.

### Owned and window-modal Windows (B6)

`RunicWindowOptions.Owner` and `Modality = RunicWindowModality.Window` open a
Window that belongs to another and blocks it until it closes, as a dialog does:
the owner `HWND` and `EnableWindow` on Windows, a child window or sheet on
macOS, and a transient window with an insensitive owner on Linux (GTK 3 and
GTK 4) (#814). An owned Window hides and shows with its owner, and a guarded
owner's close asks its owned Windows first. A ViewModel names its own Window
with `IRunicWindowContext.Window`. Runic Desktop windows have the same as
`DesktopWindowOptions.Owner` and `Modality`, also with a WPF window as the owner
(`WpfPlatformServices.ForDesktopWindowOwner`); custom window hosts receive the
owner's handle when they report `DesktopWindowCapabilities.Ownership`. CS-WebUI
opens such a Window on its own and logs event 1180 `WindowOwnerIgnored`.

On macOS a window-modal Window is a sheet, which has no title-bar close and
which Esc does not close, so its page offers Cancel.

### Test real Windows and their close decision (E2)

`RunicWindowTestHost.CreateWindowAsync<TWindow>(services)` opens a real Window
headless with the application's own window service (#814).
`RequestUserCloseAsync()` closes it as the user does and tells whether its close
guard let it close, and `OpenedWindows` and `WaitForOpenedWindowAsync<TWindow>()`
reach the Windows its ViewModels opened, with their parameter, key, owner and
root driver.

## Platform: menu check marks, power events and recent documents (P)

### Added

- **Menu check marks follow state.** A check or radio item's mark now comes
  from the command target: `IDesktopMenuCommandTarget.IsChecked(item)` (a
  default method with no answer, so the declaration stays), or
  `IRunicMenuCheckedSource` on a Window's root ViewModel, which is read again
  after the root ViewModel raises `PropertyChanged` or the app calls
  `RunicMenu.Refresh(viewModel)` (or `RunicMenu.RefreshAll()`). The mark follows
  the key window on macOS, Windows, GTK 3 and 4, a Linux global menu and the
  in-page menu bar, without rebuilding the bar with `SetMenuBar` (#802, #821).
- **Power and session events.** `IDesktopPowerEvents` (Runic.Platform) reports
  sleep and wake (`Suspending`, `Resumed`), session lock (`Locked`,
  `Unlocked`), and on-battery and low-power changes, with `ReadAsync` for the
  current `DesktopPowerState`. It uses `WM_POWERBROADCAST` and WTS session
  notifications on Windows, `NSWorkspace`, the screen lock notifications and
  IOKit on macOS, and logind, UPower and the power-profiles daemon on Linux.
  Runic Windows get it from `AddRunicPlatformServices`; CS-WebUI and serve-only
  report `Unavailable`. `Suspending` is a hint: the system does not wait for the
  application. A Flatpak needs `--system-talk-name` for
  `org.freedesktop.login1`, `org.freedesktop.UPower` and
  `org.freedesktop.UPower.PowerProfiles` (#808).
- **Recent documents on Windows and Linux.** `IDesktopRecentDocuments`
  (Runic.Platform) adds a document to the desktop's recent documents and clears
  the application's list, with each outcome as a `PlatformResult`. It uses Open
  Recent and the Dock on macOS, Recent items and the Jump List on Windows
  (`SHAddToRecentDocs`), and `recently-used.xbel` on Linux, which GTK and KDE
  file choosers list. Runic Windows get it from `AddRunicPlatformServices`;
  CS-WebUI and serve-only report `Unavailable`. On Linux the list is capped at
  500 entries, and a damaged `recently-used.xbel` is reported, never replaced.
  On Windows, clearing empties only the application's Jump List (#803).

### Behaviour changes

- `DesktopHost.NoteRecentDocumentAsync` and `ClearRecentDocumentsAsync`, which
  did nothing outside macOS, now add to and clear the recent documents on
  Windows and Linux too (#803).

## Forms (F)

### Locale-aware fields and new field kinds (C1)

`createFieldController`, `useField` and `injectField` take `locale`, `scale`,
`parse` and `format` (#797). With `locale: navigator.languages`, a number field
in German shows `2,5` and reads `1,5` and `1.234,5`; the text is never grouped
while it is edited. Without `locale`, a field follows the window's locale when
the application sets one ([Translated text](#translated-text-e5)) and otherwise
keeps the invariant form `1.5`, which `<input type="number">` needs.

Generated descriptors give `decimal` members the kind `decimal`, an exact
string. `DateOnly`, `TimeOnly`, `DateTime` and `DateTimeOffset` members get
`date`, `time` and `datetime`, whose text is what the native date and time
inputs use. A `datetime` field shows the page's local time and writes a local
edit with the page's offset; an edit of a `DateTimeOffset` field keeps the
value's offset when the text is unchanged and inside a DST overlap. `scale`
limits the digits after the point of the number the text means.

### Enum value lists and field constraints (C8)

Each generated C# enum type has a value list beside it, `{Enum}Values`, for menus
and `<select>` options (#800). Field descriptors carry `constraints` from
`[Required]`, `[MinLength]`, `[MaxLength]`, `[StringLength]`, `[Range]` and simple
`[RegularExpression]` attributes, so a page can set `required`, `maxlength`,
`min`, `max` and `pattern` on its inputs. They are hints: the field controller
does not check them, and .NET still validates. Date and time bounds are in ISO
form. A pattern is included only when a browser's `pattern` attribute reads it
as .NET does: no `\d`, `\w` or `\b`, and no character class that the `v` flag
rejects.

### `long` collection keys (C7)

`[RunicCollection]` accepts `long` key properties in addition to `string`,
`Guid` and `int` (#800).

### Validation in progress (C3)

A ViewModel can report that its validation is still running, for example an
asynchronous check of a user name (#805). Implement `IRunicPendingValidation` by
delegating to a `RunicPendingValidation`, then wrap the check in
`Pending.Track(nameof(UserName), cancellationToken => …)` (CommunityToolkit),
which cancels the previous check of the name, or follow a ReactiveUI.Validation
rule with `TrackPending`. The page's field handles gain `validating`
(`useField`, `injectField`, `createFieldController`), so a form can show
"checking…". The wire feature is `validation-pending/1`: `validation.pending`
lists the paths, sorted, and `validation.pendingTruncated` reports when its
limits cut it. Pages and hosts before 0.16 ignore both. In tests, use
`RunicViewState.IsValidating`.

### Edit sessions and forms (C2)

`RunicEditSession<T>` (`Runic.Navigation`) keeps a form's saved baseline and
tells whether the edited values differ from it (`IsDirty`, with change
notification) (#809).

- Use `Accept(submitted)` after a save and `Revert` to discard.
- It works with ReactiveUI, CommunityToolkit and WPF ViewModels, and pairs with
  `LeaveConfirmation`.

On the web, `useForm` (React, Vue, Svelte), `injectForm` (Angular) and
`createFormController` combine fields into one `dirty`, `pending` and `valid`
state.

- `submit(command)` writes every field before it runs the command, and retries
  a draft that a lost connection kept.
- It skips the command when a value did not reach .NET.
- With `waitForValidation`, it can wait for running checks.
- The adapters also re-export `commitAllFields`.

### Field drafts before departures (C2)

A 0.16 page and host use `field-flush/1` (#809). Before a departure guard runs,
the window asks its pages to write what the user typed but the page has not
sent yet, and waits up to 1 second. This covers a navigation from a menu, a
shortcut or the model, `RequestCloseAsync` (also from a menu command), and the
close button of a guarded window, so `IsDirty` includes the last keystrokes.
Only the departing window's pages are asked; an unanswered flush is logged at
`Debug` as event 1140 `FieldFlushUnanswered`.

- Register other presentations with `RunicDraftFlush.Register(context, …)`.
- The page also writes its drafts on Ctrl/Cmd/Alt shortcuts and when its window
  loses focus, and before it acknowledges a window close. AltGr and Option
  typing don't count as shortcuts.
- In tests, set `InMemoryBridgeTransport.FieldFlush`, or call `flushFields()`
  on the mock bridge.

### Behaviour changes

- Decimal and date/time members are no longer kind `text`. `BridgeFieldKind` is
  open; a page that switches over it treats an unknown kind like `value` (#797).
- Empty text in a nullable `decimal`, `date`, `time` or `datetime` member is now
  `null`, and in a non-nullable one an `invalid-text` error; before, `""` was
  sent.
- `datetime` text is the page's local time rather than the wire string.
- `time` text omits zero seconds (`10:30`); reading `10:30` gives `10:30:00`.
- Number text no longer accepts hexadecimal or binary forms (`0x10`, `0b1`).
- A nullable UTC `DateTime` that starts as `null` writes a local date-time,
  which .NET reads as `Unspecified`; give it a `parse` that writes UTC (the
  Views README shows one).
- With a 0.16 page and host, a departure guard runs after the window's pages
  wrote their drafts, up to 1 second later than before (#809).

## Editable rows and nested fields (C4)

A page can now edit the members of an object and the cells of a collection's
rows as fields, with no command per cell (#816).

- `InvoiceFields.address.street` and `InvoiceFields.lines.at(line.id).quantity`
  work with `useField`, `injectField`, `bindField` and forms.
- Each cell keeps its draft and writes after a pause or on blur.
- It shows the validation messages .NET reports at its path, such as a row's
  `INotifyDataErrorInfo` error.
- It reports a conflict when another writer changed the same cell meanwhile. A
  change of another cell in the same row is not a conflict.

On the .NET side:

- Settable object members get these fields automatically, down to three objects
  deep. A write assigns a copy of the object with the one member changed,
  through the setter.
- A `[RunicCollection]` becomes editable when the ViewModel declares a row
  editor, `[RunicRowEditor] void UpdateLine(int id, InvoiceLine line)`. It
  receives a copy of the row with one cell changed, replaces it, and can
  normalize it or throw to refuse it.
  - Copies keep members the page does not see, such as a `[RunicIgnore]`
    database id.
  - Use records, or sealed classes with a copy constructor or `Clone()`.
  - An optional `RunicRowEdit` parameter tells the editor which cell changed and
    what the row was before.
  - `Conflicts = RunicRowConflicts.Row` makes any change of the row meanwhile a
    conflict.
  - `[RunicNoField]` keeps a member read-only.
- Generator diagnostics `RUNICBRIDGE050` (a row editor that matches no single
  keyed collection, names a query collection, or has another signature),
  `RUNICBRIDGE051` (two row editors for one collection), `RUNICBRIDGE052` (rows
  that cannot be copied exactly) and the warning `RUNICBRIDGE053` (an object
  inside an editable row that cannot be copied).
- Tests write cells with
  `RunicViewDriver.WritePathAsync(vm => vm.Lines, ["7", "quantity"], 3)`.

Pages and hosts of 0.16 use the new protocol feature `field-paths/1`; older
pages and hosts are unaffected. See the new `examples/invoice-grid`.

## Translated text (E5)

Text that a ViewModel produces, such as a status line or a validation message,
can follow the window's language (#818).

- Give a member, DTO member or command result the type
  `Runic.Translations.TranslationReference`, or a validation message a text
  reference (`RunicValidationMessage.Text`, `RunicValidationResult`, or
  `IRunicTextReferenceSource` for ReactiveUI.Validation). The page then shows it
  in the window's language with its Translations runtime.
- Set the window's language from the ViewModel with `IRunicWindowLocale`, which
  `AddRunicWindowService()` registers. The window's pages follow it and format
  every reference again, without a call per string. `null` (the default) leaves
  each page in its own language.
- On the page, connect the generated Translations runtime once with
  `configureTranslatedText`. Then use `useText` (React, Vue, Svelte),
  `injectText` or the `runicText` pipe (Angular), `texts` (Effect) or
  `resolveText`. Field errors are translated automatically.
- A reference of a later Translations transport version than the page reads
  shows its fallback text. The Views packages do not depend on Runic
  Translations.
- Tests read references with `RunicViewState.Read`, and the mock bridge's
  `setWindowLocale` pushes a locale. See "Translated text" in the
  `Runic.Application.Views` README and the multi-window example.
- The wire feature is `translation-text/1`. Log events 1170
  `WindowLocaleChanged` (Debug) and 1171 `ValidationTextTooLarge` (Warning).

### Behaviour changes

- **Number, date and time fields follow the window's locale.** Once the
  application sets `IRunicWindowLocale`, number, date and time fields without
  their own `locale` show and read their text in the window's locale (`2,5`,
  `03.11.2026, 21:30` in German, `11/03/2026, 9:30 PM` in `en-US`); they format
  again when the locale changes, but never while the user edits a draft, and
  date and time fields also accept the ISO form. The ViewModel still receives
  the same values; the wire value stays the invariant or ISO form. A field bound
  to `<input type="number">`, `type="date"`, `type="time"` or `datetime-local`
  takes `locale: null` to keep the forms those inputs need (`bindField` does
  that itself). A window without a locale keeps the invariant and ISO forms.
- A date or time field with its own `locale` option shows it in that locale's
  form.

## Query collections (Q, C5)

- **Large lists that stay in .NET.** A `RunicQueryCollection<TRow, TKey>`
  property is a list too large to send, such as a database table, that the page
  sorts, filters and scrolls (#813). The rows stay in an `IRunicRowSource`.
  `RunicQueryableRowSource` runs over any `IQueryable` (Entity Framework Core,
  an in-memory list) with the fields `RunicQueryFields` allows. Each page loads
  only the rows it shows, in cached, shared and cancellable pages, so memory
  stays bounded however long the list is.
- **Per-presentation ranges.** The query (sort and filter) is ViewModel state
  that every presentation shares. Each page or CS-WebUI client reads its own
  range, so scrolling one client doesn't move another. The host bounds what each
  connection and each burst of query changes can make the row source do; a
  request over a connection's limit is `rejected` with the new reason `busy`,
  which the client retries.
- **Page side.** Generated clients have `client.queries.{name}` with
  `setRange`, `setQuery`, `indexOf`, the total, placeholders, and loading and
  error state.
  - `createQueryViewportController` lays rows out with variable heights and
    scrolls to a key.
  - React, Vue and Svelte have `useQueryCollection`, Angular
    `injectQueryCollection`, and `@runic-artifex/views-effect`
    `queryCollectionChanges` and `queryViewportChanges`.
- **WPF.** `CreateView()` binds the collection to a virtualizing
  `ItemsControl`.
- **Testing.** The mock bridge serves query rows with latency, and
  `Runic.Application.Testing` adds `QueryRowsAsync`, `SetQueryAsync`,
  `IndexOfAsync` and `RunicTestRowSource`.
- **Example.** `examples/query-collections` shows 100,000 rows with sort,
  filter, variable heights and scrolling to a row.
- **Recipes.** The README shows DynamicData integration and flattened trees,
  which keep row changes on expand and collapse.
- **Wire.** New `hello` feature `query-collections/1`. Pages and hosts of
  earlier releases keep working; the generated client and host must come from
  one release, as before.
- Generator diagnostic `RUNICBRIDGE060`; log events 1190
  `BridgeQueryRowsFailed`, 1191 `BridgeQueryIndexFailed`, 1192
  `BridgeQuerySetFailed` and 1193 `QueryCollectionWithoutModelContext`.

## Blobs and uploads (BL, C6)

Binary data now crosses the Bridge without JSON (#815):

- **`RunicBlob`.** Use it for images, thumbnails and downloads that a ViewModel
  produces: a state property, a DTO or collection member, or a command or
  operation result. The page receives `{url, type, size, name}` and uses `url`
  directly in `<img src>`, `<a href download>` or `fetch`. The window's host
  streams the content with its media type, file name and caching headers, and
  answers byte ranges.
  - Create one with `RunicBlob.FromBytes`, `FromFile` or `FromStream`.
  - The URL is unguessable and works only for its window. On Runic Desktop and
    WPF it works only for the window's browser. It stops working when the
    property stops holding the blob, when the View is released, or when the
    window closes.
  - Every blob response carries a sandboxing content security policy, so HTML or
    SVG a user uploaded cannot run in the application's origin.
- **`RunicUpload`.** This is how files come in from the page.
  `client.upload(file, { signal, onProgress })`, or `upload` from
  `@runic-artifex/views`, streams the file over HTTP to the window's host and
  resolves with a `BlobRef`. A command whose parameter is a `RunicUpload` takes
  it.
  - The command reads the file with `OpenReadAsync` or moves it with
    `SaveAsAsync`.
  - An upload works only on the connection that sent it, only once, and for at
    most 10 minutes.
  - Limits: `MaximumUploadBytes` (default 256 MiB) and
    `MaximumWindowUploadBytes` (default 1 GiB) on `RunicWindowOptions` and the
    host options. An upload that sends nothing for 30 seconds is dropped.
  - Uploads are stored in a new private folder of each window and read through
    the file the host created.
  - On CS-WebUI, which has no file dialogs, this is the way to get a file into
    .NET.
- `RunicBlob.Release()` ends a blob's URLs at once. A blob in state or in a
  `[RunicCollection]` row stays served while it is shown, whatever the number of
  rows. A window keeps at most 1,024 blobs of command results and interaction
  inputs, and releases the oldest beyond that (event 1208 `BlobEvicted`).
- A property that holds a `RunicBlob` is read-only for the page. A `RunicBlob`
  command input fails the build with `RUNICBRIDGE065`; take a `RunicUpload`.
- **Testing.** `RunicWindowTestHost.UploadAsync` and `ReadBlobAsync`,
  `RunicUpload.FromBytes` for ViewModel tests, and on the page `mockBlob()` and
  the mock Bridge's `uploads`.
- **Native server.** `Runic.Desktop.NativeServer` streams request bodies (C ABI
  3). Applications that reference the package get the matching library.
- The new example `examples/attachments` shows an avatar and attachment uploads.
- Log events 1200–1208 (`BlobServeFailed`, `UploadRejected`,
  `UploadReceiveFailed`, `UploadExpired`, `BlobRequestDenied`,
  `BlobsUnavailable`, `BlobCleanupFailed`, `BlobEndpointFailed`,
  `BlobEvicted`). The wire feature is `blobs/1`.

### Behaviour changes

- **CS-WebUI windows serve blobs and uploads from a loopback endpoint of their
  own**, an `HttpListener` on `localhost` that each window starts, on another
  origin than the page. A page `Content-Security-Policy` must allow
  `http://localhost:*` for `img-src`, `media-src` and `connect-src` for blobs
  and uploads to work. A window whose listener cannot start opens without blobs
  and uploads (event 1207).

## Region collections (D1)

- **Region collections (`region-collections/1`).** A web View can present
  navigation regions that open and close at run time, such as document tabs
  that each keep their own back stack (#810).
  - Mark a get-only `NavigationSelection` with
    `[RunicRegionCollection(typeof(IPage))]` and add tabs with `Add`.
  - The page gets `{ regions: { key, content }[]; selected }` and generated
    `select{Name}(key)` and `close{Name}(key)`.
  - Both go through the departure guards: a switch asks the tab left as
    `Retain`, and a close asks every page of the tab as `Retire`. They resolve
    with the `NavigationOutcome`.
  - `PageCanClose = false` leaves tab closing to the ViewModel.
  - A second close of a tab whose close is pending joins it, and a select
    supersedes a pending close.
  - A guarded window close removes tabs one by one, so the tabs that agreed
    close even when a later one keeps the window open.
- **Adapters.** React, Vue, Svelte and Angular render a collection with
  `RegionOutlets`, which keeps hidden tabs mounted by default. `panelProps` adds
  tab-panel attributes, and `regionEntries()` builds a tab bar.
- **Mock bridge.** The mock bridge and generated mocks answer region requests;
  a `regions` handler stands in for the guards.
- **Testing.** `Runic.Application.Testing` adds `state.Regions(...)`,
  `SelectRegionAsync`, `CloseRegionAsync` and `RunicCallReply.RegionOutcome`.
- **ReactiveUI.** `Runic.Navigation.ReactiveUI` (both flavors) adds
  `WhenRegionsChanged()` and `CreateCloseCommand()`.
- **Diagnostics and logging.** Generator diagnostics `RUNICBRIDGE070` and
  `RUNICBRIDGE071`; log events 1210 `BridgeRegionRequestFailed` and 1211
  `BridgeRegionRequestUnresolved`.
- **Example.** `examples/document-tabs`.

A page and a host that do not both list `region-collections/1` keep the 0.15
behaviour. Only Views that use the attribute get a new contract fingerprint.

## Navigation paths, Back and the URL (D2)

### Routes, saved paths and deep links

- **Navigation routes and saved paths.** Runic.Navigation can save a window's
  navigation and rebuild it after a restart (#817).
  - Every `AddRunicNavigationRoutes(...)` call adds to one map. It maps typed
    route templates, such as `customers/{id:int}/invoices/{invoice:int}`, to
    navigation targets and names entries back.
  - `navigator.GetPath()` returns a `NavigationPath`: every region's entries by
    route, the regions and selections below them, and selected tabs.
    `NavigationPath.ToJson`/`FromJson` store it wherever the application keeps
    its state.
  - `RestoreAsync(path)` rebuilds it with ordinary navigation requests, so
    guards and hooks run. It keeps what already matches and reports what it left
    out in `NavigationRestoreResult.Issues` instead of failing.
  - A region stops at its first page that no longer has a route, unless
    `NavigationRestoreOptions.UnmappedEntries` is `Skip`. Restores are capped at
    256 entries per region and 256 tabs per selection.
  - Tabs that couldn't be restored are discarded rather than left as empty
    regions; `RunicNavigator.DiscardRegionAsync` does the same for an app's own
    abandoned tab.
  - Region-collection tabs are restored by position through
    `NavigationSelectionOptions.RestoreRegion`.
  - Route paths are at most 2048 characters without control characters, and
    string parameters are untrusted text.
- **Deep links.** `region.OpenRouteAsync(route, mode)` opens a route path from a
  link, a notification or a second launch. `NavigationRouteOpen.Stack` builds
  the history from the route's prefixes, so `customers/42/invoices/7` gives
  Customers → Customer 42 → Invoice 7. `NavigationRouteLinks.TryGetRoute` reads
  the route of `myapp://…` and `https` web links.
- **Testing.** `Runic.Application.Testing` adds `navigator.SavePath()` and
  `RestorePathAsync(saved)`, with `RunicNavigationRestore.IsExact`, for restart
  tests.
- **Logging.** Events 1220 `NavigationRestoreSkipped` (Information) and 1221
  `NavigationRouteUnmatched` (Debug).
- **Example.** `examples/document-tabs` reopens its tabs after a restart and
  opens `document-tabs://` links from the command line, a second instance and a
  notification.

### Back and the URL (`navigation-path/1`)

A web View page can go back in its window, and keep its URL in step with the
window's navigation (#819).

- `installBackNavigation()` makes the mouse's Back button, Alt+Left, Cmd+[ on
  macOS and the Browser Back key run `RunicNavigator.BackAsync()`. That goes
  back in the innermost presented region that can, such as the selected tab or
  an open dialog, through its departure guards. With `installNavigationPath()`
  active, they go back in the page's history instead, so a Back runs once.
- `RunicPresentation.SyncNavigationPath(region)` makes a region the window's
  path region. With `installNavigationPath()`, the URL follows it, for example
  `#/customers/42/invoices/7`.
- The browser's Back and Forward and the address bar open their path through
  the guards; a refused change puts the URL back. Going back to a page without
  a route goes back in the window. History entries keep their index and path
  across a reload.
- A path in the URL when the page loads opens as a deep link, also when the
  window chooses its path region later.
- Several pages of one window follow the same path region, and the last change
  wins.
- `navigateBack()`, `openNavigationPath(path)` and `onNavigationPath(listener)`
  are available for routers of the page's own, such as SvelteKit's.
- **Adapters.** React, Vue, Svelte and Angular re-export the navigation
  functions.
- **Mock bridge.** `createMockBridge({ navigation })` and `pushNavigationPath`.
- **Testing.** `Runic.Application.Testing` adds `NavigateBackAsync()`,
  `OpenNavigationPathAsync(path)` (a simulated `popstate`) and
  `NavigationPathPushes`.
- **Example.** The `examples/document-tabs` page goes back in the selected tab
  with the mouse and keyboard.

A page and a host that do not both list `navigation-path/1` keep the earlier
behaviour: the page's navigation calls fail with a `failed` BridgeError.

## Testing and page errors (T)

### Platform test fakes (E1)

- `services.AddRunicTestPlatform()` (`Runic.Application.Testing`) registers
  scripted, recording fakes for a window's platform services, and
  `RunicWindowTestHost.Platform` returns them (#799). They cover file dialogs,
  with in-memory leases that follow the real single-use, one-transaction and
  conflict-checked commit rules; message boxes; context menus; the clipboard;
  notifications; the launcher; and announcements.
- Queue what the user does:
  `host.Platform.FileDialogs.EnqueueOpen("notes.txt", "Hello")`,
  `EnqueueSave("out.txt")`, `MessageBoxes.EnqueueAnswer("save")`,
  `ContextMenus.EnqueueChoice("row.delete")`. Then assert on `Calls`,
  `ReadAllText()` or `Clipboard.Writes`. An unscripted call answers as a user
  who dismissed it.
- Serve-only browser tests script the same fakes across the process boundary.
  Use `RunicServeOnlyTestPlatform` in the test, and
  `services.AddRunicServeOnlyTestPlatform()` in a test build of the application
  that also carries `[assembly: RunicServeOnlyTestPlatform]`. Activation logs
  warning 1158 `ServeOnlyTestPlatformActive`.

### Every Window in serve-only browser tests (E3)

- `RunicServeOnlyApplication.Urls` lists the URL of each Window the application
  opens (#801).
- `WaitForWindowUrlAsync(1, timeout)` or
  `WaitForWindowUrlAsync("SettingsWindow", timeout)` waits for a later Window.
- Runic Desktop and CS-WebUI now follow each `RUNIC_APPLICATION_URL=<url>` line
  with `RUNIC_APPLICATION_WINDOW=<url> <Window type>`. Parsers that read only the
  URL line are unaffected.

### Page errors in .NET logs (E4)

- Call `installErrorReporting()` from `@runic-artifex/views` once when the page
  starts. Its uncaught errors, unhandled promise rejections and the errors the
  Views runtime catches are then logged by the .NET host as event 1150
  `PageError`, in the new category `Runic.Application.Views.Page`
  (`RunicViewsTelemetry.PageLogCategory`), where crash reporters and log
  forwarders that read `ILogger` see them (#804).
- Reports are bounded, redacted and rate-limited: URLs lose their query and
  fragment, and a `redact` hook can remove more. The host caps and cleans them
  as untrusted input, marks every stack line, and logs at most 10 per page
  connection and 30 per window a minute (events 1151 `PageErrorsSuppressed` and
  1152 `WindowPageErrorsSuppressed` when it starts counting).
- New Views protocol 4 feature `client-errors/1`. Pages and hosts of earlier
  releases are unaffected.

## Views protocol 4 features

0.16 adds these features to Views protocol 4. Each is negotiated in `hello`, so
a page and a host of different releases use only what both list. The in-memory
test transport's `hello` lists `view-requests/1`, `region-collections/1`,
`query-collections/1`, `field-paths/1` and `navigation-path/1`, and
`field-flush/1` once a test sets `InMemoryBridgeTransport.FieldFlush`.

| Feature | What it adds | Section |
| --- | --- | --- |
| `request-session/1` | Requests name their page's session | [Security](#security-connection-keys-on-cs-webui) |
| `view-requests/1` | `view-requests` registration and `view-request` pushes | [View requests](#view-requests-and-view-questions-v-sdk796) |
| `validation-pending/1` | `validation.pending` and `validation.pendingTruncated` | [Validation in progress](#validation-in-progress-c3) |
| `field-flush/1` | The window asks pages to write their drafts before a departure | [Field drafts](#field-drafts-before-departures-c2) |

| `translation-text/1` | The window's `locale` push and the errors' `text` | [Translated text](#translated-text-e5) |
| `query-collections/1` | `query-rows`, `query-set` and `query-index`; reason `busy` | [Query collections](#query-collections-q-c5) |

## Known issues

- An async ReactiveCommand run by an in-page menu click keeps the page's
  identity only until its first `await`; ask the page before it. CommunityToolkit
  `IAsyncRelayCommand` keeps it until its task completes (#811).
- CS-WebUI reports no window activity (it counts as active and visible) and
  supports only `PresentAsync` and, with `UseWebView`, `Minimize` of
  `IRunicWindowPresentation` (#807).
- Wayland reports no minimized state: a GTK 4.12+ window counts a suspended
  surface as not visible, and a GTK 3 window only loses `IsActive` (#807).
- On Windows, `NoPreference` pins the title bar to the system's apps theme at
  the time of the call; a later system change does not reach it, while the
  page does follow (#807).
- `Suspending` is a hint: Runic takes no delay before the system sleeps, and a
  Linux watch that loses its D-Bus sources may miss sleeps, wakes and lock
  changes until it reopens them 5 seconds later (#808).
- Left to manual checks, not CI: native window ownership and modality
  (disabled owners, macOS sheets, transient windows on real compositors),
  activation and minimize on real window managers, run-time color scheme
  switching of title bars, menus and libadwaita, menu check marks in native and
  global menus, power and lock events on real hardware, recent documents in
  Explorer, Jump Lists, GTK and KDE file choosers, and blobs and uploads in
  WebView2, WKWebView and WebKitGTK windows
  (#802, #803, #807, #808, #814, #815).
