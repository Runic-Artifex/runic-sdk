- `dotnet runic dev`'s debugging endpoint for the WebKitGTK Window (Linux) no longer loses a file's breakpoints in VS Code's
  JavaScript debugger after a few reloads in quick succession, such as Vite's full reloads while files change. The
  endpoint passed WebKit's events on with a delay. In such a reload it could still tell js-debug of the scripts of a
  page WebKit had already left, right before telling it that the page was gone. js-debug then kept that page's
  original source of a file, bound to a script that no longer existed, and from then on set a breakpoint in that
  file only as a guess at its path: on the next page, or after the Window restarted, the debugger did not stop
  there. The endpoint now leaves out the scripts of a page that WebKit already replaced. It also no longer hides
  one of two scripts whose source maps name their source alike (`@vite/client` and `virtual:runic/client`), whose
  console output had kept js-debug from clearing a page's scripts (#1108).
