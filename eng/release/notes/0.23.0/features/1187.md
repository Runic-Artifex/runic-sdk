## `dotnet runic dev --browser`: an address of its own for each session, for one browser (#1187)

`--browser` now serves the Window at `http://<label>.localhost:9224/`, a proxy to the serve-only Window's pages instead
of a redirect to the Window's own address. The label is random for each `dev` run and stays the same across its Window
restarts, so a tab keeps its address when `dotnet watch` restarts the Window. A Runic Desktop page reloads itself onto
the new Window (the stopping Window's close command reaches it as the Bridge's token refusal), and the JavaScript
debugger's breakpoints stop again; reload a CS-WebUI tab. Chromium browsers (Chrome, Edge) and Firefox resolve names
under `.localhost` to the loopback interface themselves.

- **An origin for each session.** Pages, service workers, storage and cookies of an earlier session or another project
  do not reach a later one. The address answers only its own name: `127.0.0.1:9224`, `localhost:9224` and other labels
  get 403.
- **One browser, by a one-time code.** The `[dev] Browser:` lines carry the address with the current code
  (`http://<label>.localhost:9224/?code=…`), and `dev` writes `obj/runic/dev-browser.html`, a page only you can read
  (mode 0600, or an access list of your account alone on Windows), which opens it with the newest code. The session file
  names that page as `browser.codeFile` and lists the address with `*` for the label. The code admits one browser with
  `dev`'s host-only `HttpOnly`, `SameSite=Strict` cookie and is then replaced; a new admission ends the previous
  browser's, and closes its open connections. Every other client gets 403.
- **Bearer secrets.** The label, the code and the cookie admit whoever has them. The browser sends the cookie to
  `<label>.localhost` on any port, so `dev` keeps the label where it keeps the code: its `[dev] Browser:` output and the
  code page.
- **The template's `Window in Chrome`** opens that page (`"file": "${workspaceFolder}/obj/runic/dev-browser.html"`)
  instead of a fixed URL, so it also follows a moved port. A configuration that matches the page by URL uses
  `http://*.localhost:9224/*`.
- **The Window's side.** `dev` sets `RUNIC_APPLICATION_SERVE_ORIGIN` for the serve-only Window: Runic Desktop admits
  the address as an origin of its pages and connects their Bridge through it, on the page's own host; Runic's CS-WebUI
  host admits it at its upload endpoint. Both take only an `http` origin on `localhost` or one label under `.localhost`.

See [Debug the page in Chrome](https://github.com/Runic-Artifex/runic-sdk/blob/v0.23.0/tools/dotnet-runic/README.md#debug-the-page-in-chrome---browser)
and [Development server security](https://github.com/Runic-Artifex/runic-sdk/blob/v0.23.0/docs/security.md#development-server).
