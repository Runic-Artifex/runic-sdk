# 1.0 wording checklist

The 1.0.0 pull request applies these edits and then deletes this file
(I-084, PLAN-RC batch R7). Each row names the line as of the R7 pull request,
a fragment of the current text to search for when lines have moved, and the
text that replaces it. Together they remove "preview" tier wording, the
"until 1.0" and "from 1.0" qualifiers and the "since 0.y" version history from
the repository's guides, so the 1.0.0 pull request flips only version-specific
sentences. Wording that was already wrong before 1.0 was fixed in the R7 pull
request itself.

Rules behind the rows:

- `Runic.Application.Views.CsWebUi` stays the preview package: its
  `--prerelease` install and "(preview)" labels stay.
- `--prerelease` and `@preview` disappear from the other install commands: from
  1.0, npm `latest` and the NuGet default select the stable release.
- "(since 0.11)", "since 0.10" and "Since 0.11." notes are deleted: 1.0 is the
  first supported baseline, and the 0.9 to 1.0 migration guide
  (`docs/migration-1.0.md`) keeps the history.
- Former names that users may still search for stay without a version
  ("its former name", "Formerly `RTKSIZE1001`"). "Until 2.0" aliases stay.

Not in this list, because they stay at 1.0: `eng/release/notes/*`, the
graduated and retired tables in `docs/experimental.md`, the measured versions
in `examples/wpf-navigation/COMPARISON.md` and the dated size measurement in
`packages/web/views-effect/README.md`, verification records under
`packages/dotnet/*/docs/`, the `publish-preview.yml` workflow name (D026.3), and
the `preview` mode of `runic-translations support`.

Elsewhere, outside this file's scope:

- `publishConfig.tag` `preview` in `packages/web/*/package.json` and the npm
  `latest` rule are release tooling (PLAN-RC P1).
- runic-site (R9) and runic-translations-sdk READMEs (R11) carry their own
  preview wording.
