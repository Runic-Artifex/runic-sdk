Standalone implementation specification · draft 2

Typed text at compile time. Deterministic locale snapshots at runtime.

This document is the complete build plan for an independent, open-source text-resource compiler and runtime. It requires no access to any prior application, private repository, or design discussion. Implement the JSON schema, incremental generator, runtime, web artifacts, diagnostics and tests described here as the normative 1.0 contract.

01 · Product boundary

Compiler first, small runtime second

The library turns application-owned resource documents into validated, typed APIs. It owns schema, key identity, formatting semantics, fallback, immutable snapshots and build integration. It never owns product wording or frontend rendering.

01

Required in 1.0

  • One or more catalogs per project
  • Named, typed placeholders
  • Explicit locale fallback
  • Ordered overlays
  • Generated C# keys and accessors
  • TypeScript and template manifests
  • Packaged analyzer, CLI and MSBuild integration
02

Explicitly out of scope

  • Translation-management UI or network service
  • Automatic machine translation
  • Rich HTML resources
  • Runtime assembly scanning
  • Implicit filesystem or network lookup
  • ICU plural/select grammar in 1.0
  • Framework-specific widgets
03

Normative language

MUST is required for compatibility, SHOULD is the default with a documented exception path, and MAY is optional. Schema and artifact versions are independent from NuGet package versions.

Guiding invariants

  • Supported lookup paths use no reflection, runtime generic serializer metadata, dynamic code, or assembly discovery.
  • The generator and CLI call the same pure compiler kernel and produce byte-stable results.
  • All values are plain text. Encoding for HTML, attributes, JavaScript, URLs or terminals happens at the output sink.
  • Changing locale swaps one immutable snapshot atomically; readers never observe a partially built catalog.

Definition of a catalog

A catalog is an independently versioned set of stable dotted keys, locale declarations, layer declarations and generated API names. Its canonical key set is the effective default locale after layers are merged. A compilation MAY contain multiple catalogs; keys from different catalogs never collide.

02 · Source contract

Two JSON schemas, explicit MSBuild items

Every catalog has exactly one manifest and one or more resource documents. Files MUST be UTF-8, MAY contain a UTF-8 BOM, and MUST be valid strict JSON: no comments, trailing commas, duplicate object properties, NaN or Infinity.

Consumer project declaration

<ItemGroup>
  <TextResourceCatalog Include="Resources/Text/app.textcatalog.json" />
  <TextResourceDocument Include="Resources/Text/*.texts.json" />
</ItemGroup>

<PropertyGroup>
  <TextResourcesEmitTypeScript>true</TextResourcesEmitTypeScript>
  <TextResourcesWebOutputPath>$(IntermediateOutputPath)text-resources/web</TextResourcesWebOutputPath>
</PropertyGroup>

No filename discovery: the package supplies MSBuild targets that convert these item types into Roslyn AdditionalFiles with metadata. A file not included by one of these items is invisible to the compiler. This keeps design-time, command-line and CI builds identical.

Resource document: schema version 1

{
  "$schema": "https://schemas.cswebui.dev/text-resources/resources-v1.schema.json",
  "schemaVersion": 1,
  "catalog": "app",
  "locale": "en",
  "layer": "base",
  "resources": {
    "Common": {
      "Save": "Save",
      "Cancel": { "$value": "Cancel", "$description": "Closes without saving." }
    },
    "Files": {
      "Deleted": {
        "$value": "Deleted {count} files from {folder}.",
        "$description": "Shown after a successful bulk delete.",
        "$placeholders": {
          "count": { "type": "int", "format": "grouped" },
          "folder": { "type": "string" }
        },
        "$since": "1.0",
        "$tags": ["notification"]
      }
    }
  }
}

Key and tree rules

  • Every resource property is either a group object, a string shorthand leaf, or a metadata leaf containing $value.
  • Key segments match ^[A-Za-z_][A-Za-z0-9_]*$, are case-sensitive and cannot begin with $.
  • Dotted identity is the JSON path, for example Files.Deleted. A path cannot be both a leaf and a group.
  • C# keywords are emitted with @. A generator-name collision is an error; names are never silently renamed.
  • null, number, boolean and array resource leaves are invalid. A layer cannot delete a lower-layer key.

Leaf metadata

  • $value: required string in a metadata leaf.
  • $description: optional translator-facing context, copied to generated XML docs and manifests.
  • $placeholders: required when the pattern contains placeholders; forbidden when it contains none.
  • $since: optional opaque release label.
  • $deprecated: optional string reason; emits ObsoleteAttribute on generated C# and JSDoc @deprecated.
  • $tags: optional unique array of non-empty strings for tooling only.
  • Unknown $ metadata is rejected in schema version 1.

Locales, fallback and layers

ConcernNormative behavior
Locale syntaxUse canonical BCP 47 language tags recognized at build time. Comparison is ordinal-ignore-case; emission uses canonical casing. Empty, invariant, extension-only and private-use-only tags are rejected in v1.
Fallback graphFallback is an explicit single parent, not inferred from host culture. It MUST reference a declared locale, be acyclic, and lead to the default locale. The default locale has no parent.
Requested localeexact accepts only a declared tag. parentsThenDefault strips BCP 47 subtags until a declared locale is found, then uses the declared fallback graph; default maps every unsupported tag directly to default.
Layer mergeFor each locale, merge documents in ascending layer priority. A higher layer replaces the entire leaf value and metadata. Duplicate definitions for the same key, locale and layer are errors.
Canonical keysThe effective default locale defines all keys. A non-default locale cannot introduce a key unless extraLocaleKeys permits it; permitted extras are lookup-capable but do not generate API members.
CompletenessCompleteness checks direct effective values before fallback. At runtime, a missing direct value is resolved key-by-key through the declared graph. Placeholder metadata and types MUST match the default definition in every translation that supplies the key.
Multiple filesMultiple documents MAY contribute to one locale/layer when their key trees do not overlap. File path never influences precedence; only manifest layer priority does.
03 · Message grammar

Portable named placeholders, deliberately small

Version 1 defines a custom, deterministic message grammar instead of inheriting .NET composite formatting or JavaScript interpolation. This enables the same contract in C#, TypeScript and templates without executing arbitrary format strings.

Grammar

message      := (text | escaped-open | escaped-close | placeholder)*
escaped-open := "{{"
escaped-close:= "}}"
placeholder  := "{" name "}"
name         := [A-Za-z_][A-Za-z0-9_]*

A single unmatched brace, nested placeholder, whitespace inside a placeholder, format suffix inside the pattern, or undeclared name is invalid. Repeated placeholders are allowed and declared once.

Formatting ownership

The resource pattern declares placement only. The placeholder descriptor declares type and optional portable format. Generated APIs supply typed values; ITextValueFormatter formats them using the resource locale. The formatter receives a closed descriptor, never an arbitrary user format string.

Cross-runtime rule: iso, GUID, boolean and ungrouped numeric output MUST be byte-equivalent in .NET and TypeScript. Locale-sensitive date/number styles MUST be semantically equivalent and are tested against documented locale fixtures; exact punctuation MAY follow the platform's CLDR/globalization data. The runtime exposes resolved text as the authoritative option when exact identity matters.
Deferred: plurals, grammatical gender and select expressions require a separately versioned message-grammar proposal. Do not add ad-hoc branches to v1; they would make generated API and translation parity ambiguous.
04 · Compiler architecture

One pure kernel, three build surfaces

The Roslyn generator emits C# only. A deterministic build task and CLI emit files outside the compilation, because source generators must not write arbitrary files. All surfaces call the same parser, validator and model builder.

ComponentResponsibilityConstraints
CsWebUi.TextResources.CompilerInternal parser, source-span model, schema validation, locale/layer merge, pattern compiler, diagnostics, canonical intermediate representation (IR), C#/web renderers.Pure inputs/outputs; no environment, current directory, clock, network or reflection. Target net10.0.
CsWebUi.TextResources.GeneratorIIncrementalGenerator; maps AdditionalFiles and analyzer options to compiler inputs, reports Roslyn diagnostics and adds generated C# sources.Target net10.0; packaged under analyzers/dotnet/cs; no runtime dependency copied to apps.
CsWebUi.TextResources.BuildMSBuild targets/task for TypeScript, JSON and template artifacts under obj; declares Inputs/Outputs and exposes generated assets as items.Never edits source files. Output root must resolve beneath an explicit intermediate/output directory.
dotnet-textresourcesCLI commands validate, generate, verify and schema.Same diagnostics and bytes as build task; response-file support; deterministic exit codes.

Incremental generator pipeline

  1. Filter AdditionalTextsProvider by build_metadata.AdditionalFiles.CsWebUiTextResourceKind equal to Catalog or Document.
  2. Read each file once, retaining normalized relative display path, checksum, UTF-16 line map and cancellation token. Never use the absolute path in generated bytes.
  3. Parse each manifest/document independently into an immutable syntax model with exact JSON property spans. Cache by content checksum.
  4. Group documents by catalog ID; combine a catalog manifest only with its group. A change in one catalog MUST NOT invalidate another catalog's generated sources.
  5. Validate schema, keys, locales, layers and message patterns; produce canonical IR ordered by catalog ID, locale, layer priority and ordinal dotted key.
  6. Emit one hint file per catalog concern: {Catalog}.Keys.g.cs, {Catalog}.Accessors.g.cs, {Catalog}.Data.g.cs, {Catalog}.Registration.g.cs. This limits recompilation churn.
  7. Report diagnostics with file, line and column when attributable. Cross-file diagnostics use the most specific offending location and mention the counterpart path in the message.

Determinism

  • Ordinal sort everywhere; \n output newlines; UTF-8 without BOM for file artifacts.
  • No timestamp, random ID, assembly path, username, machine path or localized diagnostic text in outputs.
  • JSON artifact properties use a specified order and no insignificant whitespace in release mode.
  • Generated headers contain schema/artifact versions and content SHA-256 only.

CLI contract

  • validate --catalog <file> --documents <glob...>: no writes; exit 0 valid, 1 diagnostics, 2 invocation/internal failure.
  • generate ... --output <dir>: atomic temp-directory render then replace declared files.
  • verify ... --output <dir>: render to temp and byte-compare; report missing, extra and changed paths.
  • schema --output <dir>: write the bundled versioned JSON schemas for editor/tooling use.
05 · Runtime and generated API

Typed accessors over immutable snapshots

The runtime is frontend-neutral and does not require dependency injection. An optional Microsoft.Extensions.DependencyInjection adapter supplies generated, reflection-free registration for hosted applications.

Key identityCatalog + Id is the fast identity; Name is retained for diagnostics/transport. Generated IDs are assigned by ordinal dotted-key order and may change when keys change, so persisted data and protocols MUST use catalog + name, never integer ID.
SnapshotImmutable and thread-safe. Get applies the manifest missing policy. Format verifies argument names/types even though generated accessors normally guarantee them.

Runtime failure model

TextResourceNotFoundException

Catalog/key not present after fallback and missing policy is throw.

TextResourceFormatException

Runtime caller supplies missing, duplicate, unknown or incorrectly typed arguments.

TextResourcePackException

External pack is malformed, incompatible, over limits or rejected by integrity policy. It never replaces the active snapshot.

Canonical encoding: properties appear in the order shown; message keys and argument names are ordinal-sorted; UTF-8 has no BOM; release JSON has no insignificant whitespace. The contract fingerprint is lowercase SHA-256 over canonical UTF-8 JSON containing catalog ID, grammar version, and the default locale's ordered key/argument contracts—but no translated patterns. A generated locale artifact and a runtime external pack use this same schema. Asset SHA-256 additionally covers the complete emitted bytes.

Template integration

The template manifest is the stable integration point. A template compiler validates literal keys and argument names/types at build time, then emits either a C# accessor call, a browser key call, or already resolved text. Dynamic keys remain possible through the runtime interface but do not receive compile-time completeness guarantees.

Transport choices

  • Resolved: .NET sends text; smallest frontend and one formatting authority.
  • Manifest: host sends locale asset once, then UI messages carry keys and typed values.
  • Hybrid: static templates use browser catalog, server errors carry resolved text.

The library does not prescribe one topology.

Escaping boundary: values and formatted arguments are always plain text. The TypeScript runtime returns a string, never TrustedHTML. Template helpers must insert through their normal escaped-text operation. A future rich-content feature requires a separate type and threat model.

09 · AOT, performance and security

Constraints are designed in, not suppressed

Compile-time data is trusted as application source; external packs are untrusted input. Both paths have finite resource limits and no executable markup.

Native AOT

  • No Type.GetType, assembly scanning, expression compilation, dynamic code or unbounded generic activation.
  • No JsonSerializer.Deserialize<T> in runtime lookup. Optional external JSON uses a bounded token reader or source-generated JsonTypeInfo.
  • Public runtime carries IsAotCompatible=true and IsTrimmable=true.
  • No trim/AOT warning suppressions in library or smoke app.

Input limits

  • Defaults: 8 MiB/document, 64 nesting levels, 50,000 keys/catalog, 64 KiB value, 32 placeholders/value, 256 locales/catalog.
  • Build limits are configurable upward; runtime external-pack limits can only be tightened without explicit opt-in.
  • Parser cancellation is checked between tokens and compiler stages.

External packs

  • Contain artifact version, catalog, locale, compatibility SHA-256 and values for known keys only.
  • Load bytes from caller interface; library opens no URI/path.
  • Optional integrity callback verifies signature/hash before parse.
  • Validate fully and atomically before cache or snapshot replacement.

Injection safety

  • Text is never interpreted as HTML, JavaScript, CSS, URL or format code.
  • Format grammar cannot access members or invoke methods.
  • Logs redact resource values and arguments by default.
  • Diagnostics include key/path, never secret-bearing values.

Performance budgets

  • Unformatted generated lookup: zero allocation after snapshot creation.
  • Lookup time: O(1) indexed array with catalog/key validation.
  • Formatting allocates the returned string and bounded scratch storage only.
  • 10,000-key clean generation target: under 2 s on CI reference hardware; one-file incremental edit under 500 ms.

Concurrency

  • Snapshots are immutable and safe for concurrent reads.
  • Locale load is coalesced per canonical locale.
  • Failed/cancelled loads are not cached as success.
  • Dispose/cancellation race tests cover external providers and manager notifications.

11 · Delivery

Seven gated phases to 1.0

Each phase ends in a usable artifact and a hard acceptance gate. Avoid implementing external packs or web runtimes before source semantics and generated API are frozen.

Phase R0

Repository and normative schemas

Create solution, package boundaries, JSON schemas, schema documentation, compiler syntax model and diagnostic catalog. Implement strict parsing with source spans.

Gate: schema examples validate; every malformed fixture yields a specified diagnostic, never an exception.

Versioning and compatibility policy

Package versions

Runtime, DI adapter, generator and build package release in lock-step SemVer. The CLI SHOULD share the same version. During 0.x, release notes identify generated-source and schema breaks. At 1.0, public runtime API and generated C# shape follow normal SemVer.

Independent format versions

schemaVersion, message grammar, runtime ABI, web artifact and template manifest each carry an integer version. Package upgrades may support multiple read versions. Writers emit one documented current version. Unsupported versions fail explicitly; never guess.

Consumer changes

  • Removing/renaming a key or changing its placeholders is a generated source/API break.
  • Adding a key is source-compatible but changes artifact fingerprint.
  • Changing translated text is behavioral/content change, not library API change.
  • Changing catalog ID or generated namespace/class is a deliberate migration.

Compatibility enforcement

Generated code embeds runtime ABI and generator version constants. A mismatch that could be unsafe reports TR0024 at build time. External packs compare catalog ID, artifact version and canonical contract fingerprint before values are parsed into a snapshot.

1.0 acceptance checklist

  • Versioned catalog/resource/web/template schemas are published with examples.
  • All diagnostics have tests for ID, severity, message arguments and exact location.
  • Clean and incremental generator outputs are byte-stable across Windows/Linux and host cultures.
  • One compilation can contain two independent catalogs without cross-invalidation.
  • Generated C# uses typed named parameters and contains no reflection or runtime JSON dependency.
  • Runtime lookup and locale swap satisfy allocation, concurrency and failure semantics.
  • TypeScript and template artifacts validate against their schemas and contain stable fingerprints.
  • .NET and TypeScript pass the shared message-format conformance corpus.
  • External packs are bounded, integrity-checkable and atomically rejected on any error.
  • Package tests restore only from a temporary feed and use no repository build files.
  • Windows and Linux Native-AOT smoke applications publish and run with zero trim/AOT warnings.
  • Public API approvals, package-content approvals, security review and license scan pass.
  • README documents a 10-minute first catalog, locale addition, DI-free usage, hosted usage and web generation.
  • No source build writes into the consumer repository outside explicitly requested CLI generation.
