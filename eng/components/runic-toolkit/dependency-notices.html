Standalone library plan · draft 1

Reproducible dependency notices, generated offline and linked to the SBOM.

Build a framework-neutral .NET toolchain that inventories resolved NuGet and npm dependencies, combines them with explicitly declared components, validates SPDX license expressions and organization policy, and emits trustworthy notice documents plus a small Native-AOT-safe runtime model. Generation is deterministic, network-free, and independent of any user interface.

01 · Product boundary

A compliance aid with explicit limits

The library creates an auditable dependency-to-notice pipeline. It must report ambiguity instead of making legal conclusions, and it must remain useful to command-line tools, desktop applications, servers, and static websites without referencing a UI framework.

01

Inventory

Read exact resolved component versions, production/development scope, direct/transitive relationship, package identity, origin, hashes, and available license metadata.

02

Evidence

Resolve license expressions, license files, notices, copyright statements, repository metadata, and manual attestations into immutable, traceable evidence records.

03

Policy

Apply allow, deny, review, obligation, missing-evidence, and override rules without changing the observed package metadata.

04

Generation

Produce stable JSON, text, and accessible standalone HTML plus a compact runtime manifest. Identical inputs must yield byte-identical outputs on every supported OS.

05

SBOM linkage

Use canonical Package URLs as component keys and optionally reconcile against CycloneDX or SPDX documents. Notice records keep the external SBOM reference rather than duplicating an SBOM engine.

06

Audit trail

Explain where every fact came from, what was overridden, which policy rule matched, which bytes were rendered, and why verification succeeded or failed.

Legal boundary: the tool does not determine whether a license is legally valid, whether distribution is permitted, whether obligations were fulfilled, or whether an SPDX identifier accurately describes custom text. Its output requires review appropriate to the distributor and jurisdiction.
Shipping scope: default inventory includes runtime dependencies actually distributed with the artifact. Build, test, development, optional, peer, bundled, and dynamically downloaded components are retained as classified records and included or excluded only by explicit profile rules.

03 · Deterministic pipeline

Discovery and network acquisition are different commands

Every stage consumes a documented model and produces a stable model. The default build path begins with already restored packages and already pinned evidence; it cannot contact a registry, repository, or arbitrary URL.

1 · Scan

Resolve graph

Read lockfiles/assets, select target, classify scope, create canonical components.

2 · Inspect

Collect local facts

Read package metadata and candidate evidence without running package code.

3 · Lock

Pin evidence

Resolve overrides, hash bytes, write a canonical evidence lock and asset references.

4 · Evaluate

Apply policy

Parse SPDX expressions, detect gaps, classify obligations, produce decisions.

5 · Link

Reconcile SBOM

Match package identities and record SBOM serial/document plus component refs.

6 · Render

Emit outputs

Sort, serialize, render, hash, and byte-compare without timestamps or host paths.

Explicit acquisition

dependency-notices acquire --allow-network is the only command permitted to download license/notice material. It applies HTTPS/host/redirect/size policy, displays origin and digest, writes content-addressed bytes, and updates a reviewable lock diff. It is never invoked by MSBuild, generate, or verify.

Canonical serialization

UTF-8 without BOM, LF newlines, invariant culture, ordinal sorting, normalized relative paths, lowercase hex SHA-256, explicit schema versions, and no creation time, machine name, temporary path, restore root, or nondeterministic dictionary order.

Repeatable selection

NuGet target selection must be supplied or uniquely derivable. npm workspace roots and output profiles must be explicit. Ambiguous framework/RID/workspace selection is an error, not an environment-dependent default.

Verify rather than rewrite

verify regenerates into an isolated temporary directory from the locked inputs, compares declared outputs byte-for-byte, validates asset hashes and policy, and prints a concise diff. It never updates source files.

04 · SPDX and policy

Preserve facts; make decisions reviewable

Implement a real SPDX-expression parser for identifiers, document-defined LicenseRef-* values, AND, OR, parentheses, and WITH exceptions. Never treat an expression as a string list.

Expression model

Build an immutable syntax tree, retain the original expression, and emit one canonical normalized expression. Reject malformed expressions with a position and expected token.

AND

All branches apply. Policy fails if any required branch is denied or lacks required evidence; output preserves evidence for every branch.

OR

Do not silently pick a branch. Policy may require an explicit selectedLicense override. Preserve the upstream expression and record the selected branch and reviewer rationale separately.

WITH

Evaluate the license-plus-exception pair as one policy subject. Never drop the exception from display, grouping, or allow/deny matching.

Unknown/custom text

Use stable LicenseRef-* identifiers linked to exact evidence. NOASSERTION, absent metadata, deprecated identifiers, and expression/text disagreement are review diagnostics.

Attribution

Keep required notices, copyright lines, author lists, modification notices, and license texts as distinct ordered assets. Deduplicate identical bytes only; never collapse similar-looking text.

Grouping and ordering

Sort dependencies by normalized display name, version, then Package URL using ordinal comparison. Render each component once. Identical evidence assets may be printed once in a license appendix only when every component retains an explicit digest-linked reference.

Runtime is read-only

The runtime package parses a generated document, exposes search/group/filter APIs, and validates schema compatibility. It performs no dependency discovery, policy evaluation, filesystem crawling, license download, or reflection-based type activation.

Attribution invariant: the byte sequence used as evidence is always recoverable by digest. Renderers may normalize surrounding layout and newline separators, but they must not “clean up,” translate, truncate, reflow, or HTML-interpret the evidence body.

07 · Diagnostics and cache

Every failure points to evidence and remediation

Diagnostics are part of the public compatibility contract. Codes remain stable across minor releases; message wording may improve. Release profiles promote selected warnings to errors without hiding their original category.

Content-addressed cache

Key evidence solely by SHA-256 bytes, not URL. A separate origin index maps reviewed URLs/package paths to digests. Cache writes use create-temp, flush, hash, and atomic rename. Concurrent writers converge on the same digest and never overwrite differing bytes.

No hidden machine cache

Release verification receives the evidence root explicitly. A user cache may accelerate acquisition, but success must not depend on undeclared files in a home directory. verify --offline --empty-user-cache is a required CI scenario.

Incrementality

Cache scan models by lockfile digest + target + adapter version, and output models by evidence-lock + policy + renderer version. Cache hits must be observationally identical to clean generation. --no-cache exists for validation.

Schema evolution

Every config, lock, policy, JSON output, and diagnostic document carries a schema version. Readers reject newer incompatible major schemas and provide a separate explicit migration command; generation never rewrites inputs implicitly.

08 · Security and robustness

Treat packages, URLs, and license text as hostile input

The tool processes attacker-controlled archives, JSON, paths, metadata, and text in privileged build environments. Security constraints are acceptance criteria rather than implementation details.

  • Build, generate, policy, verify, and SBOM commands create no sockets and perform no DNS resolution.
  • Acquisition allows HTTPS by default, enforces host allowlists, revalidates every redirect, strips credentials, and caps redirects, bytes, time, and decompression ratio.
  • Archive and package paths are normalized; absolute paths, device paths, .. escape, alternate streams, and symlink/reparse-point escape are rejected.
  • npm lifecycle scripts, binaries, MSBuild targets, PowerShell, shell commands, package tools, and repository hooks are never executed during inspection.
  • HTML renderer escapes all names, URLs, expressions, metadata, and evidence; emits no raw package HTML, JavaScript, remote CSS/font/image, or dangerous URL scheme.
  • JSON parsing uses depth, token, property-count, and total-byte limits; duplicate security-significant properties and malformed Unicode are rejected.
  • Output writes remain inside the resolved output root, use temporary files and atomic replacement, and refuse collisions with source inputs/evidence.
  • Logs and diagnostics redact credentials, authorization headers, user information, sensitive URL queries, home paths, and registry tokens.
  • Hashes provide integrity and reproducibility, not authenticity. Optional signature/provenance verification is reported separately from hash validation.
  • Remote content changes at the same URL never update silently: acquisition produces a digest diff requiring explicit review and lock update.
License preservation caveat: security normalization must not mutate evidence bytes. Decode text through a recorded encoding into the runtime model only after storing and hashing the original bytes; malformed or binary “license” content requires explicit override/review.
09 · Verification strategy

Fixtures prove ecosystems, policy, attacks, and AOT

Tests use synthetic public fixtures checked into the repository. They must not require access to a private registry, proprietary project, developer machine cache, or live network.

Core unit tests

Package URL normalization, exact-version identity, SPDX lexer/parser/formatter, AND/OR/WITH evaluation, policy precedence, stable sorting, canonical JSON, hashing, and schema validation.

NuGet fixtures

Direct/transitive packages, multiple targets/RIDs, embedded license file, expression, URL only, missing metadata, development dependency, package hash mismatch, duplicate versions, and locked-restore drift.

npm fixtures

Scoped packages, workspaces, production/dev/optional/peer, aliases, bundled dependencies, integrity, multiple license files, missing node_modules, symlinks, and supported lockfile generations.

Manual/SBOM fixtures

Vendored and modified code, native asset, font, LicenseRef, exact override, expiry, CycloneDX/SPDX matching, missing/extra/ambiguous components.

Golden outputs

Byte-approve JSON, text, HTML, manifest, lock, diagnostics, and print layout. Run twice, with empty cache, from different absolute roots and cultures on Windows/Linux/macOS where available.

Malicious corpus

Traversal, symlink escape, archive bomb, oversized JSON/text, duplicate keys, invalid UTF, hostile HTML/script/URL, redirect loop, credential leak, lock collision, and concurrent cache writers.

Package consumers

Pack local NuGets, restore a clean sample, invoke CLI and MSBuild targets, include outputs in publish/package, and verify no project-reference-only assumptions.

Native AOT

Publish the tool and a Runtime consumer for supported RIDs with trim/AOT warnings treated as errors. Load embedded JSON, enumerate/search notices, render a basic list, and exit without dynamic-code requirements.

Offline enforcement

Run generation in a network-denied environment with empty user caches and only declared restore/evidence inputs. Assert deterministic success; assert missing evidence fails without attempting a download.

Fuzz targets: SPDX expressions, Package URLs, npm/NuGet metadata, evidence lock, policy, SBOM reconciliation, archive entry paths, HTML escaping, and canonical serializer. Every found crash becomes a minimized regression fixture.
10 · Native AOT design

No discovery reflection in tool or runtime

Native AOT is verified on the executable and the optional runtime package. The design avoids APIs that merely suppress trim warnings while retaining an untested reflection path.

Generated JSON metadata

Use explicit JsonSerializerContext types for config, policy, locks, diagnostics, SBOM subsets, and runtime output. Do not deserialize arbitrary Type values or use reflection contract resolvers.

Explicit adapters

Register built-in ecosystem scanners and renderers through closed factories. A plugin SDK may exist later, but the AOT executable uses compile-time composition rather than assembly scanning or dynamic loading.

No dynamic code

No expression compilation, runtime proxy generation, emit, dynamic binder, reflection-based command discovery, or late-bound MSBuild task assembly. Regexes are source-generated or replaced with parsers.

Published artifact tests

Tests execute the actual Native-AOT binary against fixtures and compare outputs. Analyze and fail on trim/AOT warnings, missing globalization behavior, path/casing differences, and single-file assumptions.

12 · Acceptance and non-goals

Definition of done

The first stable release is complete only when its offline, legal-fidelity, package, and Native-AOT claims are demonstrated from public fixtures and packed artifacts.

  • Exact NuGet, npm, and manual component inventories are reproducible from declared roots and versioned lockfiles.
  • Every included component has a canonical Package URL, effective license expression, evidence digest, origin, scope, and policy decision.
  • SPDX AND, OR, parentheses, WITH, and LicenseRef semantics have unit, integration, and failure tests.
  • License, notice, attribution, author, and modification evidence is preserved and rendered without silent mutation.
  • generate and verify succeed with network denied and empty user cache, or fail explicitly for missing declared inputs.
  • Same inputs produce byte-identical JSON, text, HTML, and manifests across clean roots, cultures, repeated runs, and supported OSes.
  • Policy overrides are exact, evidenced, expiring, visible in output, and rejected when unused, conflicting, or stale.
  • Optional SBOM reconciliation reports stable links and deterministic missing/extra/version-mismatch diagnostics.
  • HTML output is standalone, escaped, accessible, printable, script-free, and contains no remote references.
  • CLI, MSBuild package, and runtime library work from packed packages; CLI and runtime pass published Native-AOT tests without warnings.
  • Malicious fixtures cannot escape roots, execute package code, inject HTML, exfiltrate credentials, exhaust unbounded resources, or introduce network access into builds.
  • Public schemas, diagnostic catalog, CLI reference, MSBuild properties/items/targets, policy guide, evidence-review guide, and security model are versioned documentation.
