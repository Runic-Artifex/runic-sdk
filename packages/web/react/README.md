# `@runic-artifex/react`

React hooks and outlet for clients generated by Runic Views. The generated
modules import `@runic-artifex/views`, which this package also builds on, so
install both:

```sh
npm install @runic-artifex/react@preview @runic-artifex/views@preview
pnpm add @runic-artifex/react@preview @runic-artifex/views@preview
bun add @runic-artifex/react@preview @runic-artifex/views@preview
```

Previews are published under the `preview` dist-tag. Install the versions that
match your Runic SDK packages. React 18.3 or later is supported.

```tsx
import { useCommand, useView, ViewOutlet, type ViewRegistry } from "@runic-artifex/react";
import { connectWorkspace, type WorkspaceState } from "./generated/workspace.js";
import type { CounterPageReference } from "./generated/counter.js";

const workspace = { connect: connectWorkspace };
const pages = { counter: CounterPage } satisfies ViewRegistry<WorkspaceState["main"]>;

export function App() {
  const { state, client, error } = useView(workspace);
  const showCounter = useCommand(() => client?.showCounter());
  if (error) return <p role="alert">{String(error)}</p>;
  return <>
    <button disabled={!client} onClick={() => void showCounter.run()}>Counter</button>
    <ViewOutlet content={state?.main} registry={pages} fallback={<p>Connecting…</p>} />
  </>;
}

export function CounterPage({ page }: { page: CounterPageReference }) {
  const { state, client } = useView(page);
  const increment = useCommand(() => client?.increment());
  return <>
    <button disabled={!client || increment.pending} onClick={() => void increment.run()}>{state?.count ?? "…"}</button>
    {increment.error !== undefined && <p role="alert">{String(increment.error)}</p>}
  </>;
}
```

## `useView(source)`

Returns `{ state, client, error, pending, retry }`:

- A generated page reference, or `{ connect: connect<Name> }` for a root
  ViewModel, is connected while the component is mounted and disposed when it
  unmounts or the reference changes. A reference is identified by its `connect`
  function, so an inline `{ connect: connectWorkspace }` does not reconnect.
- An already connected client is observed and left to its owner.
- `state` renders through `useSyncExternalStore`, so concurrent rendering sees
  one consistent snapshot. StrictMode's extra mount disposes its connection.
- `pending` is true while a reference connects. `error` holds a failed
  connection; `retry()` connects again.

A `connect` function created during render, such as
`useView({ connect: () => connectWorkspace() })`, is a new reference on every
render, so each render reconnects. In development `useView` logs a warning when
this repeats. Pass the generated function itself, a generated page reference,
or memoize the source with `useMemo`.

## `useSuspenseView(source)`

Suspends the component until a reference connects, then returns
`{ state, client }` without `undefined`. A failed connection is thrown to the
nearest error boundary. Call `retrySuspenseView(reference)` when the boundary
resets, so the next render connects again; an unretried failure is forgotten
after ten seconds:

```tsx
<ErrorBoundary fallback={<p role="alert">Offline</p>} onReset={() => retrySuspenseView(page)}>
  <Suspense fallback={<p>Connecting…</p>}><Counter page={page} /></Suspense>
</ErrorBoundary>

function Counter({ page }: { page: CounterPageReference }) {
  const { state, client } = useSuspenseView(page);
  return <button onClick={() => void client.increment()}>{state.count}</button>;
}
```

Components that pass a reference with the same `connect` function share one
client, which is disposed after the last of them unmounts. The reference must
be stable: a `connect` function created during render never resolves.

## `ViewOutlet`

`<ViewOutlet content={reference} registry={pages} fallback={…} />` renders the
component registered for `reference.kind` with the reference as its `page`
prop. Declare the registry with `satisfies ViewRegistry<State["main"]>` so each
kind has a component whose `page` prop matches. A different reference
remounts the component; a kind without a component renders an alert, and
`fallback` renders while `content` is empty.

## `useCommand(command)`

Returns `{ run, pending, error, failure, reset }`. `run(...args)` calls the latest
`command`, so it may close over the current client, and resolves to its result
or to `undefined` after a failure, which `error` then holds until the next run.
It never rejects, so handlers need no `try`/`catch`. One command can serve
several buttons:

```tsx
const navigate = useCommand((name: "showWelcome" | "showCounter") => client?.[name]());
<button onClick={() => void navigate.run("showWelcome")}>Welcome</button>
```

For a command that declares a failure (`[RunicFailure]` in .NET), `run` resolves the
`BridgeOutcome`, and `failure` holds the declared failure of the latest run, typed
from the outcome, while `error` keeps unexpected failures. Starting a run and
`reset()` clear both, and a run superseded by a later run or by `reset()` sets
neither.

## `useCollectionViewport(options)`

Follows a fixed-row-height scroll container and returns `{ viewport, ref }`.
`viewport` is the [`collectionViewport`](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#collectionviewportoptions)
range for the container; it changes only when the range or sizes change. Send
the range to the ViewModel from an effect:

```tsx
const { state, client } = useView(rows);
const { viewport, ref } = useCollectionViewport({ totalCount: state?.totalCount ?? 0, rowHeight: 32 });
useEffect(() => {
  if (viewport.size !== 0) void client?.setViewport({ start: viewport.start, size: viewport.size });
}, [client, viewport.start, viewport.size]);
return <div ref={ref} style={{ height: 480, overflow: "auto" }}>
  <div style={{ height: viewport.totalSize }}>
    <div style={{ transform: `translateY(${viewport.offset}px)` }}>{/* state.rows */}</div>
  </div>
</div>;
```
