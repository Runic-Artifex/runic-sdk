# `@runic-artifex/vue`

Vue composables and outlet for clients generated by Runic Views. The generated
modules import `@runic-artifex/views`, which this package also builds on, so
install both:

```sh
npm install @runic-artifex/vue@preview @runic-artifex/views@preview
pnpm add @runic-artifex/vue@preview @runic-artifex/views@preview
bun add @runic-artifex/vue@preview @runic-artifex/views@preview
```

Previews are published under the `preview` dist-tag. Install the versions that
match your Runic SDK packages. Vue 3.5.30 or a later 3.x release is supported.

```vue
<script setup lang="ts">
import { useCommand, useView } from "@runic-artifex/vue";
import type { CounterPageReference } from "./generated/counter.js";

const props = defineProps<{ page: CounterPageReference }>();
const { state, client, error } = useView(() => props.page);
const { run: increment, pending, error: incrementError } = useCommand(() => client.value?.increment());
</script>

<template>
  <button :disabled="!client || pending" @click="increment()">{{ state?.count ?? "…" }}</button>
  <p v-if="(incrementError ?? error) !== undefined" role="alert">{{ String(incrementError ?? error) }}</p>
</template>
```

Every composable returns its state as shallow refs, so a handle can be
destructured in `<script setup>` and its refs unwrap in the template.

## `useView(source, options?)`

Returns shallow refs `{ state, client, error, pending }` and `retry()`.
`options.release(client)` replaces `client.dispose()` for a client the composable
connected:

- A generated page reference, or `{ connect: connect<Name> }` for a root
  ViewModel, is connected while the current effect scope (normally the
  component) is active. A reference is identified by its `connect` function, so
  a getter that returns a new `{ connect: connectWorkspace }` object does not
  reconnect.
- Disposing the scope or changing the reference keeps the client connected for
  `options.keepAlive` milliseconds (2000 by default), and the next `useView` of
  the same reference takes it over with its state in `setup()`, so a `v-if`
  that toggles, HMR and A→B→A navigation show the View at once instead of
  "Connecting…" and do not open the route again. `keepAlive: 0` disposes at
  once.
- An already connected client is observed and left to its owner.
- The source can be a value, a ref or a getter such as `() => props.page`.
- `pending` is true while a reference connects. `error` holds a failed
  connection; `retry()` connects again.

All four composables release their controller when the current effect scope is
disposed. Call them in a component's `setup()` (or `<script setup>`) or inside
`effectScope().run()`, and stop that scope to release them. Called outside an
effect scope, for example from a plain module or an event handler, nothing ever
releases them: `useView` keeps its client connected. Development builds warn
in the console when that happens.

### Async setup: `useSuspenseView(source, options?)`

`await useSuspenseView(page)` in an async `setup()` (a top-level `await` in
`<script setup>`) connects like `useView` and resolves once the View
connected, with `state` (a ref that is never `undefined`) and `client`.
`<Suspense>` shows its `#fallback` meanwhile:

```vue
<!-- CounterPage.vue -->
<script setup lang="ts">
import { useSuspenseView } from "@runic-artifex/vue";
import type { CounterPageReference } from "../generated/counter.js";

const props = defineProps<{ page: CounterPageReference }>();
const { state, client } = await useSuspenseView(props.page);
</script>

<template><button @click="client.increment()">{{ state.count }}</button></template>
```

```vue
<Suspense>
  <CounterPage :page="page" :key="page.kind" />
  <template #fallback><p>Connecting…</p></template>
</Suspense>
```

A failed connection rejects, so the error reaches `onErrorCaptured` of a
parent; render the component again, for example with a new `key`, to connect
again. Call `useSuspenseView` before any other `await` in `setup()`. The
source is read once: key the component by its reference to follow another one.

### Selecting state: `computed`

`useView` exposes the whole state as one shallow ref, which changes with every
change of the View. A `computed` that selects a member triggers its dependents
only when its value changed (Vue 3.4+), so a template part or a `watch` that
reads `title` does not run again when another member changes:

```ts
const editor = useView(page);
const title = computed(() => editor.state.value?.title);
```

Members the View did not change keep their identity, so selecting a member,
also an object or a list, is enough. A computed that builds a new value, such
as `items.filter(…)`, changes every time; compare it yourself
(`computed(previous => …)` returns `previous` when equal).

### Read-only state and `v-model`

As in any MVVM View, the ViewModel's C# setters decide what the page may set.
Read state one way from `state`. A property with a public C# setter also gets a
`set<Property>` client method; wrap it in a writable `computed` to use
`v-model`. Status with a `private set`, such as `IsDirty` or `Error`, has no
setter and is only rendered:

```vue
<script setup lang="ts">
// C#: public partial int Count { get; private set; }  public partial int Step { get; set; }
import { computed } from "vue";
import { useCommand, useView } from "@runic-artifex/vue";
import type { CounterPageReference } from "./generated/counter.js";

const props = defineProps<{ page: CounterPageReference }>();
const { state, client } = useView(() => props.page);
const { run: setStep } = useCommand((value: number) => client.value?.setStep(value));
const step = computed({ get: () => state.value?.step ?? 1, set: value => void setStep(value) });
</script>

<template>
  <p>{{ state?.count ?? "…" }}</p>
  <select v-model.number="step">
    <option :value="1">1</option>
    <option :value="5">5</option>
  </select>
</template>
```

### Fields: `useField(view, field, options?)`

Binds an element to a member while the effect scope is active. Pass the generated `{View}Fields` descriptor; it knows
the member's kind, setter, checked write and validation. The handle is `reactive`, so bind its members directly:

```vue
<script setup lang="ts">
import { useField, useView } from "@runic-artifex/vue";
import { EditorFields, type EditorPageReference } from "./generated/editor.js";

const props = defineProps<{ page: EditorPageReference }>();
const editor = useView(() => props.page);
const title = useField(editor, EditorFields.title, { commit: "pause", checked: true });
const step = useField(editor, EditorFields.step);
const done = useField(editor, EditorFields.done);
const mode = useField(editor, EditorFields.mode);
</script>

<template>
  <input v-model="title.value" @blur="title.commit" :aria-invalid="title.errors.length > 0 || title.error !== undefined">
  <p v-for="message in title.errors" :key="message" role="alert">{{ message }}</p>
  <p v-if="title.conflict" role="alert">
    Changed elsewhere to “{{ title.conflict.value }}”.
    <button @click="title.retry">Keep mine</button> <button @click="title.reset">Take theirs</button>
  </p>
  <input type="number" v-model="step.text" @blur="step.commit">
  <input type="checkbox" v-model="done.value">
  <select v-model="mode.value"><option v-for="choice in EditorFields.mode.choices" :key="choice">{{ choice }}</option></select>
</template>
```

It has `value` and `text`, which `v-model` reads and sets, the read-only `editing`, `error`, `errors` and
`conflict`, and `input(value)`, `commit()`, `retry()` and `reset()`. Bind number inputs to `text`: it keeps `-` and
`1.` while the user types, and a text that does not parse stays the draft with an `invalid-text` error while nothing
is written. A string set on `value` of a field that is not text is taken as its text, as `v-model` on
`<input type="number">` sets one. `v-model` already writes nothing during IME composition.

`options` are read once, when the field is created:

- `commit: "pause"` writes the draft after `delay` milliseconds without input (700 by default) and at once on
  `commit()`, which blur calls; use it where each write is an undo step or starts work in .NET. The default,
  `commit: "input"`, writes each input. `commit()` resolves once the field's writes settled, so a command that
  depends on the field can follow them: `await title.commit(); await editor.save()`.
- `checked: true` writes with the member's checked write, so a change by another writer while the user edits is a
  conflict instead of being overwritten. A `rejected` receipt keeps the draft and sets `error` to a `FieldError` with
  the setter's message; a `conflict` keeps the draft, sets `conflict` to the producer's `{ value, version }` and
  writes nothing until `retry()` writes the draft over it or `reset()` takes it.
- `coalesce` and `keepDraftOnError` as for text inputs below.

`errors` holds the member's validation messages from the descriptor (`[]` when valid), `error` why the latest write
or text failed (a `BridgeError` or a `FieldError`, whose `kind` is `rejected`, `conflict`, `committed-with-error` or
`invalid-text`). `FieldError`, `FieldOptions`, `FieldState` and `BridgeField` are exported from this package. See the
[field controller](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#fields) for the receipts
and text forms.

### Text inputs: `useTextField(view, read, write, options?)`

Binds a text input to a member through the framework-neutral
[text field controller](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#text-inputs)
while the effect scope is active. Each field is a ref, so the handle can be destructured:

```vue
<script setup lang="ts">
import { useTextField, useView } from "@runic-artifex/vue";
import type { PersonPageReference } from "./generated/person.js";

const props = defineProps<{ page: PersonPageReference }>();
const person = useView(() => props.page);
const { value: name, error } = useTextField(person, state => state.name, (client, value) => client.setName(value));
</script>

<template>
  <input v-model="name">
  <p v-if="error !== undefined" role="alert">{{ String(error) }}</p>
</template>
```

It returns `value`, a writable computed for `v-model`, the `editing` and `error`
refs and `reset()`. `v-model` already writes nothing during IME composition. `view`
is a `useView` handle or any `{ state, client }` refs. The options are `coalesce` and
`keepDraftOnError`.
The field shows what the user typed while its writes are in flight, so a reply or
frame that answers an older keystroke never replaces newer text. At most one write is
in flight; text typed meanwhile is written next as one value (`coalesce: false` writes
every change). Nothing is written during IME composition. Once the last write settled,
the field shows the View's value again, including any normalization the ViewModel
applied (trimmed, upper-cased). `write` may also be a command or a checked write,
whose receipt the field reads: `rejected` and `conflict` keep the draft and set `error`
to a `FieldError` of that kind, `committed-with-error` drops the draft and sets it too,
and `applied.validation` is `errors`. A failed write keeps the draft and sets `error`
(`keepDraftOnError: false` shows the View's value instead); `reset()` drops the draft. `editing` is true while a draft
exists. Don't disable the input on the View's busy state (`isSaving`, `can…`) while
the user types: the field's own write causes it, and keys typed meanwhile would be
lost. Test such fields by typing key by key (Playwright `pressSequentially`, Testing
Library `user.type`) against the mock with `latency: "slow"`; `fill()` sets the whole
text at once and hides the race.

## `ViewOutlet`

Renders the component registered for a generated reference's `kind` and
passes the reference as its `page` prop. A different reference remounts the
component, a kind without a component renders an English `<p role="alert">`
(or the `missing` slot), and the default slot renders while `content` is empty:

```vue
<script setup lang="ts">
import { useView, ViewOutlet, type ViewRegistry } from "@runic-artifex/vue";
import { connectWorkspace, type WorkspaceState } from "./generated/workspace.js";
import CounterPage from "./pages/CounterPage.vue";
import WelcomePage from "./pages/WelcomePage.vue";

const pages = { counter: CounterPage, welcome: WelcomePage } satisfies ViewRegistry<WorkspaceState["main"]>;
const { state } = useView({ connect: connectWorkspace });
</script>

<template>
  <ViewOutlet :content="state?.main" :registry="pages"><p>Connecting…</p></ViewOutlet>
</template>
```

`satisfies ViewRegistry<…>` checks that every kind has a component whose `page`
prop accepts that reference.

The `missing` slot replaces the English alert, for example with localized text.
It receives `{ content }`, the reference whose kind has no component, and its
markup (including any `role`) is yours:

```vue
<ViewOutlet :content="state?.main" :registry="pages">
  <template #missing="{ content }"><p role="alert">{{ t("missingView", { kind: content.kind }) }}</p></template>
</ViewOutlet>
```

## `useCommand(command)`

Returns `{ run, pending, error, failure, reset }`, with `pending`, `error` and
`failure` as shallow refs.
`run(...args)` resolves to the command's result, or to `undefined` after a
failure, which `error` then holds until the next run. It never rejects, so
handlers need no `try`/`catch`. One command can serve several buttons:

```ts
const { run: navigate } = useCommand((name: "showWelcome" | "showCounter") => client.value?.[name]());
// <button @click="navigate('showWelcome')">Welcome</button>
```

`pending` covers only this component's run. Whether .NET can run the command is
the View's state: a command without an argument publishes `can<Name>` (such as
`state.canSave`), so disable a button while either says no. A command with an
argument has the `can<Name>(input)` query on the client instead.

For a command that declares a failure (`[RunicFailure]` in .NET), `run` resolves the
`BridgeOutcome`, and `failure` holds the declared failure of the latest run, typed
from the outcome, while `error` keeps unexpected failures. Starting a run and
`reset()` clear both, and a run superseded by a later run or by `reset()` sets
neither.

## `useOperation(start, options?)`

Observes a generated `start<Command>()` operation through the framework-neutral
[operation controller](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#operation-feedback-and-latest-selection)
and returns each state field as a shallow ref, with `run`, `cancel` and `reset`:

```vue
<script setup lang="ts">
const { run: push, cancel, pending, cancellationRequested, cancelled, error } =
  useOperation((remote: string) => client.value?.startPush(remote));
</script>

<template>
  <button :disabled="!client || pending" @click="push('origin')">Push</button>
  <button v-if="pending" :disabled="cancellationRequested" @click="cancel()">Cancel</button>
  <p v-if="cancelled" role="status">Push cancelled.</p>
  <p v-if="error !== undefined" role="alert">{{ String(error) }}</p>
</template>
```

The result has `pending`, `admitting`, `operation`, `status`, `progress`, `outcome`, `failure`,
`error`, `cancelled`, `cancellationRequested`, `cancelling`, `cancellation` and
`cancelError`, with `run(...args)`, `cancel()` and `reset()`, which never reject. A
run that ends with a `cancelled` status sets `cancelled` and resolves to `undefined`
without an `error`; `failed` and `timed-out` statuses are still `error`. `pending`
stays true after a Cancel response until the operation reaches its terminal status.
`progress` is how far the running operation got, from 0 to 1, when its command
reports progress (`RunicOperationProgress.Report` in .NET), for example
`<progress :value="progress">`; it is `undefined` while unknown and after the run.
Disposing the effect scope settles run promises without cancelling accepted work.

## `useLatestOperation()`

Admits only the newest of several reads, for example loading the item the user
selected last, through the framework-neutral
[latest-operation controller](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#operation-feedback-and-latest-selection),
and returns each state field as a shallow ref, with `run` and `clear`. Each
`run(intent)` replaces the queued intent and cancels the active read; the next read
starts only after the previous one reaches its terminal status and the intent's
optional `waitForCompletion` barrier:

```vue
<script setup lang="ts">
const { run: load, outcome, blocked } = useLatestOperation<Item>();
function select(id: string) {
  const current = client.value;
  if (current) void load({ start: () => current.startLoad(id), isCurrent: () => client.value === current });
}
</script>

<template>
  <ItemView v-if="outcome?.ok" :item="outcome.value" />
  <p v-if="blocked" role="alert">Reconnect before selecting again.</p>
</template>
```

The result has the `useOperation` fields plus `blocked`, with `run(intent)` and
`clear(mode?)`, which never reject. The intent carries `start` and the optional
`cancel`, `waitForCompletion` and `isCurrent` callbacks, so it captures the client or
session it belongs to. `blocked` means admission is uncertain, for example after a
lost Start reply; only `clear("replace")`, called after the application has
established a fresh session, clears it. `clear()` drops the queued intent and cancels
the active read. Disposing the effect scope settles run promises without cancelling
accepted work.

## `useBridgeConnection(options?)`

Follows the page's connection to its .NET host. It wraps `onBridgeConnection`
from `@runic-artifex/views` (re-exported here since 0.11, with the
`BridgeConnectionState` and `BridgeConnectionOptions` types) and returns `{ state }`, a shallow ref holding a
`BridgeConnectionState`: `connecting`, `connected`, `reconnecting` or `lost` (a
closed set, see
[Connection state](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#connection-state)):

```vue
<script setup lang="ts">
import { useBridgeConnection } from "@runic-artifex/vue";

const { state: connection } = useBridgeConnection({ lostAfter: 5_000 });
</script>

<template>
  <p v-if="connection === 'lost'" role="alert">The application stopped responding.</p>
</template>
```

Disposing the effect scope (unmounting the component) unsubscribes. Call it in
`setup()` or `effectScope().run()`: outside an effect scope nothing stops it, and
development builds warn. An invalid `lostAfter` throws a `RangeError`.

## `useMenuBar(options?)`

Follows the declared menu bar of a Runic Desktop window that leaves it to the
page (`DesktopMenuBarPresentation.Page`) until the current effect scope is
disposed. It wraps `createMenuBarController` from `@runic-artifex/views` (see
[In-page menu bar](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#in-page-menu-bar)) and returns `{ state, invoke, handleKeyDown }`: `state` is a shallow ref
of a `MenuBarState`, and the bar is rendered by the menubar component of the
application's own UI library. Runic ships no menubar component.

```vue
<script setup lang="ts">
import { ref } from "vue";
import { useMenuBar } from "@runic-artifex/vue";

const open = ref("");
const { state: menuBar, invoke } = useMenuBar({
  onRequest: request => { if (request.kind === "open") open.value = request.menu.key; else focusFirstTrigger(); },
});
</script>

<template>
  <!-- On macOS the application menu bar keeps the menus ("global"): render nothing. -->
  <nav v-if="menuBar.placement === 'page'"><!-- the menubar component; an item's select handler calls invoke(item) --></nav>
</template>
```

Options are those of `createMenuBarController` (`shortcuts`, `keyboard`)
without `signal`, plus `onRequest`, which receives the `focus` and `open`
requests. Stopping the scope disposes the controller, which also returns the
`shortcuts: "app"` lease. Call it in `setup()` or `effectScope().run()`;
outside an effect scope it is never released (development builds warn). Server
rendering creates no controller: `state` stays `connecting`.

### With Reka UI

Reka UI's `MenubarRoot` with `v-model` of the open menu; the
[Notes example](https://github.com/Runic-Artifex/runic-sdk/tree/main/examples/notes-view-first#in-page-menu-bar) adds submenus, check and radio
items and is tested with real keys:

```vue
<script setup lang="ts">
import { ref } from "vue";
import { MenubarContent, MenubarItem, MenubarMenu, MenubarPortal, MenubarRoot, MenubarSeparator, MenubarTrigger } from "reka-ui";
import { splitAccessKey } from "@runic-artifex/views";
import { useMenuBar } from "@runic-artifex/vue";

const bar = ref<{ $el: HTMLElement }>();
const open = ref("");
const { state: menuBar, invoke } = useMenuBar({
  onRequest: request => {
    if (request.kind === "open") open.value = request.menu.key;
    else bar.value?.$el.querySelector<HTMLElement>("[role=menuitem]")?.focus();
  },
});
</script>

<template>
  <MenubarRoot v-if="menuBar.placement === 'page'" ref="bar" v-model="open" aria-label="Application">
    <MenubarMenu v-for="menu in menuBar.menus" :key="menu.key" :value="menu.key">
      <MenubarTrigger :disabled="!menu.enabled">
        <template v-for="(part, index) in splitAccessKey(menu)" :key="index">
          <u v-if="index === 1 && menuBar.accessKeyHints">{{ part }}</u><template v-else>{{ part }}</template>
        </template>
      </MenubarTrigger>
      <MenubarPortal>
        <MenubarContent align="start">
          <template v-for="entry in menu.entries" :key="entry.key">
            <MenubarSeparator v-if="entry.kind === 'separator'" />
            <MenubarItem v-else-if="entry.kind === 'item'" :disabled="!entry.enabled"
              :aria-keyshortcuts="entry.ariaKeyShortcuts" @select="invoke(entry)">
              {{ entry.label }} <kbd aria-hidden="true">{{ entry.shortcutText }}</kbd>
            </MenubarItem>
            <!-- a submenu: MenubarSub; check and radio items: MenubarCheckboxItem, MenubarRadioGroup -->
          </template>
        </MenubarContent>
      </MenubarPortal>
    </MenubarMenu>
  </MenubarRoot>
</template>
```

## Errors

The `error` of `useView` and of a command or operation handle is typed
`unknown`: it holds whatever the connection or the call rejected with. A Bridge
failure is a `BridgeError` from `@runic-artifex/views`. Show it with
`describeBridgeError(error)`, one English sentence, instead of `String(error)`,
and narrow it with `isBridgeError` (or `instanceof`) before reading `kind`,
`route` or `detail`:

```ts
import { describeBridgeError, isBridgeError } from "@runic-artifex/views";

const offline = computed(() => isBridgeError(error.value, "disconnected"));
const message = computed(() => describeBridgeError(error.value));
```

`instanceof` holds for errors from every copy of the package on the page.
[Errors and diagnostics](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#errors-and-diagnostics)
lists the kinds. Any other value, such as an exception that your own connect
function or command callback throws, arrives unchanged.

The composables run in the browser or webview that a Runic host serves.
`useView` connects during `setup()`, which also runs in a server render: render
the components that use it on the client only.

## Interactions

A ReactiveUI `Interaction<TInput, TOutput>` on the ViewModel, such as the
question of a `ReactiveLeaveConfirmation.WithInteraction` leave guard, is
`client.interactions.<name>` on the generated client. Register the page's answer
in `watchEffect`: `handle((prompt, { signal }) => …)` returns the function that
removes it, so pass that to `onCleanup`, and Vue removes the handler when the
client changes or the component unmounts:

```vue
<script setup lang="ts">
import { watchEffect } from "vue";
import { useView } from "@runic-artifex/vue";
import type { EditPageReference } from "./generated/edit.js";

const props = defineProps<{ page: EditPageReference }>();
const { client } = useView(() => props.page);
watchEffect(onCleanup => {
  const remove = client.value?.interactions.confirmDiscard.handle(
    async (prompt, { signal }) => confirmDialog(`Discard the changes to ${prompt.itemName}?`, signal),
  );
  if (remove) onCleanup(remove);
});
</script>
```

`prompt` and the answer are typed from the ViewModel's interaction. The handler
may return the answer or a promise of it; `confirmDialog` stands for the
application's own dialog.

- The page is asked for a departure that its own window starts: its Close, the
  shell's Back in the same window, or a guarded window close.
- `signal` aborts when .NET no longer needs the answer, for example when the
  departure is superseded or the window closes. Close the dialog then; a late
  answer is ignored.
- The handler exists only after the client connected and the effect ran. A
  departure before that is answered by the ViewModel's .NET fallback handler, or
  fails closed without one.

The [ReactiveUI leave confirmation](https://github.com/Runic-Artifex/runic-sdk/blob/main/packages/dotnet/Runic.Application.Views.ReactiveUI/README.md#leave-confirmation-in-a-web-view)
has the .NET side and which View answers which departure. In a frontend test,
the generated mock's `interactions.<name>.request(input)` resolves with the
registered handler's answer; see the [Testing guide](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#testing).

## `useCollectionViewport(options)`

Follows a fixed-row-height scroll container and returns `{ viewport, attach }`.
`viewport` is a shallow ref with the [`collectionViewport`](https://github.com/Runic-Artifex/runic-sdk/tree/main/packages/web/views#collectionviewportoptions)
range; `attach` is a function ref for the container. Bind it to a native element
such as a `<div>`: a component instance (`:ref="attach"` on a component) or a
non-HTML element detaches the viewport, and development builds warn. Pass a getter for the
options and watch the range to send it to the ViewModel:

```vue
<script setup lang="ts">
const { state, client } = useView(() => props.page);
const { viewport, attach } = useCollectionViewport(() => ({ totalCount: state.value?.totalCount ?? 0, rowHeight: 32 }));
watch(() => [viewport.value.start, viewport.value.size] as const, ([start, size]) => {
  if (size !== 0) void client.value?.setViewport({ start, size });
});
</script>

<template>
  <div :ref="attach" style="height: 480px; overflow: auto">
    <div :style="{ height: `${viewport.totalSize}px` }"><!-- state.rows --></div>
  </div>
</template>
```
